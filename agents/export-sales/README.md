# 四品类出口业务员 Agent

面向海外 B 端买方，代表中国出口供货方处理产品咨询、采购条件收集和需求推进。2026-10-28 的范围、页面、授权、接入顺序和验收统一以 [AI 业务员与邮箱自动接待设计](../../docs/ai-sales-agent-design.md) 为准，架构决定见 [ADR-0019](../../docs/adr/0019-ai-sales-agents-with-controlled-mail-reception.md)。

## 当前状态与目标

- 已实现：沟通中心的多邮箱首封计划、手动只读邮件同步、原格式阅读、人工回复、草稿及发送台账。新首封计划按 ADR-0018 使用普通 LLM、程序固定称呼和账号签名；旧专业模式计划保留原方式。操作见 [沟通中心](../../docs/outreach-first-touch.md)。
- 待实现：侧边栏「AI 业务员」、接待配置、后台增量收信触发、来信自动起草与发送、自动接待中的人工交接。
- 后续范围：客户未回复时的主动跟进、图纸自动解析及自动选择技术附件。人工回复现已支持附件，不代表这些自动流程已接通。

四个品类业务员共用一套运行程序、模型连接和客户历史，按需求加载专业规则，不要求创建四套独立平台 Agent。一个企业可有多个品类需求，同一会话统一组织回复；品类分工不产生第二个对外邮箱或客户档案。

## 四个固定品类角色

| Agent    | 来信接待提示词                              | 专业范围                                                               |
| -------- | ------------------------------------------- | ---------------------------------------------------------------------- |
| shutter  | [透气窗](prompts/01-透气窗Agent.md)         | Plantation Shutter：实木、PVC、铝；成品及适用型材配件                  |
| venetian | [百叶窗](prompts/02-百叶窗Agent.md)         | 木、复合木、PVC、铝、PS 横百叶；Cut Down／Custom Made 及配套           |
| indoor   | [室内成品帘](prompts/03-室内成品帘Agent.md) | 卷帘、斑马、香格里拉、蜂巢、布艺、罗马帘等及适用半成品、面料、电机配件 |
| outdoor  | [户外遮阳](prompts/04-户外遮阳Agent.md)     | 防风卷帘、天幕、凉亭、伸缩棚、阳光房遮阳等及系统配套                   |

这些画像表示专业分工，公司实际可供产品、品牌覆盖和对外声明取自审核资料。室内机构工程由 indoor 对外主责，横百叶由 venetian 提供专业支持；户外工程由 outdoor 主责。

## 共同规则

- 已有客户沿用固定邮箱及批准签名；总目录确认有的新产品可由对应品类内部支持，统一在原会话回复。首次开发另按已审核的官网具体产品覆盖分配邮箱。
- 每封所需资料有适用、有效的已确认依据才算资料完备；客户要求、搜索词、行业常识和历史个案不成为我方供货事实。
- 回信接待单独选择关闭、仅生成草稿或自动接待，并保存范围授权；首封启动、邮箱连接和资料审核不代替自动回信授权。
- 常规答疑及采购条件收集可在授权范围自动发送；标准商务承诺在资料适用、客户条件齐全且显式获授权时可免逐封审核。有依据但缺自动权限时形成待审草稿，缺依据时先澄清或核实，超权限事项转人工。
- 单封审核只批准该版本邮件；需求级接管暂停该需求，会话级接管暂停全部需求。人工发信、报价完成和时间流逝不自动交回，须由真人明确选择。
- 企业暂缓、退订、勿联系和邮箱暂停等限制独立生效；客户新回信不解除限制。新消息、人工操作或资料版本变化使相关旧草稿失效，发送前再次核对，结果未知不自动重发。

## 协议与资料入口

- [会话协议](conversation-contract.md)：上下文、结构化建议、商务权限、人工交接与统一发送。现有 JSON Schema 与示例为 1.3；正式自动接待接入时按最终设计升级为 1.4，此前无自动商务权限上下文时仍生成单封审核草稿。
- [邮箱路由](mailbox-routing.md)：首封品牌覆盖、客户固定邮箱及共享目录。
- [知识清单](knowledge-checklist.md)：公司、产品、商务政策及对外使用资料。
- [图纸协议](drawing-protocol.md)：提取候选、参数批准、原图版本及独立外发许可，属于后续自动流程。
- [验收案例](acceptance-cases.json) 与 examples/：虚构协议样例，不代表模型或真实渠道已通过行为验收。

examples/quote-_ 展示缺少报价依据时澄清，mixed-_ 展示需求分别接管，drawing-_ 展示批准参数与附件申请，catalog-fallback-_ 展示共享总目录支持。客户只接收统一整理后的邮件正文，不能直接发送模型 JSON。

## 维护与检查

来信规则维护来源为 shared-system.md，专业差异来自 category-profiles.json；outreach-system.md 和 prompts/outreach/ 保留旧专业首封模式的规则，不是当前新首封计划的默认生成方式。修改源文案后执行：

```powershell
node agents/export-sales/build-prompts.mjs
node agents/export-sales/build-prompts.mjs --check
node --test tests/agent-policy.test.mjs
```

生成命令只维护八份提示词，不连接邮箱或发送邮件。提示词不能代替邮箱授权、持久化状态、发送检查和人工按钮；正式实现前仍须升级协议并执行最终设计中的接入验收。
