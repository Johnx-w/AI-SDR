# 四品类出口业务员 Agent｜V3.3

本公司是从中国向海外 B 端客户出口窗饰产品的供货卖方；客户是采购我方产品的海外买方。四个 Agent 负责卖方接待、产品沟通和需求推进，个人消费者不进入销售接待。

本设计按 2026-10-23 最新确认的多官网、单客户固定邮箱规则更新。交付为平台无关的完整系统提示词及接入规则；模型、客户库、人工通知与定时跟进尚未接通。仓库代码已实现本机固定双公司地址的收发技术试点，但尚未取得并配置新生成的本机邮箱客户端安全密码与操作者口令，尚未完成真实邮箱联通；这项试点不等于真实客户邮箱接入或触达授权。

V3.3 在 V3.2 的首次选择官网邮箱、客户固定邮箱及公司总产品目录回退之上，分开记录单封人工审核、需求级接管与会话级接管；会话输入输出协议升级为 `1.3`。OCR、视觉或 CAD 解析、文件存储、真实发图、官网覆盖表和总目录属于待接入能力。当前真实产品资料尚未提供并审核，主动开发输出必须保持 `suppress`，真实潜客发信与自动追信保持关闭。

## 固定的业务规则

- 出口卖方立场，面向海外进口商、经销批发商、品牌商、组装加工厂、工程或机构采购方；英文优先、邮件优先。公司是否自有工厂、海外仓或当地服务团队，以已审核资料为准。
- 型材、配件、面料、电机按产品品类归属承接；一个会话可以有多个品类需求，共享客户历史并统一回复。
- 首次联系按客户需求及已确认的官网产品覆盖选择一个官网邮箱；客户从某官网来信则沿用该收件邮箱。同一客户此后只用这个邮箱沟通，对外各品牌独立。官网未覆盖的新需求先查公司总产品目录；有产品则对应品类 Agent 内部协作、原邮箱统一回复；确认没有则该需求转人工，目录未知先核实。
- 政府、学校、医院等室内工程由 `indoor` 对外主责；横百叶产品内容由 `venetian` 支持，其他专业内容交对应品类。户外工程由 `outdoor` 主责。
- 常规答疑、需求收集和已确认样品政策介绍可自动回复。标准报价、运费、常规交期、MOQ 与标准付款条款只有在存在适用且已审核的版本化依据时才能起草；含具体商务承诺的完整邮件必须逐封人工审核，缺少依据时只澄清或内部核实，不编造数字或条件。超权限议价、特殊付款、非常规定制等按需求接管，强烈投诉、赔付、复杂商务、明确签单意向及代理、独家或年度框架洽谈按整段会话接管。
- 单封人工审核不等于人工接管。人工按具体需求接管时，其他独立常规需求继续自动接待；人工处理后选择继续跟进或明确交回 Agent，报价审核既不自动接管，也不自动交回。
- 自动跟进按自选频率执行，间隔、次数、时段和时区在系统配置，未配置并启用前不定时发送。首封主动开发不从本次已有会话跟进授权中推断。
- 图纸自动提取先作为待审候选；关键参数人工批准后才能引用，按 SKU、部件、图号版本与标注位置关联原图。图片另需技术与外发批准，Agent 仅申请附件编号，发送程序核对并读取真实文件后附图。

## 邮箱路由与图纸

[邮箱路由](mailbox-routing.md) 规定首次选定邮箱、客户绑定、总目录回退及跨品类内部协作。当前三个官网邮箱仅作为已经确认的绑定示例，网站实际产品覆盖与公司总目录尚待导入审核。客户固定邮箱和每项需求的 `product_access` 由可信业务系统提供，Agent 不能选择发件地址。当前沟通中心代码另有更窄的技术边界：只允许固定发件地址 `SL01@shutterblindssolutions.com` 与固定测试收件地址 `SL01@honeybadgerblinds.com` 之间的新测试线程；网页操作须用本机操作者口令解锁，不会导入历史邮件或放行真实潜客。

[图纸协议](drawing-protocol.md) 说明“提取 → 审核 → 原图关联 → 检索 → 文字回复与图片发送”的完整规则。[图纸上下文 Schema](drawing-context.schema.json) 分开记录提取值与批准值、原图及局部图、技术审核与外发授权。

图纸审核通过不改变人工接管状态；图纸换版后旧批准和待发草稿需重新核验。报价、异形评估及其他人工权限继续按既定规则执行。

## 接入时的顺序

1. 创建四个独立 Agent，分别复制上面的完整提示词；配置实际可用的模型和工具。
2. 按 [知识资料清单](knowledge-checklist.md) 准备公司、品类和政策资料，并建立已审核的官网产品覆盖、公司总产品目录和官网邮箱配置；空缺保持待核实。
3. 先用新生成且仅保存在本机的邮箱客户端安全密码和独立操作者口令完成固定双公司地址技术试点；通过后再另行接入真实邮箱收件与客户记录。首次开发邮件先匹配官网邮箱，来信则绑定实际收件邮箱，并将固定邮箱保存到客户档案。技术试点通过本身不开放真实潜客发信。
4. 拆分每封来信中的需求，为每项分配编号、产品归属、对外主责、接待归属及目录核对结果；按 [输入 Schema](turn-input.schema.json) 传入上下文调用对应 Agent。
5. 按 [会话协议](conversation-contract.md) 校验结果、执行人工交接、整合正文，并在发送前再次核对客户固定邮箱、最新状态与资料版本。
6. 配置图纸解析和审核流程，将批准参数及已授权图片登记到文件库；按图纸协议接入真实附件或内嵌图发送。
7. 用 [验收案例](acceptance-cases.json) 跑通所选模型和真实接入环境，再启用实际自动发送及自选跟进计划。

提示词中的权限约束须由收发与接待状态控制共同落实。提示词本身不能实现邮箱连接、多人并发协调、持久化记忆或人工按钮。

## 输入输出示例

`examples/` 中均为虚构的协议演示数据，没有真实客户、有效价格或实际工具调用：

- [混合品类来信](examples/mixed-input.json) 与 [建议输出](examples/mixed-output.json)：百叶窗正常接待，异形透气窗已由人工负责。
- [正式报价来信](examples/quote-input.json) 与 [建议输出](examples/quote-output.json)：资料不足时保留 AI 接待、澄清关键缺项且不编价；以后只有取得适用已审核条款，才能形成逐封人工审核的商务草稿。
- [图纸尺寸来信](examples/drawing-input.json) 与 [建议输出](examples/drawing-output.json)：引用人工批准的尺寸和公差，请求相同 SKU、部件、版本的图片；文件引用和哈希只是虚构协议数据。
- [总目录回退来信](examples/catalog-fallback-input.json) 与 [建议输出](examples/catalog-fallback-output.json)：原邮箱官网不覆盖新问的产品，公司总目录确认有产品，对应品类 Agent 内部支持、原邮箱回复。

这些输出是人工编写的参考结果，不是已经完成的模型或真实邮件实测。验收场景仍须在所选模型与接入环境执行。

## 维护

共享规则的维护来源是 `shared-system.md`，品类差异来源是 `category-profiles.json`。修改后执行：

```powershell
node agents/export-sales/build-prompts.mjs
```

该命令重新生成四份来信接待提示词和四份主动开发提示词，不连接任何外部平台，也不发送邮件。来信接待共享来源为 `shared-system.md`，主动开发共享来源为 `outreach-system.md`；两者使用相同品类画像。直接修改生成文件会在下次生成时被覆盖。主动开发流程只有获准产品声明和可信发件身份齐备后才可能生成可审草稿，实际发送仍由独立程序控制。

已确认的多品类、固定邮箱、商务承诺审核及邮箱试点边界分别记录在 `docs/adr/0003-category-demands-with-shared-conversations.md`、`docs/adr/0005-one-mailbox-per-customer-with-shared-catalog.md`、`docs/adr/0006-review-commercial-commitments-separately-from-handoff.md`、`docs/adr/0007-isolate-mailbox-pilot-from-real-outreach.md`，术语记录在根目录 `GLOSSARY.md`。完整规格暂保留于本地 `docs/agents/four-sales-agents.issue-draft.md`；公开 GitHub Issue 发布尚未授权。
