# 发件邮箱池、邮件归属与品类协作

首次主动开发先按客户经营证据匹配具体产品，再按已审核的官网产品覆盖选择对应邮箱。本规则依据 [ADR-0012](../../docs/adr/0012-route-first-outreach-by-approved-brand-products.md)，替代不区分产品范围的共享发件池规则。四个品类 Agent 是共享产品专家，其专业分工不是公司完整产品目录，也不自动授予任何邮箱整个品类的开发范围。

## 首封开发的内容与账号分配

1. 可信业务系统核对企业未触达状态、商务邮箱及来源证据，再依据客户实际经营情况选择相关的具体产品和获准用于本计划的产品声明。客户销售某产品或存在供货机会，只证明业务相关性，不证明正在采购、已询价或愿意更换供应商。
2. 将具体产品的稳定编号及适用采购形态、市场，与计划中各邮箱的已审核官网产品覆盖逐项核对。仅在覆盖有效且声明适用的账号中，按连接、暂停、额度、发送间隔及已分配工作量安排新任务；匹配不明、覆盖缺失或适用账号均不可用时等待，不把同属一个宽泛品类当作覆盖依据，也不转到无覆盖的空闲邮箱。
3. 在准备邮件时保存确定的发件账号、显示名称、固定签名和配置版本，模型只接收该账号上下文，不能选择或更换账号。已准备邮件遇到账号暂停、覆盖变更、配置失效或发送结果未知时保留原账号并等待核对，不静默改发；失效草稿重新准备与批准时仍保留原记录。新增尚未准备的任务只能分配给覆盖同一具体产品的其他适用账号。
4. 同一企业跨联系人、品类、账号和计划只安排一封首信；实际发送后记录所用邮箱及真实渠道结果。服务商接受与实际收件是不同证据，结果未知保持占用，不因未查到收件而重复发送。

发件账号配置包括准确邮件地址、官网品牌、已审核的具体产品覆盖、显示名称、批准签名、连接、额度、间隔和暂停状态。邮箱地址和签名取自真实配置。当前业务确认的品牌方向如下，具体产品、采购形态、市场和可外发声明仍须登记为有效审核记录，表中的方向不能替代逐项核对：

## 既有往来与共享产品目录

已有客户的真实发件和收件记录用于确定邮件归属，不因新产品、品类 Agent 改派或人工接管自动更换邮箱。将来接入来信时，客户主动来信以实际收件邮箱核对；同一客户出现在多个邮箱时先关联企业档案，停止第二条自动开发或回复，由人工核实冲突。调整既有归属须保留明确决定和记录。

每项产品需求由对应品类 Agent 提供内部支持。已有会话可使用已审核的官网覆盖信息，并在官网未展示时查询共同交易主体的公司总产品目录；目录确认有产品则在原邮箱统一回复，确认没有则该需求转人工，目录未知或检索失败先核实。目录命中不等于具体规格、库存、价格、MOQ、交期或文件获准外发；标准具体商务承诺仍遵守逐封人工审核规则。

多个官网对外品牌和共同交易主体事实保持有效。不得将其他品牌专属的介绍、价格、图纸直接当作当前邮件的公司事实，也不自动向客户介绍品牌间内部关系；客户主动询问时交人工决定。既有会话的总目录协作不用于绕过首次开发的品牌产品覆盖。

## 运行与发送前核对

选择账号、保存归属、校验签名和记录结果由可信编排及发送程序执行。发送前核对当前计划批准版本、客户与产品证据版本、官网产品覆盖及其版本、发件账号配置、账号可用状态以及抑制和去重记录；失效草稿重新核对或准备，模型输出不能授予发送权限。

当前运行范围为首封主动开发，不包括收件、自动回复和追信。公司邮箱技术测试使用明确的自有地址、唯一测试标记和固定非营销内容，与正式计划分开；测试成功不代替产品声明和计划批准。实际操作与存储边界见 [多邮箱首封开发](../../docs/outreach-first-touch.md)。
