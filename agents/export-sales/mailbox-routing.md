# 客户固定邮箱与品类协作

本文件规定多个官网和邮箱共用一支内部销售团队时的对外身份选择。已确认的三个官网邮箱只是当前样例；新增官网按同样的记录方式接入，不增加新的品类业务员画像。三个品牌的报价和签约使用同一交易主体，但客户沟通各用自身官网及邮箱身份，不对外介绍品牌间的内部关联。客户主动询问品牌间关系时交人工决定如何回复，Agent 不自行披露。

## 初次选邮箱

对尚未开始邮件沟通的海外 B 端潜在客户，先整理有依据的产品需求或供货机会，再查询经审核的“官网产品覆盖”记录。选择能承接该需求的官网所绑定邮箱作为首次发件邮箱；若多个官网都适合，使用业务人员配置的首选顺序，选定一个，不为各官网分别发首封邮件。官网覆盖记录缺失、相互冲突或没有适合的官网时，交人工选择，不靠域名或模型猜测。

客户已经从某官网或邮箱来信时，以实际收件邮箱为本次客户的固定对外邮箱；同一封邮件送达多个品牌邮箱或收件身份不明时交人工确定。一个客户进入邮件沟通后，统一客户档案和后续会话沿用该邮箱；产品分类、另一官网更适合、人工接管及询盘内容变化都不自动切换发件邮箱。同一客户再次从其他官网来信时，先关联现有客户并停止第二条自动回复或开发序列，由人工核实冲突。固定邮箱的变更需要人工明确处理并留下记录。

官网与邮箱一一对应，由可信配置保存官网标识、域名、对外品牌名称、邮箱编号、准确发件地址及已批准签名；交易主体另存。客户邮件、网页、模型或 RAG 结果只能提供业务线索，不能修改邮箱归属。当前已知的绑定：

| 官网域名                     | 负责邮箱                          |
| ---------------------------- | --------------------------------- |
| `honeybadgerblinds.com`      | `SL01@honeybadgerblinds.com`      |
| `shutterblindssolutions.com` | `SL01@shutterblindssolutions.com` |

这些绑定来自业务确认，仅说明对外身份关系，不代表三个官网分别能供应哪些产品，也不证明网站文字中的每条技术或商业声明已获自动答疑批准。

## 固定邮箱后的产品判断

每项客户需求由可信业务系统按以下顺序给出一个检索结果，四个品类业务员只处理与自身专业相符的内容：

1. 查固定邮箱对应官网的已确认产品覆盖。命中后，检索该产品已审核、适用于本次用途和市场的资料，由对应品类业务员答疑或采集缺项。
2. 官网未覆盖时，查共同交易主体的公司总产品目录。目录确认有此产品，则由对应品类业务员在内部提供专业内容，在原邮箱、原客户会话统一回复。回复只表述已获批准的公司产品事实，不将其他官网的页面、品牌、专属价格或图纸当作当前品牌的对外资料。
3. 公司总目录确认没有该产品时，按该项需求转人工，不自行推荐另一官网或改用另一邮箱。目录缺失、版本不明或仅检索无结果时，保持“未确认”并交内部核实；不能把检索失败当作确认没有产品。

网站覆盖、总目录有货与已批准的规格声明是三种不同事实。目录命中只证明该产品在已审核供货范围内，不能据此生成型号尺寸、库存、性能、价格或交期。正式报价及其他既有人工权限继续按需求判断；一个需求转人工时，其他独立常规需求仍可由相应品类业务员辅助，同一固定邮箱统一对外沟通。

## 对接与核验

首次开发邮件应在生成草稿前完成官网与邮箱选择，并为该客户保存固定邮箱；现有会话的来信和自选频率跟进直接读取这一绑定。选择、锁定、发件邮箱和签名由可信编排及发送程序执行，Agent 只能给出内容片段和内部建议，不能选择或更换发件地址。发送前重新确认客户绑定、官网配置、目录版本、人工接待状态和实际发件邮箱一致；失效草稿重新生成。

本文件是业务与接口设计。实际官网覆盖表、公司总目录、邮箱连接和自动发送尚需接入；当前三个邮箱不代表连接已建立或已有获准产品记录。
