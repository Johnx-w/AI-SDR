# ShadeFlow · 外贸窗饰获客工作台

本地长期维护项目，路径 `D:\CodeX\ai获客`。采用 React 19、TypeScript、Vite、React Router、Lucide 图标与独立 Node.js API 服务。

2026-10-21 开始迁移 Node.js 直连获客：服务端支持 Tavily → 官网补全 → DeepSeek → 飞书，保留 n8n 回退入口。通过 ACQUISITION_PROVIDER 选择引擎，接入、核验与恢复说明见 [迁移说明](docs/native-migration.md)。以下旧版 n8n 说明仅适用于 n8n 模式。

现在可在“API 连接”页填写并更新直连凭证，在“获客任务”选择单次、每天或每周定时运行，并在“自动获客”页暂停、恢复或关闭计划。时间统一使用北京时间，本机后端需保持启动。配置与调度的存储、恢复规则见 [API 连接与定时获客](docs/connections-and-schedules.md)。

直连引擎已接入官网自动评分、T2当前评级与T12评估历史。客户库 → 企业详情 →“评分与历史”可重新研究并评级，保留当轮依据和版本。当前海关项保持未知，后续接文件导入；规则、表结构和恢复说明见[自动评分与T12](docs/automatic-assessment.md)。

## 启动

要求 Node.js 24+，批量任务使用内置 SQLite 持久化队列。

```powershell
cd D:\CodeX\ai获客
npm install
npm run dev
```

网页：<http://127.0.0.1:5174>，API 服务：<http://127.0.0.1:4311>。

```powershell
npm test
npm run build
npm start
```

生产构建本地预览使用 <http://127.0.0.1:4311>。开发进程会监听文件修改。

自动获客支持每次新增 1–200 家，默认 20 家，后台逐家处理并自动补找。进度、停止、继续及任务历史保存在本机，详见 [批量收录说明](docs/batch-acquisition.md)。

## V2 演示界面

依据提供的两张设计图调整为青绿色工作台，保留 React / TypeScript / Vite 与独立 Node API。客户库沿用 `D:\CodeX\ai获客系统` 的客户线索结构，增加数据切换。

- 运营总览：待处理事项、演示运营指标、漏斗、优先跟进客户、任务进度与回复趋势。
- 客户库：演示客户 / 真实获客切换，市场、评级、产品、状态、来源与匹配筛选；搜索、分页、CSV 导出与详情。
- 真实获客：通过服务端 `GET /api/v1/leads/real` 实时读取飞书记录，支持上游分页。查看画像、匹配结论、官网事实、联系方式和原始字段；没有评分的客户显示“未评分”，不将任务目标国家当作实际所在地。
- 联系方式补全：详情页域名与来源页可直接点击；在“联系方式”中自动核实当前官网页、首页及已发现的站内联系页，支持手动重新读取。电话、邮箱均附来源和原文证据，本次补全不自动写回飞书。电话链接使用已规范化的国际号码。
- 绿色品牌主题：深绿色侧栏、浅绿色主界面，左上角使用四条窗饰线条与 ShadeFlow 标识。真实客户列表和详情优先显示官网 Logo，失败时使用网站图标，再降级到文字缩写。品牌资源独立异步读取，不阻塞客户表，服务端缓存一小时。
- 获客任务：创建、暂停、继续与完成 mock 扫描。真实获客仍走独立的 n8n 工作流页面。
- 沟通中心：待处理 / 全部会话、搜索、编辑与保存回复草稿、附件移除、四类回复识别、人工审核与模拟发送。审核后新增本地跟进事项，不调用真实发送接口。
- 产品与资料：产品目录、技术资料和沟通模板，支持检索、分类、预览与下载演示说明。
- 策略设置：市场、时区、每日额度、人工审核与跨渠道冷却偏好，全部仅保存为本地演示设置。

演示样本使用浏览器 `shadeflow:workspace:v3`；旧版本演示缓存保留，当前版本不混入真实客户。首页趋势与漏斗是独立演示汇总，待处理与跟进数根据本地实际演示状态计算。

## 保留的功能

- 业务总览：客户统计、历史聚合演示趋势、优先客户、可勾选待办与 CSV 导出。
- 客户线索：搜索、市场与等级筛选、分页、批量状态更新、CSV 导出、添加客户、画像抽屉、跟进待办。
- 多渠道触达：演示计划创建、启用与暂停、跟进序列查看。
- 统一收件箱：搜索、未读筛选、示例英文模板、回复草稿自动保存。
- 数据洞察：根据当前客户计算市场、等级和来源分布；独立历史趋势明确标注演示样本。
- 自动化中心：原 n8n 流程结构说明、真实参数表单、Webhook 提交、JSON 结果与导出、可选真实执行记录。
- 设置：本地偏好保存、集成状态说明、客户备份、演示数据恢复。
- 桌面与窄屏响应式布局、语义化表单与可键盘关闭的原生 dialog。

## 数据边界

除自动化中心和客户库的“真实获客”外，业务数据均为 mock，虚构客户域名使用 `.example`。不会发送邮件或 WhatsApp，不会自动将真实 n8n 结果写入 mock 客户列表。操作通过 `WorkspaceRepository` 保存到浏览器 localStorage。首页历史趋势是独立聚合演示样本，不代表客户表的实际历史。

真实 n8n 工作流：<https://vynox.app.n8n.cloud/workflow/EycE9OmaPkRFUDSq>。

2026-10-19 已修复原入库节点仅匹配澳洲电话导致美国号码漏采的问题。`构建飞书记录` 节点与本地官网补全使用同一提取函数，支持美、澳、英、阿联酋号码及国际格式、电话/邮件链接、JSON-LD 联系字段与公开邮件保护编码，并规范去重。搜索、画像、身份键、写入分流与既有飞书记录保持原逻辑；没有为此重新执行付费搜索或批量写回历史客户。

飞书只读工作流：<https://vynox.app.n8n.cloud/workflow/n5emHnlFL4iTQSNW>。该流程独立于原获客链路，复用现有 Header Auth 与飞书自建应用凭证，仅获取 token 并读取客户记录；不会触发 Tavily、Dify、写入或发送。服务端通过 `FEISHU_READ_WEBHOOK_URL` 配置入口，复用 `.env` 的 `N8N_WEBHOOK_SECRET`。不把密钥、token 或 Webhook 认证头交给前端。

2026-10-19 已验证只读接口返回 7 条飞书真实客户；数量会随飞书数据变化。详情中的匹配结论、事实和研究时间来自原始记录；公开联系方式未验证投递。

Codex MCP OAuth 是开发工具的授权，不自动提供给本网页。网页使用独立服务端 Webhook 凭证。**没有配置 Webhook 时，界面会明确显示“等待接入”，禁用真实运行；不会退回 mock 成功。** 真实运行会沿原 n8n 逻辑调用 Tavily、Dify 并写入飞书。此版本不提供 iframe 编辑器。

## 项目结构

```text
src/app/          路由、应用壳、工作区状态
src/components/   通用界面组件
src/domain/       业务模型与仓储契约
src/data/         虚构业务样本与已核对的流程结构
src/services/     mock 仓储、未来 HTTP 仓储、n8n API 客户端
src/pages/        页面
server/           同源 API、Webhook 转发、可选执行记录与静态托管
tests/            服务端契约、幂等、失败与凭证边界验证
docs/             n8n 接入与后续开发说明
```

详细接入步骤见 [n8n 接入](docs/n8n-integration.md)，后续业务接口见 [架构与 API](docs/architecture.md)。

## 当前限制

应用为本机单用户开发版本，服务仅绑定 `127.0.0.1`，没有团队身份认证。上线公网前需要服务端会话、权限、持久化数据库、队列和运行审计。幂等记录当前保存在服务进程内，服务重启后不保留；超时任务必须先核对 n8n 历史。不得把 `.env`、平台密钥或用户凭证放进前端、Git 或公开部署包。
