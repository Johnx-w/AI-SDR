# 统一获客实施任务

状态见各项验收记录。共同需求、参数和指标见[实施规格](spec.md)。原有七项功能保留，新增 00，共八项。依赖表示集成验收的前置，开发者可先并行处理互不冲突的部分。

开发期间完成采集对照和 Linux 依赖验证；全部功能统一验收后执行标准合并和云端发布。生产获客任务由用户自行启动，历史数据处理另议。

| 任务                     | 前置       | 用户能验收的结果                                         |
| ------------------------ | ---------- | -------------------------------------------------------- |
| 00 Scrapling 采集验证    | 无         | 可重复采集对照、兼容性与资源基线，后续采集接入有依据     |
| 01 官网准入与采集接入    | 00         | 从任务入口自动补抓必要证据，读到主体正确的合格企业       |
| 02 唯一新增与人工补证    | 01         | 重复候选、补录、重试由同一套主库结果计数                 |
| 03a 获客计划支持所有国家 | 无         | 创建和编辑全球计划，按已保存范围到期执行                 |
| 03b 跨批累计新增         | 02、03a    | 一个目标跨国家、跨批持续累计，所有批次共用受限采集队列   |
| 04 执行中断与恢复        | 03b        | 工作进程故障或服务重启后接续，清理子进程并核对记录与计数 |
| 05 地图发现对照          | 02         | 地图发现的企业也走同一准入和去重                         |
| 06 统一验收与发布报告    | 00、04、05 | 全功能对照验收、标准云端部署及实测报告                   |

### 00 Scrapling 采集验证

在开发测试环境锁定 Scrapling、Python、浏览器及系统依赖，用受控网页验证采集方案。固定快照回放和美国／澳大利亚现场配对随开发持续执行，结果随实现版本迭代，最终纳入 06。最初可用的采集接口及环境结论使 01 能集成；对照退化由后续开发修正后统一复验。

开发入口、样本和分阶段验证结果见[采集开发验证](collection-validation.md)。

- [ ] 核对目标 Linux 环境、当前正常业务负载及 Python 兼容性，完成锁定版本的安装、浏览器启动、页面返回及进程退出验证。记录实际依赖版本与安装步骤，生产发布使用验证过的依赖。旧的可用内存快照只作参考。
- [ ] 固定 HTML、模型与规则，对比现有清理和新版证据选择。预先标注主体、否定、用途、经销与制造并存、第三方归属，核对原文位置和被保留事实。
- [ ] 现场首批建议美国和澳大利亚各 30 家，静态／动态／曾失败页面分层；两条采集路径使用同一候选和目标页，交叉顺序并重复。记录网站变化及独立真值，四家合作样本另外校准，已有客户不计新增。
- [ ] 输出初步采集成功率、必要证据齐备率、耗时、Python 与浏览器子进程树及整机内存峰值，区分实测与预期。成本和 token 在具备完整正常研究入口后补齐，并在 06 交付最终配对结果。

### 01 官网准入与采集接入

运营从立即或定时任务收到有出处的“收录／排除／待核实”结果。将现有身份复核、产品抽取和准入判断接在所有写入路径前；复用原文，限制同一缺口的补查次数。证据不充分的候选让出队列。以交接案例的冻结原文预先标注真值，在现有 native-acquisition 与 customer-eligibility 套件加入回归。

- [x] 在正常入口贯通页面缓存、Node 直接读取、按需 Scrapling 补抓及外部提取回退。Node 管理独立 Python 工作进程与结构化返回，保存每页的原始与最终 URL、采集时间、方式、状态、原文、哈希和触发原因。
- [x] 从同一任务处理两家需要不同补抓路径的合格企业和一个只有动态空壳的对照，补齐前两家的必要证据并正确收录，对照保留待核实。网页抓取成功但身份不符时按业务规则判断。校验重定向、子资源公网访问与网站归属。
- [x] 验证压缩后的身份、法律声明、否定及制造／经销上下文完整。分别验证定制零售、本地完整成品加工、混合自产经销、纯自产配件的收录与排除。缺证候选继续自动补查并让出队列。

- [x] 对 Hillarys、暂按 VD 解读的 Vision Decor 分别核对经营主体、域名与主营，实际收录 2 家。GaLaBau 主办方排除。只有参展页的被介绍企业待核实。检查档案列表、原文和执行记录。
- [x] 为准入表逐行配正反例，包括纯自产配件与经销、成品优先、家用与商业项目、遮阳伞和挡烟帘、客户自备与供货不明。旧目录信息不足时保留缺口。
- [x] 在采购证据中分别输入明确采购窗帘布、明确否定采购窗帘布、仅采购办公用品，核对三者的需求字段、评级依据和首发选材。合格经营事实足以入库。

本地隔离任务、快照、定时轮次和采购证据回放见[验收记录](acceptance.md#已执行的隔离验证)。Vision Decor 的经营证据已核实，交接简称「VD」的对应关系待确认。

### 02 唯一新增与人工补证

把立即、定时与“核实并尝试入库”的持久化、读回和新增归属接通。依托现有 batch-jobs、acquisition-review-api 与主库检查，给执行页提供可核对的结果及理由。

- [ ] 页面快照、提取版本、原文位置和主体核验相互关联。模型缓存键包含主体、内容、规则、提取、模型及提示词版本。重复 URL／企业在付费研究前识别；改官网、改规则、证据变化时旧结果失效并重新判定。
- [ ] 对两家主体使用不同采集方式和相同／变化后的网页，核对有效命中、失效重判、并发复用及原文引用。补证只重判受影响事实，最终同时保留有效机会与冲突，已有排除或待核实不会永久阻止新证据。

- [ ] 两家主体共用一域名但各有独立经营证据时分别入库；同主体换域名或重复命中仍一档。仅有名称近似的候选暂存。并发到达时重读档案、来源和计数与预标结果一致。
- [ ] 缺证候选更正官网后，自动补证成功与人工裁定成功均可入库，保留依据、操作者及时间。人工新增单列，累计总数只增一次，历史轮次计数不变。
- [ ] 写后读回不明时保持待核对。模拟写成功应答丢失和镜像不可用，恢复后各以主库结果计数。已存在客户、多个供货方向及模型给出的评级均不增加新增数。

### 03a 获客计划支持所有国家

本项可独立编排。修改新建和编辑计划的国家选择、API 校验与存储、搜索预览、到期调度、发现和研究的国家匹配。先让全球和单国范围在正常入口走通，再扩展总目标与跨批执行。

国家范围按任务保存；采集与缓存使用真实 URL 和企业证据。后续报告可按市场比较采集成功率，03a 可与 00 并行。

- [x] 从获客计划页面创建一次性“所有国家”计划，保存后刷新并进入编辑，核对范围和时区。用测试时钟触发，保存的计划、实际查询、执行详情三处一致。再从单国编辑为全球，下一次重复计划按新范围执行，之前轮次仍显示原范围。
- [x] 在隔离库注入有原文证据的美国和法国窗饰商（法国在旧 25 国选项之外），另加无关旅游企业。全球计划收录前两家，逐家读回真实属地，旅游企业无新增。用同一输入运行美国计划，仅美国合格企业新增，两次各用空测试库。
- [x] 已有单国计划按原时区、原范围触发。空值、无效旧范围及地区字段冲突在到期时暂停，等待重新选择。企业属地未知时保持未知。搜索预览及供应商请求均省略全球范围标签。

本地在 Edge 核对页面保存、刷新和编辑。`connections-and-schedules`、`native-acquisition` 与 `scheduled-acquisition-ui` 测试覆盖定时计划与回读，使用测试时钟、隔离 SQLite 与冻结的官网和供应商响应。样本为两家窗饰商和一家旅游企业，全球与美国轮分别新增 2 家和 1 家，档案差异符合预期。真实供应商覆盖率和生产运行留待统一验收。

### 03b 跨批累计新增

用户设置目标数即可立即运行或定时开始。后台以同一任务持续调度市场、语言及搜索词。内部批次继承进度，按剩余名额协调并发。展示实际覆盖和剩余，不要求设置角色、国家配额或逐条审核。

- [ ] 跨批次、跨任务限制为服务器全局一个活动浏览器页面，队列有背压与等待原因。分别模拟两个批次需要动态页和一个可直接读取的任务，核对资源限制、进度及健康路径产出。内存暂缓不造成业务误排。

- [ ] 隔离数据集预先列出不同国家、两个合格角色和一个个人自用对照。以单个目标执行，验证搜索角色与实际经营角色不同仍按定稿入库，检索国家不能填入未知的企业属地。
- [ ] 用模拟时钟、足量唯一候选与重复项跨越 200 家和内部时限；验证超过单批容量的自定义目标可跨批累计、末批并发时准确停止。网页关闭、服务重启后仍回到同一任务。
- [ ] 已运行的旧任务保持原规则版本和累计结果；稳定夹具核对切换前后。展示当前吞吐与剩余，区分候选耗尽和执行中断。

### 04 执行中断与恢复

在任务页展示用量、暂停原因和“继续”。复用执行游标、原操作查询和供应商队列。复用有效缓存，记录已完成步骤。此项验收用替身及隔离库。

- [ ] 注入 Python 崩溃、浏览器单页超时、进程树内存超限、低可用内存及外部提取失败，按规格回退或延后，保存阶段与原因，有限重启。完成、取消、重启及部署维护后无遗留浏览器子进程。
- [ ] 完整快照直接复用，未完整保存的页面按缺口补取。切换采集器仍沿用原任务和操作，验证主库写入阶段恢复优先读回，失败采集不产生业务排除。
- [ ] 按规格起始参数实测全局并发、超时、两次补抓预算、约 1GiB 进程树限制及系统余量门槛。记录最终参数、主应用响应、CPU、磁盘与峰值内存，快照清理遵循保留策略。

- [ ] A 已入库、B 已抓页待模型、第三条重复 A 时模拟服务重启。恢复执行后，B 不重新抓页，A 只计一次。单独在写成功未读回时中断并重启，两次点击继续，确认调用与读回账均无重复。
- [ ] 检查付费请求结果未知、已派在途返回及缓存失效。列明哪些结果可复用、哪些需核对；以供应商请求日志对账。执行详情显示已完成步骤、剩余目标及未决操作。

### 05 地图发现对照

复用地图原型中适用的发现能力。取得地点线索后定位独立官网，沿用 01、02 的判定与写入。先核账号与可留存字段，记录允许的数据、来源和验证环境。自动定位受限时报告该路径可用能力，官网主量任务继续。

- [ ] 地图候选官网使用统一采集及缓存。分别核对地图发现的独有合格新增、Scrapling 补抓后找回的合格新增以及重叠集合，避免同一家同时被归为两个互不重叠的增量。

- [ ] 隔离提供方返回独有门店 A、与官网搜索重合的 B 和无法定位独立官网的 C。核对 A、B 各有一档；B 可追两源，C 待核实。多个门店归同主体时再次核对。
- [ ] 用同市场、同品类比较独有合格新增、共同发现、总消耗及每家成本；只读位置编号的模拟不能作为真实账号与定位能力验收。
- [ ] 注入地图错绑、权限不足、暂时限流。核对地图路径状态、已保存进度及官网路径连续性。共享身份核验遭污染时，所有依赖路径暂停自动入库。

### 06 统一验收与发布报告

将每次验收的采样框、独立真值、来源、版本与执行结果关联，完成 00 的开发配对验证及全部功能的统一验收。隔离库承接采集、模型研究和实际写后读回，记录受控现场读取与服务调用的真实消耗。生产获客由用户在安全部署后自行启动。

- [ ] 汇总两条采集路径的采集成功率、必要证据齐备率、自动收录确认合格率、合格企业漏收、单家实际合格新增 token 与总成本、耗时及进程树和整机内存峰值。失败和回退也计费；零新增展示总消耗。报告证据压缩丢失、缓存命中和失效，实际节省比例由配对结果计算。
- [ ] 自然样本在预筛前抽取并按主体去重，人工盲标、分歧裁决。分别交付自动收录合格率分子、分母和区间、人工无法判断数、漏收原因及官网错绑；挑战组独立报告。99% 作为放量目标；样本不足注明范围并继续校准。
- [ ] 展示各来源的去重新增、自动和人工贡献、单位成本、调用数、缓存命中、小时产量、剩余时间及预计缺口。
- [ ] 销售是否接手、拒绝原因、报价或订单能追到对应企业与记录，缺少记录标未知。最终运行报告同时给出适用范围、实测国家与路径、预期及实际数量、差异，区分模拟通过与真实产量。
- [ ] 所有任务集成后运行仓库要求的格式、完整测试、构建和专项验收，按固定比较基线执行 Standards 与 Spec 两轴 code-review，修复后复验受影响行为。pr 描述提供行为变化、证据、依赖安装和版本回退影响，默认省略工具署名。
- [ ] 按仓库标准流程合并最新 main、推送功能分支、等待同一版本 CI 通过并合并 PR；继续跟进 main 的 CI 和自动 CD。确认备份、维护结束、Linux 浏览器依赖和受限工作进程可用，以只读方式核对实际部署 SHA、进程目录、健康、日志和相关页面／API。异常按仓库恢复流程处理，保留生产数据及配置。
- [ ] 交付最新提交、任务状态、PR、CI/CD、云端 SHA、备份位置、统一验收报告和待生产运行验证的范围。将开发实测及环境不可用导致的未验证项逐项记录，避免以接口模拟推断真实账号权限或线上收益。

交付前从现有测试入口检查立即、定时及人工补录的调用方，并同步实际切换的获客主题和 ADR。安全发布属于完整交付。生产获客启动由用户负责，历史数据处置另议。
