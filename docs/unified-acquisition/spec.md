2026-11-27 业务定稿，实施中。Scrapling 调整方案已确认，替代 79fc610 中的采集设计；业务准入沿用定稿标准。代码对照 main 的 93144d8，开发开始时核对最新主线。适用于新建的统一获客任务。[实施任务与依赖](tasks.md)

完整交付包含原有七项功能、Scrapling 采集与证据处理、开发期间对照验证、统一验收及标准云端发布。全部功能验收并安全部署后，由用户自行启动生产获客任务。历史数据处理另议。

## 业务结果

运营在一个任务里填写新增目标，选择立即或定时开始。默认搜索全球、全部合格窗饰品类和企业角色，无国家配额。网页关闭后后台继续；普通候选缺证不要求值守。运营能看见已确认新增、还差多少、哪些渠道带来新企业，以及任务当前状态。

新增单位是经营主体。同一企业跨门店、品牌、国家、域名、发现渠道和供货方向都只计一次。企业首次写入 SQLite 主库、按档案身份和归属读回且取得唯一新增归属后计数。人工补证后首次入库也计入实际完成期间的总新增，归到有关任务，自动与人工分列；历史批次数字不回填。已有客户命中只标重复或已有。销售接受、交接就绪、可首发及飞书镜像各自记录，不影响新增。

## 从候选到企业

1. 官网搜索承担主量；地图商家是首个外部发现对照。保留合法可存的来源标识、候选官网、被提及企业和发现任务。查询词、地图点位和个人联系人仅用来找企业。核对实际账号权限、字段留存约束和自动定位官网可行性后启用地图；地图不可用时官网继续。比较同市场与品类的地图独有、官网独有、共同命中及总成本。海关、目录、招投标和社媒保留为后续选项。
2. 尽早用已有身份索引去重。域名或企业名只用来找可能相同的对象。用法律声明、条款、经营名称、供货主体等解决同域多主体、多域同主体。第三方页面的运营者与被介绍者分别判断；集团成员只用能归属自己的经营证据。
3. 用 DeepSeek Flash 阅读多语言官网，保存身份、产品、用途、供应或制造角色、主营依据、原文出处和取证时间。主营可有多项，从整体定位或系列、询价、交付等官网事实判断。拟收录结果复核身份、业务引文和反证，优先复用同一份原文；固定页数、额外付费调用次数均不作业务门槛。
4. 输出收录、业务排除或待核实及理由。缺一项关键事实就定向补查；对同一缺口限制补查次数，耗尽即暂存并继续下一家。新证据或更正官网可重判。技术失败、重复、写入待核对各自显示。人工记录操作者、更正内容、证据和裁定，使用与自动流程相同的准入与写入入口。
5. 同一主体可有多项供货机会。区分经营产品、我方可供方向、已核实的历史进口及当前采购。采购事实核对主体、对象、时态、否定和用途；档案、评级与首发选材消费同一份核实结果。公开采购意向、采购量、联系方式、账号分配与销售接手均非收录条件。此任务默认仅获客。

## Scrapling 采集、证据提取与复用

本地实现已覆盖新轮次的采集、快照、准入、主体去重、唯一新增归属和人工补录。跨批、快照清理及运行恢复按任务继续实施。见[任务与验收](tasks.md)。

### 职责与调用顺序

本轮先交付官网获客闭环，地图对照限隔离供应商替身。正常任务即使环境带有 Places 凭据和诊断开关也只执行官网搜索。地图仍是未来首个外部发现对照，真实接入和成本验收暂缓。Scrapling 负责候选官网的页面补抓和程序提取。后续接入获准使用的名录时可复用其多主体、链接提取能力，渠道选型继续分别验证。准入判断、采购事实和新增计数使用统一业务流程。

现有 Node 官网采集已有直接读取、外部提取、正文清理、重复文本压缩、输入长度限制和精确模型请求缓存。新增路径在该流程中复用这些能力，按以下顺序执行。

1. 检查可复用的页面快照。缓存有效时复用，失效或存在关键缺口时取证。
2. 先直接读取官网。正文能够支持本次身份和经营判断时进入证据处理。
3. 动态空壳、加载不完整或直接读取失败时，按具体缺口调用 Scrapling。补抓限于必要的身份、产品或服务页面，保存触发原因及尝试次数。
4. Scrapling 失败、不可用或资源不足时，依据剩余尝试预算使用现有外部提取回退。连续失败保存原因及待补事实，让出候选队列。
5. 各采集方式返回统一的请求 URL、最终 URL、抓取时间、方式、状态、原文快照、内容哈希及缺口。引用和身份归属从该证据链核查。

Node 管理单个独立 Python 工作进程，以结构化请求和结果调用 Scrapling，进程只承担采集和提取。任务状态、游标、SQLite 写入及新增归属由原 Node 流程统一管理。同站采集可以复用会话，不同站点隔离会话。锁定并验证 Python、Scrapling、浏览器及必要系统依赖版本，覆盖 Linux 部署、依赖安装、启动探测、日志和回退。以开发期间的配对结果确定具体错误类型的回退顺序和尝试预算，避免每页固定遍历所有采集器。

### 必要证据与 token

程序提取链接、公开联系入口和结构化字段；身份、供货角色、用途、主营及反证交给模型与统一规则核实。保留原始页面和证据位置，送入模型的片段携带标题、相邻段落、出处及主体信息。法律声明、否定、第三方归属、制造与经销并存等上下文必须保留。选择器匹配和结构化声明须核查其归属。

在现有清理基础上去除重复导航、Cookie 控件及重复模板文字，优先选择本次缺口所需证据。仅补足新事实时重判受影响部分，最终判定仍检查已有冲突及其他有效机会。单纯按关键词裁剪或先生成模型摘要可能损失关键事实，证据压缩须通过固定快照回放核对。

进入付费研究前按已核实身份和 URL 去重；页面缓存按规范 URL、时间及内容版本识别；提取缓存包含内容哈希和提取版本；核验缓存包含主体、证据快照、规则、模型、提示词版本及适用范围。更正官网、变更证据或规则后重判，旧的待核实或失败不能永久挡住新的有效证据。并发命中复用同一有效结果，身份歧义继续按主体证据解决。

分别记录模型输入、输出、服务商缓存命中 token 和应用直接复用次数。预期节省来自机械字段提取、无关正文减少、重复企业研究减少和补证后局部复核。抓取更完整也可能增加有效输入及模型调用，最终按实际合格新增的总消耗比较。各候选的失败尝试与外部回退费用均计入该组总数。服务器固定费用与可归属资源占用分别展示，新增现金支出以实际费用为准。

### 资源限制与故障恢复

云端配置为 2 核 4GB、80GB 磁盘。此前约 1.8GB 可用内存、57GB 可用磁盘和 Python 3.14.4 为时间点快照。开发验证前重新核对目标 Linux 环境与常规业务负载，依赖可安装性和浏览器运行兼容性纳入交付。

下列数值为已确认采用的试验起始参数，根据开发实测调整并记录最终值及理由。

| 项目       | 起始参数与验收要求                                                       |
| ---------- | ------------------------------------------------------------------------ |
| 浏览器并发 | 服务器全局一个浏览器采集任务、一个活动页面，跨批次共用限制               |
| 超时       | 浏览器单页约 20 秒，Python 单请求含启动硬超时约 30 秒                    |
| 补抓量     | 每家先最多两次浏览器补抓，仍受站点页面及尝试预算限制                     |
| 页面资源   | 优先阻断图片、视频、字体和追踪请求，保留必要脚本，按实际内容等待         |
| 内存       | 抓取进程树先约 1GiB 硬限制，系统可用内存低于约 1GiB 时暂缓新浏览器派单   |
| 磁盘       | 快照和日志有容量、保留期及清理规则，正常采集关闭截图、视频与完整网络记录 |

资源限制覆盖 Python 和全部浏览器子进程。浏览器崩溃、超时或内存超限后清理完整进程树，保存阶段及原因，回退或延后该候选。观察主应用响应和健康状态，资源不足时健康采集路径仍可按负载继续。有限重启避免持续故障消耗资源。暂停、服务重启及部署维护期间回收在途采集并保存已完整取得的页面。

公网地址校验覆盖入口、重定向和浏览器子资源，保留现有私网访问与地址解析保护。最终 URL 与企业官网归属须核对；跨域返回不能自动继承原身份。任何采集失败都记录为采集状态，企业业务排除仍需充分证据。

恢复时先复用完整快照和已确认核验；部分结果标明未完成阶段。原操作已进入主库写入时先读回确认，任务重启、重复点击和供应商回调不会重建企业或重复计数。采集回退也保留原任务和操作关联。

## 获客计划的国家范围（本地实现）

新建计划默认选中“所有国家”，同时保留指定单一国家的选项。范围随计划持久保存；用户可创建、查看、编辑计划，按需立即启动任务或按自己设定的时间启用计划。一次性及重复计划到期时均使用已保存范围。已有单国计划继续按原国家执行，旧记录缺值或范围失效时提示修正，不能静默扩大范围。

“所有国家”允许发现在现有 25 个单国选项之外经营的合格企业。新轮次交替安排无地区限制和含当地用语的地区定向查询；搜索地区和可选的搜索角色只影响检索。官网复核和写入使用任务保存的主范围，客户属地以官网证据为准，未知时留空。计划列表与执行记录显示“所有国家”，各次执行保留自己的范围快照和新增计数。全球计划按保存的计划时区触发。

## 无人值守执行与进度恢复

跨批累计与浏览器队列已有本地实现。受限进程运行、完整故障恢复及放量目标继续按任务 04 和统一验收执行。

- 一个对外任务可在后台拆成国家、语言、查询和执行批次。现有 25 国目录可作起点，记录实际覆盖并支持扩展；200 家、6 小时、查询上限和单批结束只影响内部批次。调度按合格新增成本、小时产量和质量分配流量，同时保留探索。达标后停止派新工作；并发在途通过原操作归属和剩余名额核对，保证目标与读回账一致。候选暂时耗尽则报告已尝试范围及可续跑位置。
- 先去重、复用网页及有效判断，再调用付费服务。缓存区分主体、证据快照、规则版本及适用任务范围；用户更正和失效证据触发重判。按供应商记录调用、实际或估算费用、命中缓存及失败；单家消耗以确认新增为分母，零新增时展示总消耗。
- 持久化任务 ID、查询游标、候选阶段、已取得网页与核验、操作标识、已知费用、在途结果及新增归属。已提交操作允许收尾；写入结果不明先按原操作查主库，付费响应不明先核对已有结果与可用的提供方记录，保留未决状态，禁止盲目重放。服务重启和重复提交恢复请求时，同一操作只生效一次。
- 执行记录汇总已新增、剩余目标、耗用及中断原因。普通待核实汇总展示。某路官网错绑时暂停该路径，健康路径继续；若错在共享身份核验，暂停所有依赖它的自动入库。修复后以错例和独立样本复验，再恢复。

## 放量验收与交付证据

### 开发期间采集对照

对照验证随开发实施，结果回写任务与最终报告。先做固定 HTML 快照回放，再做受控目标站点的现场采集，均使用隔离数据和正常业务入口。采集对照会读取公开目标网页，可按测试环境有效配置调用所需服务；记录费用与次数。生产获客计划由用户在完整交付后自行启动。

固定快照使用相同模型、提示词与业务规则比较现有正文处理和新版证据选择，核对身份、否定、用途、制造／经销及第三方归属事实的保留。另用固定证据比较缓存命中、缓存失效及补查恢复。

现场首批建议美国、澳大利亚各 30 家，覆盖静态页、动态页和曾失败页面，分层样本分别报告。相同候选和目标页面分别跑现有采集与增加 Scrapling 的路径，交叉顺序并重复测量，保留快照、运行版本及网站变化。合作样本另列，排除出新增分母。将地图发现增量与采集补抓增量分别核对。

配对固定输入至少包括两个可区分的合格企业和一个无关或缺证对照；另外覆盖本地完整成品加工、纯自产配件、第三方目录、动态页面及否定采购。程序提取不得丢失改变预期的上下文。实际页面无变化时核对两组差异；页面变化或独立真值不足时说明原因。已稳定复现的差异纳入现有套件。

零新增时展示该组消耗及零产量。正式报告同时列原始快照、独立真值、环境、模型和依赖版本、样本数与未覆盖范围。首批 60 家用于定位兼容性、资源和证据损失问题，99% 总体合格率仍需独立自然样本支持。对照出现退化时修正提取和回退路径并复验，综合正确性、漏收、单位成本、耗时及资源确定 Scrapling 适用页面范围。

从正常任务入口在隔离主库运行，使用固定搜索结果、官网快照、模型响应和供应商替身。按原始材料独立标记身份、域名、产品、期望判定与新增数。覆盖立即、定时、人工补证、双来源并发、重复、限流及重启。按两个可区分的适用对象加一个不适用或缺证对照验每类行为；可稳定复现者进入现有测试套件。检查漏项、错归、多余结果，以及关闭网页后的实际状态。

校准时从预筛前抽自然候选，独立盲标并裁决分歧；已知错例和挑战样本另外报告。自动收录确认合格率目标 99%，报告分子、全部自动收录分母、无法判断数和区间。以独立人工搜集集合补查未发现者，报告合格企业漏收比例及发现、误排、待核实、写入各环节损失。样本不足以支持放量时扩大核验；不把 99% 换成单家模型分数。运营校准另测来源归因、待核实积压、单位成本和小时吞吐，按每个任务的实际目标、耗时与进度报告。销售价值另报去重后愿跟进的新增、每家接手成本；有实际记录才报报价和首单。

交付报告注明适用范围、实际版本、环境、快照来源、样本数及未覆盖部分。Scrapling 收益、线上准确率、实际产量、地图权限及自动定位能力按实测证据记录。全部功能完成并统一验收后，按仓库标准流程合并、跟进同一提交的 CI/CD、部署与云端验收，由用户自行启动生产获客任务。生产验收使用健康检查及只读业务核对，历史客户的更正、合并、删除、重评单独立项确认。上线切换时区分既有任务和新任务的规则版本，保留既有运行计数，明确进行中任务的续跑边界。浏览器依赖安装、受限工作进程启动、维护清理与版本回退纳入发布和恢复步骤。
