## 结论

**当前主流程只有一条业务 LLM 入口：读取企业官网资料，形成有原文依据的企业画像、准入判断和评分事实。成熟 Flash 级或中档结构化语义模型适合作为主力起点，不需要所有客户默认使用最强模型；但现任务不能整体当成简单字段提取交给最轻模型。**

本机只读状态显示当前为 `native / direct`，网页提供方 Tavily，研究模型 `deepseek-flash`。代码对 DeepSeek 显式设置 `reasoning.effort=none`，不是使用提供方默认思考档位；这可以作为回放基线，不必立即判定不足，也不能仅凭成功返回 JSON 就认定够用。当前没有“疑难自动升级模型”的实现。[研究请求实际参数](D:/CodeX/ai获客/server/research-providers.mjs:71)

## 2. 现有研究为何不只是“提取几个字段”

单次返回 Schema 有 **21 个必需顶层字段**，评分机会最多 6 个，每机会最多 60 条事实。它需要区分经营主体与个人、法人和商号、兼营角色、成品与材料配件、销售目录与真实采购需求，并对任意必需条件输出“满足/不满足/未知”；不是把网页整理成漂亮摘要。[研究提示与 Schema](D:/CodeX/ai获客/server/company-research.mjs:15)、[机会事实结构](D:/CodeX/ai获客/server/assessment-evidence.mjs:26)

采集设计通常按 5 个 URL、每页约 16,000 字符规划，即约 8 万正文字符，另有提示词；**字符不是 token，亦非严格总上限**。canonical 跳转和提取分支可能增加实际研究页面，当前没有独立总 token 闸门。选模型应按实际输入及 16,000 输出 token 配额验证上下文与截断行为，而非只看宣传的上下文窗口。批任务“目标数量×3”是研究尝试上限，不是每家公司固定调用 3 次模型。[采集与正文处理](D:/CodeX/ai获客/server/native-acquisition.mjs:332)、[批任务上限](D:/CodeX/ai获客/server/batch-jobs.mjs:125)

## 3. 一般什么级别够

以下是代码分析后的选型建议，尚未做本项目效果对比。

| 任务                          | 建议起点                                                                    | 何时升级                                                                                              |
| ----------------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 当前整包官网研究              | 成熟 Flash 或中档、指令遵循和结构化语义能力稳定的模型；先评测现有非思考配置 | 法人/品牌冲突、多语言复杂官网、证据跨页矛盾、条件判定反复错误时，对少量案例试中高档模型或更高推理档位 |
| 将来拆出的单字段提取/简单分流 | 更轻、更快模型，或继续用确定性代码                                          | 只有拆分任务回放达标后才下放；不能直接据此降级现整包研究                                              |
| 未来销售常规答疑与需求收集    | 有审核资料约束的中档模型                                                    | 跨品类商务、复杂约束与冲突处理可试更强模型；缺资料仍须澄清或人工处理                                  |
| 未来原始图纸识读              | 具备实际视觉输入能力的模型，配合 OCR/CAD 工具与人工审核                     | 细小标注、复杂部件/公差需要更强视觉能力；模型输出只形成图纸参数候选，不能自动成为已确认规格           |

官方定位可作参照：OpenAI 将 Luna 放在明确范围、分流及高频自动化侧，Sol 兼顾复杂任务的质量与时间成本，Astra 面向模糊问题和深度分析；同一模型还可选择不同推理档位。官方也建议用相同输入比较，保留达到质量要求的较轻设置。**这不是上述品牌与其他厂商的一一等价表，也不是本项目已验证的可用模型名单。**[OpenAI 模型选择](https://developers.openai.com/api/docs/guides/model-selection?site_locale=en)

DeepSeek 当前官方表中，`deepseek-flash` 对应 V4.1-Flash-1017，`deepseek-v4-pro` 对应 V4-Pro-0813；版本不同，不能仅凭 Pro 名称认定更适合。两者有 JSON/Responses 能力；表中 Flash 支持视觉，Pro 不支持，因此未来图纸也不能简单“升级 Pro”。[DeepSeek 当前模型能力](https://api-docs.deepseek.com/quick_start/pricing/)

批准后的结构化图纸参数答疑可使用文本模型；准确检索 SKU、版本、单位及审核记录，不必每次重新调用视觉模型。直接读取 DWG/DXF 对象与测量仍需要专门 CAD 解析工具，不能仅靠升级文本模型。

推理档位也不能跨厂商照抄：DeepSeek Responses 明确支持 `none/low/high/max`，并支持 `json_schema`；思考模式文档另列出 `medium/xhigh` 映射到 `high` 的兼容规则。当前兼容提供方分支则走 `/chat/completions`，没有发送显式推理档位。更换时要核实真实接口、Schema、输出长度及参数兼容性；当前设置页选模型不等于已经具备分任务/分档位路由。[DeepSeek Responses 参数](https://api-docs.deepseek.com/api/create-response/)、[DeepSeek 思考模式与映射](https://api-docs.deepseek.com/guides/thinking_mode/)、[本项目两类请求](D:/CodeX/ai获客/server/research-providers.mjs:64)

## 4. 不能因换强模型而放松的最低要求

必须完整返回约定结构，事实带输入原文连续引文与真实来源 URL；无依据保持 null、空数组或 unknown。不得把目录写成采购意向、把住宅客群企业当个人、把美国披露口岸当加拿大买家经营国。引文命中只证明“这句话存在”，不自动证明解释正确；仍须检查事实归属与语义。评分和身份关联继续由代码控制，不能把更强模型当成自动合并授权。

未来销售报价只能引用适用且已审核的价格/政策，具体商务承诺仍逐封人工审核；图纸参数审核与图片外发授权分别保留。更换模型不改变这些业务边界。[商务承诺边界](D:/CodeX/ai获客/docs/adr/0006-review-commercial-commitments-separately-from-handoff.md)、[图纸边界](D:/CodeX/ai获客/docs/adr/0004-reviewed-drawing-facts-and-versioned-assets.md)

## 5. 建议先做 40 条固定回放，再决定升降级

可从 30–50 条起步，建议 40 条：12 条普通窗饰官网、8 条法人/品牌及第三方主体冲突、8 条自产/销售目录/采购需求/必需条件语义边界、6 条海关买方与官网关联、6 条证据缺失/长页面/提示注入。海关关联案例评测完整流水线，模型仍只负责其官网研究部分。

冻结同一网页文本、目标条件与人工答案，对当前 Flash 基线和一个备选模型逐条比较：结构完整与截断、引文支持、关键字段与三态判定、误排有效买家/误合并主体、评分事实变化、耗时和实际 token。高风险错误单列，不用一个平均分掩盖；不要求无证据页面“硬提齐”。先确认错误来自模型、采集还是规则，再决定升档或拆任务。以上是建议验收设计，**不是已取得的通过率或模型排名**。

建议顺序：保留当前配置完成回放 → 修正采集/提示/规则缺口 → 再决定是否替换主力模型 → 有需要才实现疑难升级队列。不要先把整个项目所有模块统一换成最强模型。
