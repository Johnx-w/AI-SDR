## 已观察到的业务语义

- 页面读取 `#wmData` 下的 `page=globalSearch`，以及 `type`、`id`、`keywords` 等路由参数。
- 入口脚本使用 `detailDrawId` 及搜索初始条件；这是支持从搜索进入某个详情状态的静态线索，尚未核实实际抽屉位置和交互。
- 新手引导包含输入公司经营产品进行搜索、查看公司官网/联系人/主营产品详情的两步流程。这是公开脚本文案，尚未实际完成搜索。
- 页面代码检查 `GLOBAL_SEARCH` 等功能权限。不同套餐/角色实际可见功能未知，不能根据脚本中存在某模块就认定账号拥有该模块。
- 搜索、企业详情、联系人查询分别有SDK方法；因此接入评估必须分别确认它们返回什么、是否额外扣费，不能把“搜索有结果”当作“已取得完整联系方式”。

## 运行时验证结果

### 搜索、国家和分页

通过正常页面输入 `roller blinds` 并点击搜索，观察到：

- `POST /globalSearch/api/globalSearch/v1/search` 返回HTTP 200，业务 `success=true`、`code=0`。
- 当前继承的语种条件包括英语和西班牙语。未限制国家时显示84,808条结果；通过国家选择弹窗选择美国后，返回7,496条。计数是该次查询的返回总量，不是核实后的合格潜在客户数，也不代表已取得全部数据。
- 美国筛选的第一页和第二页各返回10条。请求页码分别为1、2，响应 `data.pageableResult.page` 分别为0、1；接入时须区分请求与响应的页码口径。
- 列表位于 `data.pageableResult.data`，总量在 `data.pageableResult.total`，另有 `data.realTotalCount`。
- 国家条件使用 `country: ["United States"]`，不能假定接收ISO两位代码。本次部分企业的原始 `country` 为空而 `standardCountry` 为美国，字段必须分别保留，不能用用户查询条件填造企业国家事实。

  "page": 1,
  "size": 10,

## 业务和前端设计建议（待产品取舍，未实施）

观察到的外贸通结构：顶部业务模块导航、左侧按业务步骤分组的功能导航；搜索首页突出关键词/公司/域名三个入口及产品相关词；结果页保留搜索与筛选，采用公司资料、联系数量和操作并列的列表；企业详情从右侧大抽屉展开，保留列表上下文；联系人按老板、管理层、采购、其他分组；结果上显示是否曾发邮件、是否同事线索等历史标签。

建议本项目采用以下流程，而不是直接把外部搜索结果全部写入飞书：

```text
产品 + 国家 + 数据来源
        ↓
外部候选预览（匹配原因、联系准备、既有开发提示）
        ↓
企业详情与联系人核实
        ↓
与既有档案去重、保留来源、补充或新建
        ↓
按本公司供货方向研究和评价 → 飞书同步 → 销售接手
```

| 外贸通设计中可参考的部分           | 本项目建议                                                           | 原因                                     |
| ---------------------------------- | -------------------------------------------------------------------- | ---------------------------------------- |
| 关键词/公司/域名分入口             | “找新客户”与“查找/补充已知企业”分开，复用国家和产品条件              | 新发现与档案刷新成果不同，避免重复计数   |
| 产品相关词与场景词                 | 将已生成的搜索词展示为可折叠面板，保留产出和人工调整依据             | 方便检查搜索方向，同时把主要空间留给结果 |
| 结果列表中的公司资料/联系方式/操作 | 用紧凑结果列表展示企业、国家、匹配依据、联系准备、来源和既有开发提示 | 销售能比较候选，不必逐家开官网           |
| 右侧详情抽屉                       | 详情内展示企业证据、联系人、评价及历史，保留结果页位置和筛选         | 减少列表和详情来回跳转                   |
| 历史联系与同事线索提示             | 显示外部历史来源和时间，与本项目开发状态分别记录                     | 避免把外部标签直接覆盖本项目的销售进展   |
| 联系人按岗位分组                   | 区分公司级入口、明确采购岗位、其他人员及待核实资料                   | 数量多不代表存在可用采购联系人           |

现有页面落点仍是 `Automation.tsx` 的发现入口、`LeadLibrary.tsx` 的企业档案及详情、`AssessmentPanel.tsx` 的评价依据/历史、`ContactPanel.tsx` 的联系资料。新增候选预览应与已收录客户库区分。官网研究和评价继续作为外部数据后的共享步骤，外贸通规模字段与职位信息应带来源，不直接作为已核实事实替换评分。
