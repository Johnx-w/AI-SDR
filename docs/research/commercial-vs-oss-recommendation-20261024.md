# 商业产品与开源方案比较及推荐实施方案

核查日期：2026-10-24。适用项目：ShadeFlow 外贸窗饰获客与四品类销售接待。

后续业务口径已更新为 [ADR-0008：宽泛收录与初始开发优先级](../adr/0008-broad-company-capture-and-initial-priority.md)。本文涉及完整 A/B 交接门槛或可交接产率的段落仅保留当时的研究背景；当前目标统计去重后实际收录企业数，未知采购、经营年限、海关或联系人资料单独列为缺项。

## 推荐选择与成本口径

**保留 ShadeFlow 的业务核心，海关与官网作为两条主要发现来源，采购可靠的数据和模型能力，直接复用成熟基础组件。当前不整体迁移到商业 CRM 或开源 Agent 平台。** 现有网易外贸通作为补充候选来源，先使用合同允许的导出或正式接口；重点企业确有联系人缺口时，再补充采购岗位数据。

海关 API 和大模型费用由公司承担。因此，不因海关生产激活费暂缓这一来源，也不为压低 token 单价牺牲研究质量。这里的“省钱”指公司总投入：数据、模型、订阅、服务器、开发、日常维护和人工纠错共同计算。报销解决个人垫资问题，不把这两项变成零成本。

这一选择基于当前已有的直连处理链、评分和证据规则；若成品能以更少维护交付同等质量，仍应采购。商业产品的主要价值是成品流程、供应商数据及服务支持，开源组件的主要价值是通用技术能力；二者都不会自动完成窗饰采购适配和主体核实。

10 月 24 日的[真实试点](live-acquisition-pilot-20261024.md)首轮研究尝试 9 次、模型请求 6 次，新增 0 家；后续 Signature 虽真实新增，但评分仍待补全、贸易关联仅名称匹配。另一任务将 ImportKey 第三方贸易页面当官网写入，不能计为合格成果。当前没有足够证据承诺稳定产率或真实单客成本。

另有两个实现差距需要先处理：当前 `BatchJobs.accept` 对新增编号及域名读回成功计数，未要求通过全部销售交接条件；每轮研究上限为目标数三倍，而后文 25% 合格率情景平均需四倍候选。应分别展示“新增入库”与“可交接企业”，把研究预算和补找约束到实际费用、次数和时长，不为达到目标降低质量。

## 海关供应商如何按效果选择

公司承担费用后，海关选型应优先比较目标市场的具名买家覆盖、字段和主体关联质量、更新、正式接口及问题支持，价格放到总投入里核算。

| 供应商           | 已能确认的交付                                                                                                                                                              | 对本项目的取舍                                                                                                                       |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| BillOfLadingData | [方法说明](https://www.billofladingdata.com/methodology)区分海关、提单及镜像数据，并说明逐国字段和运输方式有差异                                                            | 保留当前适配是最快路径；不能把镜像统计当逐票买家，也不能让其国家字段覆盖已核实官网经营国                                             |
| 腾道             | [官方 API 服务](https://www.tendata.cn/service/consult/#api)提供贸易、工商、联系人，列出调试支持及 5×12 服务                                                                | 作为首个商务替代候选；若域名/法人/联系人补全和中文支持能明显减少研究工时，较高报价也可能更省。总覆盖国家数不保证每国都有同样具名字段 |
| ImportGenius     | [官方 API 集成](https://www.importgenius.com/features/api-integration)列 REST/JSON、25+ 国家、记录/企业/元数据及集成支持；Enterprise 包含 API，部分 Business 国家套餐可加购 | 适合北美贸易刷新与专业支持的备选；按已订国家和字段审样，不从“每日更新”推断所有来源均完整日更                                         |
| Vujis            | [官方 API 页](https://www.vujis.com/api-pricing)列提单、公司、联系人、邮箱、统计及 REST/Webhook/MCP                                                                         | 技术接口可作为候选；逐国来源、实际字段、更新和支持尚未获得足够证据，暂不为宣传覆盖数迁移                                             |

给供应商同一组现有成交客户、已核实买家及物流/误词负例，要求提供相同产品和时间窗的样本与字段定义。比较每家合格企业的人工分钟数、正确官网和主体比例、有效新增及问题处理效率；成品可以替代贸易采集、标准化、更新及通用查询界面，窗饰适配、证据评分和企业归档仍保留在共享处理链。若只需销售人工查阅复杂贸易分析，可直接使用供应商界面并导入结果，不重建完整海关分析台。

## 模型选择和长期 API 账单

**先用同一组事实样本比较质量，再定主力与疑难处理策略。** 当前 `deepseek-flash` 是可用基线，不预设最轻模型必然够用，也不认为换 Pro 就能修复错误官网和错误计数。建议 40–50 个样本覆盖普通官网、品牌法人冲突、第三方资料页、当地工厂/安装商、组件采购推断和证据缺失。优先考核主体错认、无依据事实、漏掉有效买家及人工复核分钟数；通过后再看单次调用费用。

短期疑难进入人工核实；样本证明某个更强模型确有收益后，再接入疑难升级路由并保留出处。当前自动分级路由尚未实现。四品类销售接待可共用模型服务与审核后的知识，专业范围依靠规则和资料，不靠四份订阅。

### 月度运行情景

下表是**多轮月度规划假设，不是实际产率、账单或获客承诺**。N 表示去重且达到销售交接要求的新增企业；当前系统还需修正该计数口径。

- 假设候选合格率 25%，需研究 `4N` 个候选；每次发现查询取得 10 个去重后可研究候选，不是 10 个合格客户。
- 为混合来源预留 50% 候选另搜官网，Basic Search 为 `4N/10 + 0.5×4N = 2.4N` credits；实际海关买方常需逐个定位，官网来源通常不需要。
- 假设 20% 候选回退提取，每次成功五页，Extract 为 `0.2×4N×5/5 = 0.8N` credits。加 20% 预算预留后网页总 `3.84N` credits；预留不代表当前已实现自动重试。
- 单次模型预算 15,000 输入和 2,000 输出 token，峰值 `$0.0069`；不预支缓存及规则预筛收益，加同样预留后模型为 `$0.03312N`。正文字符上限不等于这个 token 假设。

## 部署维护与工程投入

起步用一台 Linux LTS 服务器、Node 24、静态前端、单个 API 进程及本地 SQLite，使用 systemd 或容器自动重启、反向代理提供 HTTPS。现有服务继续绑定回环地址；通过反代与经过验证的身份控制访问。公网团队使用前补应用登录、角色和审计；小范围试点可先限定私有网络。

每天做数据库一致性备份并加密复制到独立位置，保存配置恢复说明，定期实测恢复；云主机周快照作为额外保障，不代替数据库备份。部署前核查海关、搜索、模型、飞书及邮箱的实际可达性，不为便宜主机牺牲日常访问。Crawlee 浏览器、并发扩容、更多原始证据和附件会增加内存与存储，应另测后配置。

工程量仅作排期估计：已有代码基础上，主体识别/计数质量、费用控制、必要导入和单团队部署可预留 **8–15 人日**；这不包含完整四品类自动业务员、供应商 API 未知适配或真实资料准备。四品类真实接待还需独立做知识审核、模型和会话编排、人工状态、邮件授权与端到端验收，不能把安装平台当作完成。

日常维护应记录依赖更新、异常处理、备份恢复和供应商变更工时。以月 2–4 小时、内部折算 300 元/小时举例，维护机会成本为 600–1,200 元/月，另加销售复核；这只是核算示例，不是已测维护量或市场报价。它可能高于搜索和模型费，所以有报销条件时更应买成熟 API 和必要的托管服务。

商业方案胜出的判据为：`可节省的开发摊销 + 运维和复核工时价值 + 更高有效产出的价值 > 新增订阅、实施、迁移和接口费用`。不为追求全部自研而反复建设投递平台、通用 CRM 或爬虫基础设施。

## 分阶段实施与验收

1. **先修事实与成果口径。** 用已保存的历史失败案例验证目录/贸易页拦截、物流分流、国家与品牌法人关系、引文与评分；分别统计新增入库、待补全和可交接数。第三方页面误认官网的已知失败必须回归通过。评分不完整及名称级贸易关联不能自动包装成合格买家。
2. **海关与官网同时产出。** 继续完善当前海关主通道；官网通道覆盖无进口记录、品牌名与法人不同及非该海关覆盖市场的客户。相同市场、产品、时间窗下记录候选、排除、主体核实、交接、人工分钟数和 API 消耗；使用真实新增而不是行数比较来源。外贸通有正式授权的部分作为补充，共用去重与研究链。
3. **按质量确定模型和组件。** 用 40–50 个案例比较主力模型与疑难处理，基于事实错误和人工节省决定路由。只有网页失败/人工补页成为实测瓶颈才接托管抓取或 Crawlee。补月度费用上限、重试及模型调用上限、页预算与部分完成说明。
4. **交付可持续使用的工作台。** 实现获授权的导入/接口、团队访问控制、备份恢复和异常处理；确认每家公司保留来源与历史，飞书失败不伪装成功。先以 30–50 家由销售逐家核验的小批验证，再按真实产率和耗时扩大任务。
5. **再上线四品类真实接待。** 先审核产品、规格、供货能力及商务资料，接入真实会话和人工接管状态。在另行确认触达范围后启用发信；多邮箱投递运营形成实际工作量时比较 Instantly，团队收件箱协作形成瓶颈时比较 Chatwoot。API 有预算不替代业务授权与资料准备。

近期采购建议是继续使用公司承担的海关和模型 API，充分利用已有外贸通及邮箱，并给必要的托管兜底留预算。新增 Clay、通用 CRM 或整套 AI SDR 应以可证明的人工节省或新增能力为触发条件。项目先交付稳定可交接企业，再扩展自动接待与规模触达。
