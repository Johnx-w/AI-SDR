# 获客后自动首发：测试用例与验收

依据：负责人已确认的业务规则及 ADR-0023。以下预期先于新增测试确定，不能根据当前代码输出改写为通过。

## 测试边界

自动化验证从获客保存结果到邮件提交：使用真实获客任务、定时计划、触达队列及邮箱模块，模拟外部客户存储、模型和 SMTP。测试数据、数据库、邮箱配置独立，凭证为假值；不读取运行环境的 `.env` 或真实邮箱配置。

真实验收单独使用现有公司邮箱内部测试功能，三个自有邮箱各一封。它验证实际传输、身份、签名和收件，不冒充真实客户，也不将内部测试记为客户首发。

## 固定用例

| 编号 | 输入与操作                                                                           | 预期结果                                                                                          |
| ---- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| A01  | 自动首发关闭，保存一个资料完整的新客户                                               | SMTP 提交 0 次；不能因客户已入库自行开通首发                                                      |
| A02  | 库中已有 H，本轮新增 A、更新未联系的 B；另有只发现但未保存的 C                       | 只发送 A、B，各 1 封；本轮仍运行时即可发送，H、C 为 0                                             |
| A03  | 保存返回客户编号，但读回不存在或域名不一致                                           | 不进入首发；SMTP 提交 0 次，不记已联系                                                            |
| A04  | 本轮有一个正常客户及一个缺邮箱客户，随后补齐后者                                     | 正常客户先发 1 封；缺项有明确原因，补齐后再发 1 封；不重复前者                                    |
| A05  | 邮件生成期间、发送前读取期间暂停                                                     | 暂停后提交 0 次；异步任务回写不能撤销暂停                                                         |
| A06  | 邮箱连接准备尚未完成，分别暂停单次首发、暂停计划、关闭首发开关、关闭计划             | 四种情况均提交 0 次；不得标成已发送或结果未知；可恢复的控制恢复后才继续，关闭计划不可恢复         |
| A07  | SMTP 已收到第一封但尚未返回结果，此时关闭计划，另有第二封待发                        | 第一封保留 SMTP 实际结果；第二封提交 0 次，不能把第一封伪装成撤回                                 |
| A08  | 同一邮箱每日额度 2、间隔 30 秒，两个获客任务合计三个不同客户                         | t=0 发 1 封；t=29 仍 1 封；t=30 共 2 封；当日不发第 3 封；北京时间次日的常规待处理复查后发第 3 封 |
| A09  | 两个获客任务发现同一企业；另一个档案编号、联系人仍指向同一企业域名；完成后重启再发现 | 该企业累计只提交 1 次，不因任务、记录编号、联系人或重启重复首发                                   |
| A10  | SMTP 明确拒收；或提交后断线、结果未知；随后再次调度并重启                            | 明确拒收不是已发送；未知不是已送达，未知不自动重试，不通过另一邮箱补发                            |
| A11  | 搜索卷帘但客户实际经营透气窗；下一轮新增已审核产品和对应可用邮箱                     | 根据经营证据匹配，不受搜索产品限制；下一轮使用新增资源；已准备邮件不因新增资源换邮箱、产品        |
| A12  | 待发期间客户变为已回复或勿联系、产品撤回审核、邮箱身份或产品授权变更                 | 旧邮件提交 0 次，列出原因；恢复时使用最新条件重新检查                                             |
| A13  | 模型失败、无事实依据、正文伪造供货承诺或改变收发身份                                 | 不生成可发送邮件；不能绕过固定收发地址和事实校验                                                  |
| A14  | 重复创建请求、重复控制请求；从沟通中心尝试单独启动获客托管触达                       | 不重复首发；不能绕过获客开关和客户范围                                                            |

判定依据包括 SMTP 实际提交次数、收件地址、发件地址及 envelope、邮件内容、对外可查的发送状态和缺项原因。不能只检查“函数返回成功”或单一状态。

## 真实邮箱验收

自动化通过后，按以下固定环路最多发送 3 封，无抄送、密送或附件（签名内嵌 Logo 除外）：

1. `SL01@honeybadgerblinds.com` → `sl01@shuangshengshutter.com`
2. `sl01@shuangshengshutter.com` → `SL01@shutterblindssolutions.com`
3. `SL01@shutterblindssolutions.com` → `SL01@honeybadgerblinds.com`

使用现有内部测试固定正文、唯一测试标记及各账号当前签名；不生成真实营销内容。实际提交前展示收发名单和内容；复用同一个幂等编号，未知结果不重发。

验收分别记录：SMTP 是否接受、收件箱是否实际出现同一 Message-ID、收发身份和签名是否正确、每个收件箱是否只出现一封。SMTP 接受不等于送达。内部测试不覆盖外部收件服务商的垃圾邮件判定，也不验证开发信转化率。
