# 客户筛选与飞书字段

2026-10-22 更新。T2“客户名称”已改为“公司名称”，名称、别名及海关主体边界见[公司名称核验](company-name-verification.md)。当前自动评分与简化字段见[实施说明](automatic-assessment.md)，后文原迁移操作记录保留历史口径。

## 任务设置

真实任务表单位于 `/automation`，名称为“获客任务”。侧边栏顺序为获客任务、自动获客、客户库。

- 获客渠道显示“网页搜索”，实际使用现有 Tavily Search / Extract；删除未接入的 Google 网页搜索选项。
- 市场保留美国、澳大利亚、加拿大、英国、欧洲（不含英国）。欧洲在后台展开为明确国家，企业实际国家仍依据官网证据。
- 客户类型为单选：工厂、工程承包商、批发商、服务商、经销商、零售商、其他行业；默认不限。
- 客户画像可选品牌与渠道经营、工程项目配套、安装与维保服务、生产加工配套；默认不限。
- 客户类型与画像进入规则生成的初始搜索词、后台补找计划及企业研究目标。明确不匹配或无法核实指定类型/画像的客户不计入新增目标。搜索词保留手动编辑，已移除 AI 搜索词生成步骤。
- 产品分为室外成品、室内成品、室外半成品、室内半成品。两组成品支持组内全选，半成品分别覆盖相应配件零件。

## 全局入库准入

准入在产品事实和原文引证校验之后、飞书新增或更新之前执行，不受任务选择的客户类型、画像或 B/C 客群覆盖。

- 自有工厂按具体产品及供货方向研究，不再因生产目标同类成品全局淘汰；材料/配件与成品机会分别保留依据。
- 本地供应安装商和零售商可以作为企业买方，按产品及供货角色评价；不因经营地区小或生产方式未知直接淘汰。
- 产品按本次目标品类匹配，室内外与成品、配件分开；“属于窗饰行业”不再等于符合目标产品。企业明确公开的采购需求也可证明目标品类相关，例如自产成品但明确采购目标配件；无公开采购证据时不推测配件需求。
- 淘汰个人消费者与个人装修求购账号。C 端表示企业面向个人消费者经营，可以通过；个人账号经营真实企业也按经营主体判断，不能仅因账号形态淘汰。

`entity_type`、`production_model`、`operating_model` 和 `manufactured_products` 都依据本次已抓取页面的完整连续原文与来源 URL，存入本地操作研究日志，不增加飞书内部控制字段。主体未能核实时返回 `insufficient_evidence`；生产方式/范围不足保留未知，不当作主体不合格。具体产品/角色不足时不发布A/B，见评分规则。历史客户不在此次规则变更中删除。

退役市场从前端选项、分组搜索计划和 API 校验移除。恢复旧任务和直接调用 native 也重新校验市场；待核对的旧写入先核对，再阻止该市场的新采集。

当前生产链路是 native；兼容 n8n 工作流生成脚本同步共享准入代码和 Schema，本次未发布线上 n8n 工作流。

## 飞书字段

| 字段         | 类型     | 写入规则                                                                                                                             |
| ------------ | -------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 客户类型     | 文本     | 按官网证据识别主要经营角色；未知留空                                                                                                 |
| 广告代码     | 文本     | 从官网 HTML 追踪配置识别 Google Ads、Meta Pixel、Microsoft UET、LinkedIn Insight、TikTok Pixel、Google Tag Manager 的 ID，附来源 URL |
| 需求产品     | 文本     | 企业自身明确表达的采购、求购、寻找供应商等需求，附逐字原文及来源；没有证据时留空                                                     |
| 客户行业画像 | 文本     | 依据官网原文概括实际行业、经营方式及服务对象，附原文和来源                                                                           |
| 用户评级     | 既有单选 | 原客户等级改名，保留人工存量；每轮官网自动评分更新当前评级，并追加T12历史                                                            |

安装追踪代码并不表示企业正在投放广告。销售产品、面向访客的询价表单和任务产品条件均不能作为采购需求。

客户库详情及 CSV 导出包含三个新增字段。没有检出结果时不清空已有信息。

## 现有数据与流程整理

迁移前备份字段定义及 19 条记录的客户类型。将制造商归为工厂、安装商归为服务商；历史合并分类“经销商 / 批发商”保存到客户行业画像，主要角色留待核实。待核实类型留空。记录 ID、客户数量、客户等级保持原样。

主流程从 39 个节点减至 38 个，移除每次仅处理一家企业时的写入循环，写入结果直接进入汇总。保留搜索、正文检查、HTML 证据、失败页补抓、研究、两次去重及结果核对，这些步骤承担不同职责。各 Code 节点仅保留实际使用的辅助函数，研究正文按 URL 合并，减少重复输入。既有批量任务的结果查询和去重写入分支继续使用。

生成部署参数：`node scripts/build-customer-fields-workflow.mjs <最新工作流快照.json>`。脚本只生成本地操作文件，不调用搜索或写入飞书。应用前应重新读取线上草稿并核对版本。

本次核验包含本地测试、前端构建、表单联动、飞书字段读回及 n8n 模拟整链路。整链路中的搜索、AI 和客户写入使用固定响应，没有新增测试客户。历史客户的新增业务字段未批量重新采集。

字段类型及配置参考[飞书字段编辑指南](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-field/guide)。

## 2026-10-21 前 10 条真实验收

通过生产工作流按原官网链接重新研究前 10 条，并按飞书记录 ID 定向更新。每条 n8n 执行均成功，写入结果为 `updated`；写入后按 ID 读回一致，客户总数保持 19，没有新增、失败或重复记录。线上工作流增加了存量复核保护：请求须同时匹配官网域名和目标记录 ID；记录不匹配或不存在时停止，禁止新增。

新增字段结果：客户行业画像 10/10 写入；广告代码 5/10 检出并写入，其余未检出时保留空值；需求产品 0/10 有可验证的采购需求，因此保持为空。三列均通过工作流文本字段类型检查；这轮真实数据证明了客户行业画像及广告代码的非空写入。没有临时写入虚构需求来测试需求产品列。

信息复核注意项：第 9 条 SunPro 当前来源链接是 Eventbrite 企业主页，不是企业官网。已找到官方站 `https://sunproproducts.com/about/`，其说明公司在佛罗里达组装电动卷帘屏与遮阳篷并通过经销商服务全国；本次写回仍基于 Eventbrite，后续应改用官方来源重新研究该记录。详情及执行记录见本地验收产物 `artifacts/first10-refresh-verification.json`。

## 电话抓取与统一格式

第 6 条 Universal Screens 的首页、联系页已抓到 `Phone: (972) 696-0181`，但旧提取器在企业国家未确认时跳过了本地格式，导致电话列空白。现先保存明确 Phone / Tel / Call 标签、联系链接和结构化数据中的号码证据，再按研究确认的企业实际国家补采和格式化，不使用搜索目标国家推定区号。

电话写入统一为 `+国家代码 本地号码`，例如 `+1 9726960181`、`+86 13800138000`、`+61 298342920`。同一号码按规范值去重；分机保留；传真、脚本数字和日期不作为联系电话。原始号码及来源仍保存在提取证据中。共享实现位于 `server/phone-format.mjs` 和 `server/contact-extractor.mjs`，可直接沿用到 Node.js 后端。

2026-10-21 本地相关回归 34 项通过。生产执行 #233 仅更新第 6 条的电话字段，写入并读回 `+1 9726960181` 与 `+1 8885833361`，其余字段一致，客户数量仍为 19。上一轮的记录更新成功不能视为所有公开联系方式均已完整采集。
