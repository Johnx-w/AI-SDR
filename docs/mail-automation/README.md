## 设计依据

真实资料验收可运行 `node scripts/verify-mail-knowledge.mjs`。脚本递归读取指定的三份 XLSX，在内存中审核，用途、材质、定金比例和含适用条件的参考价均逐项核对原单元格。数值按 Excel 的 15 位有效数字读取，文本型型号保留前导零。

沟通中心的「邮箱管理」可为每个账号设置官网、负责人、签名、发送间隔及接待方式。业务备注可填写、改写或留空，只在团队页面显示。新增邮箱按官网匹配已审核的销售产品，保留既有邮箱已确定的产品范围。选择「回复可用资料」时会按该官网与产品适用品牌筛选已审核记录。「按此邮箱资料试问」使用实际回复检索路径并展示文件、版本、工作表、单元格及取值。报价和待核对的条目交业务员审核。

在素材库直接上传原件，打开「原件与校对」核实工作表单元格、文件位置或视频时间点，再审核资料。资料可上传新版本、恢复历史版本或撤回。已选中的旧版发生变化时，自动答复按当前有效版本重新检查。独立上传的素材仅供回复选用。

- 使用同一发件箱，在原线程按计划跟进，客户回复后结束未回复序列。[HubSpot 序列编辑器](https://knowledge.hubspot.com/sequences/create-and-edit-sequences)
- 自动应答和真人回复分开处理，在同一工作区展示需要处理的邮件和暂停状态。[Apollo 序列](https://knowledge.apollo.io/hc/en-us/articles/4409237165837-Sequences-Overview)

本次开发复用产品、邮箱、会话、草稿和发送台账。在现有产品资料中审核工作簿，对外回信只读取邮箱已选的有效资料。来信处理记录其原消息、分类、所用资料版本和回复结果。验收使用独立的本地存储、模拟时钟和三个公司内部地址。

## 素材库与业务员操作

1. 在「素材库」选择文件上传。打开资料，填写所属官网、品类及关键词，在「原件与校对」核对原文，填写审核人并审核通过。需要换版时选择「上传新版本」，资料不再适用时选择「撤回资料」。
2. 到「沟通中心 → 邮箱管理」点「连接邮箱」。核对官网、回复可用资料、负责人、签名、日额度及发送间隔。业务备注可记录交接信息。填写客户端授权码并保存。「验证连接」核实 SMTP 登录，并用 IMAP 只读打开收件箱和已发送文件夹。「按此邮箱资料试问」可在发送前查看答复和依据。
3. 选择「生成草稿，逐封审核」或「有明确依据时自动回复」。系统只自动回答能从本站所选有效资料中定位、匹配条件明确的技术问题。报价、付款条件、无法定位型号、附件或收件人复杂的来信交业务员核对。纯手动邮箱在收件箱的原线程处理。
4. 在获客任务启用自动首信，或在「触达计划」预览和启动。三个正式站点的产品需要本站来源或适用品牌依据。程序按客户官网的产品机会和供货证据选一个可用邮箱，核对客户固定邮箱、企业、域名和收件地址占用。启用未回复跟进时，首封提交采用当时的工作区序列，SMTP 接受后再按实际发送时间排期。默认第 3、7 天各跟进一次。已准备首信更换官网会撤回旧正文。
5. 在正常业务服务打开收件箱顶部的「待审草稿」，查看原信、草稿、资料版本和单元格，核对后批准发送。需要改用新版本时选「按当前资料重新生成」。人工接管会终止本轮追信并保留人工编辑的草稿，恢复邮箱接待仅适用于后续新来信。退订或停止联系继续生效。

### 在收件箱使用 AI起草

打开客户来信，在「回复客户」一行点「AI起草」。这一步会把当前来信、有限的同线程上下文和当前邮箱可用的相关资料片段发送给服务端配置的模型。本机当前使用 `deepseek-flash`。业务员可编辑生成的草稿并展开资料来源。没有匹配资料时，可以写致谢或澄清问题，产品细节留待人工核实。已有手写正文或附件时先处理当前草稿。审批发送是之后的独立操作。

本机 14324 将结果保存到本地快照。Windows 使用下方 PowerShell 入口启动时，从快照目录的 `deepseek.dpapi` 读取以当前 Windows 用户加密保存的密钥，也支持进程环境变量 `DEEPSEEK_API_KEY`。正式服务读取项目的模型连接配置。打开邮件、搜索或刷新均不会触发起草。

## 正常业务服务中的发送与恢复

在「跟进序列 → 编辑序列」中修改名称、增删跟进步骤，分别设置相对于首封的天数与 AI 写作要求。可设 0 至 12 步，每步为第 1 至 365 天，同一天只能安排一步。保留零步时仅发首封。新规则用于之后提交的首封。计划详情按实际跟进日显示，展开客户的「写作要求」可查看当时采用的版本内容。

收件箱列表直接提供「全部」「未读」「有回复」。「有回复」按会话汇总有回复头的真实外部客户来信，和跟进任务共用判定。普通询盘、自动通知、退信、内部往来、退订和投诉各有自己的来信类型。可继续选择邮箱或输入关键词缩小范围。页面顶部「刷新」重新读取本地记录，列表底部「同步」从所选邮箱获取新邮件。选择「全部会话」时同步全部邮箱。

「稍后」用于暂缓处理，到时回到进行中。「已完成」用于收起处理完的会话，有新客户来信会重新打开。两者都可以在搜索框旁的「其他状态」里查看。「全部」涵盖所有状态。桌面默认并排显示会话列表与对话，选中邮件即可阅读、回复或写内部备注。点对话右上角「联系人」可查看客户及接待设置，工作区足够宽时资料与邮件并排显示。手机选中邮件后进入整页对话，点左上角返回箭头回到原列表、筛选和沟通中心栏目。[Front 会话状态](https://help.front.com/en/articles/2134) · [Fluent 2 字号](https://fluent2.microsoft.design/typography/) · [Fluent 2 间距](https://fluent2.microsoft.design/layout/)

- 新消息和 IMAP 游标在同一 SQLite 事务入库。按原消息登记接待任务，以 IMAP 到达时间筛除启用前的历史来信。休假或收件通知归为系统消息，已排任务按首封采用的序列执行。已关联的退信停止相应追信，真实客户回复立即结束余下追信。历史任务中的人工暂停仍保留。
- 发送有据可查的自动回信或批准系统草稿前，先同步收件及已发送文件夹，再检查发送账号、固定归属、最新来信、人工接管、资料版本和草稿修订。回信写入 `In-Reply-To` 和 `References`，自动回信标记 `Auto-Submitted`。
- 发信前先登记提交。重启、重复点击、重复 IMAP 消息及多个执行者复用这次提交。若 SMTP 已经接手而应答中断，显示「结果待核实」，请核对原邮箱和服务商记录。首封可用原邮箱已发送的 Message-ID、收发地址和发送时间核实后安排追信。
- 外部邮箱和本机数据库之间存在投递延迟。已同步到本机的客户来信或员工回信可以拦截尚未提交的追信；服务商已经接受的邮件无法撤回。

使用 `node scripts/verify-communication-tabs.mjs` 对照短摘要和长摘要，检查换行、内容顺序和记录的实际高度。在 1600、1397、541 px 三种视窗宽度下，脚本打开同一封长邮件，核对 HTML 默认字体和发件人指定的表格字体、实际可见的 HTML 与纯文本正文、联系人开关，以及窄屏返回列表后的邮箱与回信筛选。

回复栏的「展开」可用于编写长信，选择「收起」或按 Esc 返回原会话。浏览器用长草稿验证从末尾回到开头修改，收起后刷新仍可读回。草稿、团队备注和处理状态的写入与发送隔离由 `tests/mail-thread-workflow.test.mjs` 验证。
