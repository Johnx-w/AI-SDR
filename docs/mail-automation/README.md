## 设计依据

真实资料验收可运行 `node scripts/verify-mail-knowledge.mjs`。脚本递归读取指定的三份 XLSX，在内存中审核，用途、材质、定金比例和含适用条件的参考价均逐项核对原单元格。数值按 Excel 的 15 位有效数字读取，文本型型号保留前导零。

沟通中心的「邮箱管理」可为每个账号设置官网、负责人、签名、可推产品、发送间隔及接待方式。选择「回复可用资料」时会按该官网与产品适用品牌筛选已审核记录。「按此邮箱资料试问」使用实际回复检索路径并展示文件、版本、工作表、单元格及取值。报价和待核对的条目交业务员审核。

工作簿在「产品资料」的产品编辑器上传，选择解析、关联并展开行号即可校对单元格。原件和 SHA-256 保存在产品数据库，校对值随产品版本保存。撤回用归档，换版可移除旧文件关联并关联新文件，再审核产品。独立的邮箱资料选择决定回复时的可用范围。

- 使用同一发件箱，在原线程按计划跟进，客户回复后结束未回复序列。[HubSpot 序列编辑器](https://knowledge.hubspot.com/sequences/create-and-edit-sequences)
- 自动应答和真人回复分开处理，在同一工作区展示需要处理的邮件和暂停状态。[Apollo 序列](https://knowledge.apollo.io/hc/en-us/articles/4409237165837-Sequences-Overview)
- 阿里邮箱使用第三方客户端密码，SMTP 走 TLS 465，IMAP 走 TLS 993；连接测试与实际到件分别取证。[阿里邮箱客户端设置](https://help.aliyun.com/zh/document_detail/36576.html)
- 工作簿解析采用 MIT 许可的 read-excel-file，锁定 9.3.20（2026-11-19 更新）。[组件文档与许可证](https://gitlab.com/catamphetamine/read-excel-file)

本次开发复用产品、邮箱、会话、草稿和发送台账。在现有产品资料中审核工作簿，对外回信只读取邮箱已选的有效资料。来信处理记录其原消息、分类、所用资料版本和回复结果。验收使用独立的本地存储、模拟时钟和三个公司内部地址。

## 业务员操作

1. 在「产品资料」打开本站产品，上传并解析资料，关联工作簿，按工作表和型号校对。填写审核人、生效日期并审核。撤回时归档产品，换版时移除旧关联并审核新版本。
2. 到「沟通中心 → 邮箱管理」点「连接邮箱」。核对官网、可推产品、回复可用资料、负责人、签名、日额度及发送间隔。填写客户端授权码并保存。「验证连接」核实 SMTP 登录，并用 IMAP 只读打开收件箱和已发送文件夹。「按此邮箱资料试问」可在发送前查看答复和依据。
3. 选择「生成草稿，逐封审核」或「有明确依据时自动回复」。系统只自动回答能从本站所选有效资料中定位、匹配条件明确的技术问题。报价、付款条件、无法定位型号、附件或收件人复杂的来信交业务员核对。纯手动邮箱继续从邮件会话处理。
4. 在获客任务启用自动首信，或在「触达计划」预览和启动。三个正式站点的产品需要本站来源或适用品牌依据。程序按客户官网的产品机会和供货证据选一个可用邮箱，核对客户固定邮箱、企业、域名和收件地址占用。首封被接受后，相对该时间加 72 和 168 小时，各安排一次原线程追信；启用时可取消勾选。已准备首信更换官网会撤回旧正文。
5. 打开「待审回信 → 查看并审核」，查看原信、已选资料版本和单元格，编辑或批准发送。资料变化时按当前资料重新生成。接管会终止这一轮追信并保留业务员已经编辑的草稿。恢复仅对后续新来信生效。客户退订或标为停止联系后，恢复按钮不能解除抑制。

## 发送与恢复

- 新消息和 IMAP 游标在同一 SQLite 事务入库。按原消息登记接待任务，以 IMAP 到达时间筛除启用前的历史来信。休假或收件通知归为系统消息，新任务仍按第 3、7 天跟进。已关联的退信停止相应追信，真实客户回复立即结束余下追信。历史任务中的人工暂停仍保留。
- 发送有据可查的自动回信或批准系统草稿前，先同步收件及已发送文件夹，再检查发送账号、固定归属、最新来信、人工接管、资料版本和草稿修订。回信写入 `In-Reply-To` 和 `References`，自动回信标记 `Auto-Submitted`。
- 发信前先登记提交。重启、重复点击、重复 IMAP 消息及多个执行者复用这次提交。若 SMTP 已经接手而应答中断，显示「结果待核实」，请核对原邮箱和服务商记录。首封可用原邮箱已发送的 Message-ID、收发地址和发送时间核实后安排追信。
- 外部邮箱和本机数据库之间存在投递延迟。已同步到本机的客户来信或员工回信可以拦截尚未提交的追信；服务商已经接受的邮件无法撤回。

## 部署与回退

本机运行 `npm ci`、`npm run build`，再运行 `npm start`。服务监听回环地址，默认端口 4311，可以用 `PORT` 覆盖。公网沿用正式 Nginx 认证。提交到本地分支不会启动云端发布。

本机重启后，在 PowerShell 中用交付端口打开同一份工作区。

```powershell
Set-Location -LiteralPath 'D:\CodeX\AI-SDR-mail'
$env:PORT = '14321'
npm start
```

正式发布由 main 的自动 CD 执行。发布时按现有标准流程等待同一提交的 CI、获取维护窗口，核对空闲状态和备份，再切换代码。备份涵盖 `.data`、邮箱加密密钥、环境和服务配置。首次启用时逐邮箱核对策略和资料。旧账号读取为手动接待，已有发送授权和历史邮件均按原记录处理。[标准发布与恢复流程](../architecture.md#标准交付流程codex执行入口)

回退时先暂停相关邮箱、获客首信和追信，等待正在提交的操作结束。保留当前数据库、已发件台账、IMAP 游标、退订记录和最新资料。通过标准 `npm run release:rollback` 切换上一代码版本，核对队列及待核实邮件后再恢复既有业务。本地可用 `git show mail-automation-production-baseline-20261122` 查看正式起点。邮箱配置的 `mailboxes` 仍采用正式 v1 格式，新字段在同一文件的 `receptionSettings` 中原子保存。旧版本能读取邮箱；旧版本再次保存邮箱会清除扩展策略，重新升级后须审核授权。回退期间保留完整配置备份，并将新增的产品资料保留到升级后再编辑。
