# 获客

新增客户写入前，已通过产品初筛的候选还要由当前配置的研究模型独立复核官网经营用途。复核按任务的产品范围读取同域产品引文及上下文，区分经营者、第三方和兼营产品，只采纳通过复核的产品证据。证据不足、模型不可用或返回无效引文编号的候选进入待核实。相同模型、目标与证据可复用此前的有效响应；用量统计包含独立复核调用。

当前代码核对：2026-11-27。用于发现潜在企业、核实经营主体与产品关联，并将去重后的实际新增收录写入客户库。评级、资料齐备、真实采购需求和开发进度分别记录。

## 使用流程

全部 25 个支持国家的立即任务和定时计划共用[获客地区目录](acquisition-regions.md)。自动生成的全国查询若遇到重复官网，且研究完本次候选后仍无新增，系统用同一搜索词加一个本国地区补搜一次，再继续下一条全国查询。追加地区后的查询超过 128 字符时跳过这次补搜。地区随全国查询位置轮换，补搜占用当前批次的搜索次数，实际搜索词可在执行记录中查看。

自动搜索优先轮换带经营角色的查询，仍覆盖各市场及窗饰成品、半成品和零件。明确的监管/统计资料、媒体、平台和目录在研究前过滤；企业自己的新闻产品页与政府采购机构继续作为候选。当前实现将已知第三方平台（包括 `mydeal.com.au`）在官网网页采集和模型研究前过滤；执行详情显示“第三方平台已过滤 N 条”，可展开查看域名、搜索词和过滤原因。过滤项不计研究失败或产品不匹配，云端上线状态以同一提交的发布验收为准。

在「获客任务」选择产品、获客范围和新增目标，可立即运行或保存定时计划。可选多个搜索角色以调整搜索词。企业的实际经营角色、产品和准入从官网取证，搜索角色不设入库门槛。搜索预览使用本轮可派发的计划查询。

获客范围默认「所有国家」，也可从 25 项业务国家目录中选择一个国家全境。全球任务交替派发无地区限制的查询及地区定向查询，初始地区包含 25 项业务国家以及法国和西班牙。已有英语搜索词，部分地区补充当地语言的产品及经营用语。指定产品保留原有产品名和已有别名。全球范围可收录目录外企业，地区检索词不用于判定企业属地。企业实际属地按官网原文核实，未知时留空。旧的空范围、洲、城市或州范围及冲突的地区字段需要在计划中重新选择后才能继续执行。客户库按客户资料归属国家和州／地区筛选。B/C 表示企业服务的客群，只作为有原文依据的企业事实保留。个人消费者另行判断。

获客只使用官网发现。指定产品只查对应产品及别名，不静默扩展到全部行业。

## 执行引擎与连接

使用 Node.js 直连：网页检索／提取 → 官网采集 → 模型结构化研究 → 原文与身份核验 → 准入及程序评分 → SQLite 保存并读回客户档案与最新评估 → 后台同步飞书。去重及新增核验使用本地主档案；本地保存成功即可收录，飞书仅作为领导查阅的报表，其连接独立于获客所需的搜索和研究凭证。飞书同步状态单独显示，失败后核对重试。唯一获客入口为 `/api/v1/acquisition`，不再支持外部工作流执行引擎。

「API 连接」保存值优先于进程环境和 `.env`；默认文件 `.data/api-connections.json`，保存后重建适配器与令牌缓存，后续任务立即生效。只回显密钥脱敏摘要；留空保留原值，明确选择清除才删除。存在运行中、执行结果待确认或后台正在核对的操作时拒绝更换连接。

| 能力           | 现有实现与替换方式                                                    |
| -------------- | --------------------------------------------------------------------- |
| 网页检索／提取 | Tavily 或 DeepSeek Search／Fetch；HTTP 桥接提供 `/search`、`/extract` |
| 企业研究       | DeepSeek；可用支持项目结构化输出约束的兼容模型服务                    |
| 客户存储       | SQLite 客户主档案，飞书后台协作镜像；业务状态另按主题管理             |

选择 DeepSeek 网页检索时，继续使用「网页检索 API 基础地址」和「网页检索 API Key」字段，地址默认 `https://api.deepseek.com`，Key 需填写。网页检索与研究模型分别配置。兼容 HTTP 搜索服务仍需实现 `/search`、`/extract` 的现有请求与结果格式；仅更换地址和 Key 不会自动兼容另一家服务的原生接口。

研究模型使用「API 连接」中保存的模型 ID；日常运行沿用该值，更换服务或模型时填写服务商提供的 ID 并保存。模型目录查询与选择功能已移除，配置和保存无需访问模型服务。推理强度不在日常设置页展示，后端沿用已有配置，未配置时默认 `none`。

具体配置名以 [环境示例](../.env.example) 和「API 连接」实际字段为准。`npm run preflight:native` 核对配置、飞书可读性与模型，不执行搜索或写入；`npm run verify:native:live` 使用真实搜索／模型额度，飞书写入由隔离模拟替代。“已填写”不代表业务能力已实测。

## 任务预算与恢复

执行详情提供「暂停并保留进度」「继续获客」「删除来源任务」。人工暂停保留剩余候选及当前操作编号，已经开始的企业先完成保存或核对，不启动下一家。后台中断恢复不解除人工暂停。删除来源结束后续执行，保留结果历史与企业去重依据；关联定时来源同时删除定时安排。

本地来源控制已支持关联触达删除时的安全暂停：来源及关联定时安排的自动首发持久化为关闭，执行详情显示原因与原触达入口。删除旧定时轮的触达时，同时暂停该来源当前轮次；已结束旧轮保持结束结果。人工直接继续仅获客，定时恢复仅执行未来时点并继承关闭值。完整触达删除入口另由触达流程集成交付；本地实现不代表云端部署。

删除后可在单次任务详情或所属定时计划重新勾选并点击“保存自动首发设置”，取得新的自动首发授权。保存不解除来源暂停；新安排使用独立编号，来源继续后才执行。重复保存不生成第二个新安排，旧删除计划不再参与同步或发送许可；同轮已跳过、明确失败、未知及已发送记录不会因新安排重新尝试。页面按来源修订保存，过期页面须刷新后重新确认，旧异步检查点不能覆盖新授权或关闭决定。已结束的单次任务可从“重新执行”入口复制当前持久化条件，自动首发关闭值随之继承；创建新任务前仍可明确调整选择。

新增目标默认 20 家，可填写超过 200 家的正整数。任务目标只计去重后写入并读回确认的新企业。既有档案更新、重复候选、未入库待核实及不确定写入不计新增。已核实主体和相关产品线的企业可保留开发机会；经营国家未知仍入库并计入实际新增，国家留空，在客户库“全部国家”筛选中的“待核实”集中查看。已证实国家与单国目标市场不符时仍排除。

执行记录中的未入库“待核实”候选可查看已保存的官网身份与产品依据，相同引文的产品依据归组显示。每家企业的业务联系表单默认折叠成一行，展开后查看不同表单编号及其来源页。同站、同插件的相同编号合并，保留不同来源页；采集支持 WPForms 和 Elementor 的编号，历史记录或其他表单缺少编号时仅按网址去重列出来源页，不推断它们属于同一个表单。

从执行详情展开待核实企业，核对或更正企业独立官网、填写操作者，点击“核实并尝试入库”。第三方平台或目录页须更换为企业官网。自动研究仍缺经营证据时，可提交人工裁定，填写同站证据页、主体和主营供货原文、产品、供货方式及理由。系统从本次官网快照逐条核对引文，保留既有冲突并沿用同一准入和主库读回规则。执行记录保存更正前后网址、操作者、时间、依据和结果。已确认的补录单列，并按实际读回时间计入新增总数，原轮次的自动新增数量保持当时结果。补录结果不明时沿用原编号核对。自动获客执行期间不受理新的补录提交。

不同范围的定时获客可并行，每个范围各自最多一轮未结束。手动获客与其他轮次互斥。每个新轮次在同一任务内跨批推进；每批最多确认 200 家、活动运行 6 小时，研究次数默认 `min(1600, max(12, 8 × 目标))`，搜索次数为 `max(20, 3 × min(目标, 200))`。达到其中一个边界时进入下一批并继承候选、查找位置及操作账。明确提交的 `research_budget` 仍是整轮上限。新任务保留大部分查询用于覆盖新地区及词组，部分流量按已确认新增、已研究、近似查询消耗和运行时长调配。搜索用尽时单独显示候选耗尽及剩余目标。

每轮保留一个待确认企业操作，读回成功后再派下一家。不同任务并行时由客户主库判断同一企业的首次确认归属。达到目标后停止派发。详情显示批次、剩余目标、平均每小时确认新增和实际检索地区及语言。已有轮次按所存规则、限额和计数继续。

本地实现按客户库、执行引擎、定时计划、业务条件及搜索词顺序保存下一条查询和剩余候选。立即任务在相同条件下独立接续。新轮先处理上轮剩余候选，再轮换下一条搜索词，走完词表后从头继续。达标、到达上限或结束任务时，SQLite 同时保存本轮结束状态与接续位置。执行中断沿用原轮次恢复。执行详情显示承接数量，承接不会增加本轮搜索次数。升级后，既有定时计划可沿用最后一轮同条件的游标；旧轮已经清空的候选无法恢复。

关闭网页后任务继续。当前统一获客轮次在暂停、停止或服务维护时让出未提交的采集工作，保留已取得的页面和在途请求记录，并等已提交的写入及核对收尾。重启及点击「继续」沿用原轮次、游标及企业操作编号。完整页面从原操作所引用的快照恢复，缺页按原预算补取。主库写入结果待确认时，先按原操作读回和归属核对，确认后再计新增。任务详情展示当前步骤、官网采集记录、请求用量、待核对的请求编号及剩余目标。

当前统一获客轮次发起付费官网搜索、外部提取或模型调用前保存原请求编号。收到结果后先保存应答，恢复时验证并接续。搜索和模型应答不明时，支持核对的供应商适配器沿用原编号查询，仍未知则暂停原步骤。外部提取应答不明且缺少证据时，该企业保留待核实，队列继续处理可读取的官网。供应商未提供相应查询时保留未知状态，历史请求缺少编号也继续待核对。应答用量仅累计供应商确认数据。

已有旧版轮次继续按原规则运行。明确在写入前中断的研究最多自动重试一次。缺失的旧操作记录记一次失败并继续队列。已退役引擎的历史任务仅供查询。发布维护期间暂停新轮次及恢复派单。

新轮次以规范官网网址去重发现，并在入库前核对经营主体。同域不同经营主体有独立法律与经营证据时各自入库；同主体换域仍归原档案，保留每次发现来源。英国登记号、澳大利亚 ABN，或能够逐字核对的法人全名与明确归属该法人的注册地址（街道、城市、邮编和国家），可支持主体关联。单有同名、域名一致但主体无法区分，或同名注册地址互相矛盾时待核实。旧轮次按保存的规则运行。定向复核仍核对指定档案与官网，保护已有的跟进资料和首次发现时间。写入应答不明时按原操作编号在本地主库读回，镜像状态另行核对。

## 连接与定时计划

定时计划和执行记录首屏只读取状态、目标和统计摘要，不传输整批企业证据与搜索明细；展开某轮任务后再读取该轮完整详情。轮询按任务更新时间刷新已展开详情，读取失败显示错误并可重试，保留上次成功读取的信息。摘要中的空明细不代表该轮没有处理企业；原始记录、核实入口和计划控制保持原有口径。

「获客任务」内统一显示新建任务、定时计划和执行记录。新建页面按目标客户、执行安排、获客后处理分组。默认所有国家、全部窗饰业务、不限搜索角色、每轮 20 家、立即获客、仅获客。定时设置区分仅执行一次（一个日期、一个时点）和重复执行（每周多选星期，最多 24 个无重复时点）。全球计划默认北京时间，单国计划也可选目标国家的首都时区。单国计划改为全球时保留已选时区，可改为北京时间。计划及其轮次分别保存范围，改动从后续轮次生效。计划卡显示范围及调度时区，执行记录显示该轮的实际范围与查询。重复计划从创建当天开始，持续到暂停或关闭；仅接受 `once`、`weekly` 和 `times` 时间列表，重复计划必须明确选择星期，选满七天即每天执行。

右侧摘要显示目标客户、每轮目标、完整一周的计划轮数及新增目标合计、实际下次执行时间和自动首发状态；数量均为目标，不保证实际收录或发送量。定时提交按钮为“创建并启用计划”，不是保存草稿。

定时计划列表分为“进行中的计划”和“已关闭计划”，复用同一计划卡片、最近轮次详情及控制接口。已关闭列表包含关闭的计划和已结束且没有进行中轮次的单次计划；已关闭计划可点击“恢复计划”，成功后回到进行中列表。此项为本地实现，云端是否上线以实际部署版本为准。存量计划也统一使用当前 `once`／`weekly` 格式，每日计划保存为每周七天，不在运行代码保留旧格式兼容分支。

调度默认每 15 秒核对到期计划。启用「到期后排队补跑」时，忙碌、停机或连接故障保留原到期时点，条件恢复后继续。同国轮次依次执行。未启用补跑时，仅在计划分钟内触发，忙碌或错过的时点跳过。单次计划错过时点后结束，次数保持为实际触发数并显示跳过原因。人为暂停或关闭后恢复同样只从未来时点继续，不自动重启旧轮次；恢复时重新校验获客条件，关闭计划恢复还受最多 100 个未结束计划的限制。已过期的单次计划不能恢复，须重新创建。关闭保留计划 ID、已触发次数和最近轮次等历史；暂停／关闭已启动轮次时，待当前企业处理后停止。每次以计划 ID 和原定时点构成持久幂等键；已创建但尚未记账的任务先恢复关联，重启不重复建任务。

回退到仅允许一个活跃任务的旧版本前，先暂停使用当地时区或排队补跑的计划，并核对最多只剩一轮未结束任务。需要核对写入的暂停任务应先完成读回，避免重复入库。

## 获客后自动首发

已确认待实施的删除联动规则见 [ADR-0026](adr/0026-pause-acquisition-when-deleting-outreach.md)。删除获客来源的触达计划后，来源任务及关联定时安排暂停，保留进度并显示原因，同时将两处“获客后自动首发”持久化为关闭、页面取消勾选。人工直接恢复仅继续获客，用户重新勾选并保存后才建立新触达安排，旧计划及邮件历史继续归入已删除记录。

自动 CD 维护使用独立门禁，保留计划状态并等在途获客到达安全边界。当前统一获客轮次回收排队或在途浏览器，将已取得页面和已返回请求保存到原轮次。服务停止同样按此边界排空。维护期间错过的时点沿用计划规则。10 分钟未能空闲则取消本次发布并解除维护，详见[自动 CD](architecture.md#自动-cd)。

开启自动首发后可选择“首封未回复自动跟进”，默认关闭。立即获客用于该轮；定时计划中的选项用于之后建立的轮次，不改写已有发送计划。各轮已建立的追信开关和暂停／恢复在沟通中心所属发送计划中管理；获客计划暂停或关闭同时阻止其追信继续。未授权自动追信的首封可进入任务页做跟进评估，T4 只记录实际排期的追信。

2026-11-05：新建立即获客或定时计划时可开启“获客后自动首发”，已有定时计划也可单独开启，默认关闭。开启后仅纳入后续轮次中实际新增或更新保存并读回确认的客户，不扫描历史客户库，也不将仅发现重复、未保存或结果待核对的企业加入发信范围。

每家客户保存成功后即可进入首封流程，不等整轮结束或飞书镜像同步。每轮开始读取最新已审核产品和可用发件邮箱，依据客户经营事实匹配，不受搜索产品限制。客户条件不足（无可用商务邮箱、已联系、身份或经营证据不足、产品匹配未通过、经营事实冲突、勿联系等）跳过本次首发，保留原因，不生成人工待办；补齐资料、修正规则、同轮更新、恢复原计划或重启都不恢复旧尝试。后续开启自动首发的获客轮次再次更新并保存客户，或新建包含该客户的手动触达计划，才重新评估。发件邮箱连接、签名、产品审核或范围配置与额度不足由计划层等待或报错，修复后重新检查仍有效的计划，不按客户跳过。每家企业仍只安排一封首信，沿用邮箱额度、发送间隔、客户实际往来与勿联系检查；明确失败与结果未知不自动重发。云端版本以发布验收为准，历史八条暂缓处理，说明见[邮件沟通](outreach-first-touch.md#历史八条首发记录的一次性整理)。

暂停或关闭定时计划会同时停止尚未提交发送的首封，恢复暂停或关闭的计划后重新核对未发客户。立即获客的执行详情可独立暂停、恢复或永久取消本轮自动首发；取消会停止未发送首封和后续追信，保留已发送记录，不能恢复。停止这轮立即获客也会暂停首发；自然完成或部分完成仍继续处理已确认的客户。执行记录中的“查看首发进度与缺项”进入沟通中心的对应记录，控制入口保留在获客任务。设计依据见 [ADR-0023](adr/0023-acquisition-scoped-automatic-first-touch.md)。

## 官网采集与证据

官网完整快照在普通任务间的复用有效期为 24 小时。后台每小时清理无保护的原文缓存，保留最近 7 天且总量最多 64 MiB。单条快照上限 12 MiB，快照所在卷剩余空间低于 512 MiB 时清理无保护缓存并延后新正文保存。在途快照和档案、复核中有实际引文的原文优先保留。已结束操作的其他快照到期或超量时清除正文，保留原编号、采集状态、内容哈希和尝试详情。SQLite 已释放页可供后续写入复用。

搜索允许使用宽泛产品词。入库、评级和首次开发按单项产品的官网引文核对窗饰用途。其他用途和用途未确认的产品可以保留在经营目录中，不能单独作为开发依据。管道八字盲板不属于窗饰。兼营企业按有独立依据的窗饰产品判断。

新建立即轮次、定时触发的新轮次和新的人工核实操作使用 `website-admission-v1`。启用前已开始的轮次按保存的旧规则继续，既有档案的专项复评沿用其入口。写入前须取得官网主体、主营、用途和供货角色的证据，并复核产品与企业的归属。专营定制零售、本地生产并供应完整窗饰、以及经营窗饰专用配件的经销商都可按证据收录。展会主办方、平台经营者、仅自产专用配件或只安装客户自备产品等按明示的经营证据排除。供应或归属缺证时保留待核实结果。[官网准入判定表](unified-acquisition/spec.md#写入前的业务判定)

每家最多读取五个计划内同域 HTTPS 页面，优先选取首页、经营产品、法律声明及联系页面。先复用 24 小时内的有效快照，再由 Node 直读。对正文空壳或主体、经营方式缺口，最多两次浏览器补抓，补抓失败且来源仍符合公网和归属规则时由外部服务补采。同一网址的直读原文和新增的渲染正文分别保留。补抓未取得新正文时保留已核实事实。所有页面均无有效正文时结束该候选的研究并记录待核实原因。切换前已创建的轮次继续使用原基础提取及高级提取回退。

浏览器补抓跨任务共用一个活动页面。最多 8 个等待请求按到达顺序派发，单次等待最多 30 秒。可用内存低于 1 GiB 时暂缓。执行详情显示当前等待原因，采集记录保留等待耗时和结束原因；队列满、等待超时或资源延后后，可按原约束进入外部提取，证据不足则待核实。官网直读仍并行完成。

官网页脚链接中的同域法律声明（如 `legal-notice`、`imprint`、`impressum`）优先于次级联系页进入取证范围。取证时解码正文中的 HTML 字符实体，按可见原文核对网站经营者身份。展会主办方进入排除判断前也须核对身份。候选参展商仍须有自己的官网证据。

识别到采购门户或目录中的供应商档案时，保留发现来源并等待核实企业独立官网。官网取证在正文压缩前核对站点经营用途。发现同域首页或补取页面提供多个商家档案的浏览服务，并有商家登记入口或候选页的档案认领、修改及评价入口时，判为第三方目录。单独出现评价或带编号的网址继续按官网取证。目录列出的独立网站可作为另一候选，按其自身证据判定。同站跳转后的最终地址同样参与校验。

执行记录显示读取方式、时间、状态、触发原因和来源。SQLite 快照保留请求及最终 URL、原始与渲染内容、研究正文内容哈希和采集状态。可核验引文附快照编号及清理后原文的字符位置。页面仅呈现引文与采集摘要，后台保留原文快照供开发复核。

研究输入最多五个有效 URL，每页 16,000 字符、合计 80,000 字符；这是正文预算，不是总 token 预算。引文必须存在于实际提交的正文，不用模型常识补事实。原始 HTML 上限 4 MiB。官网读取支持 `WEBSITE_HTTPS_PROXY`，Windows 未显式指定时读取已启用系统代理，缓存 30 秒；公网地址、同域跳转、TLS 与私网拒绝校验继续生效。

原生引擎在预算截断前折叠同页精确重复块、重复短菜单并清理明确的 Cookie 控件；法律及隐私页只压缩可识别的模板段落，保留公司、法人、商号、邮政地址、产品用途、否定说明及第三方归属。无法可靠分类的正文保留；已识别的平台来源保留原文供来源预筛。删除位置及预算截断使用独占一行的 `[...]` 标记，引文不能包含或跨越该边界，模型与证据核验使用同一份正文。完整 HTML 联系证据不受精简影响；操作用量保存 `original_chars`（精简前）、`compacted_chars`（精简节省）及 `input_chars`（预算后实际正文），字符减少不直接视为 token 或耗时同比减少。

电话区号依据实际企业国家或原国际区号；规范值去重，保留分机，最多三个主要号码，不将分支网点全部混入。实际地址、服务范围和搜索目标分开，社媒保留来源。获客不抓取广告追踪代码。新轮次核实企业自身当前明确表达的窗饰采购。档案采购字段、评级依据和首发选材共用该引文。历史、否定或其他用途的采购摘录不会进入当前需求。按经营事实判断准入与评级。企业名称与联系人边界见 [客户数据](customer-data.md#企业身份与联系方式)。

模型响应按主体和范围、正文内容哈希、准入和证据提取版本、提示词、Schema、模型及请求参数精确匹配。经营复核复用与其实际输入一致的证据，原文以快照编号和位置关联。跨域页面正文相同、原登记引文仍能定位，且规则和目标一致时，可在发起模型请求前确认已知主体。普通缓存保存 7 天，每表作用域最多 200 项。更正官网后重新读页；页面或规则变化后重判。执行详情显示模型用量及复用次数，档案接口保留各次发现的有效机会及来源。

## 地图发现对照

正常获客轮次只执行官网搜索。地图发现限隔离测试中显式注入的供应商替身。地图对照候选复用官网取证及主库读回流程。地点、名称、搜索词和候选 URL 属于发现线索。依据独立官网原文核对经营者或已证实的商号后才能归档地点来源。有独立官网的同一主体即使有多个门店也只计一家。找不到独立官网的地点进入待核实，可在隔离任务执行详情补填官网。

隔离对照的执行详情记录地点来源编号、查询状态、发现量、调用和替身返回的额度。官网独有、地图独有和共同发现按本轮实际确认新增的主体计数。引用了成功 Scrapling 快照的入库证据可与地图独有取交集，采集带来的净增量仍须用相同网站的配对运行核对。已保存的对照详情可继续读回。

对照骨架每轮最多三次查询，每次最多 20 个地点。地图调用总时限为 2.5 秒，明确限流时只在短等待条件内重试一次。较长等待、忙碌、权限不足和结果待核对在执行明细显示，官网路径继续。确认地点与独立官网不符时暂停本轮地图路径，保留待核实原因，独立官网搜索的候选仍按相同准入继续。服务重启遇到已发起且结果未保存的地图请求时，本轮不重复扣用量。

正常应用入口忽略 `GOOGLE_PLACES_API_KEY` 和 `GOOGLE_PLACES_IDS_ONLY`，两者同时存在也不会触发 Places 请求。编号诊断通过隔离测试显式构造，请求字段为 `places.id`，只记录数量和状态。本轮无真实地图凭据、请求和成本数据。未来开放地图需先确认实际账号权限、字段留存及独立官网关联。见[地图对照验收](unified-acquisition/acceptance.md#地图对照)。
