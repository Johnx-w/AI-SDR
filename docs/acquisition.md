# 获客

当前代码核对：2026-11-10。用于发现潜在企业、核实经营主体与产品关联，并将去重后的实际新增收录写入客户库。评级、资料齐备、真实采购需求和开发进度分别记录。本文说明当前实现，不要求重做历史迁移。

## 使用流程

自动搜索优先轮换带经营角色的查询，仍覆盖各市场及窗饰成品、半成品和零件。明确的监管/统计资料、媒体、平台和目录在研究前过滤；企业自己的新闻产品页与政府采购机构继续作为候选。每条搜索词记录来源过滤数量和原因，过滤项不计研究失败或产品不匹配。

在「获客任务」选择产品、客户类型、市场、地区和新增目标；可立即运行或保存定时计划。支持多产品、多客户类型，不设置服务客群筛选、补充要求或必需条件。搜索词采用共享确定规则生成并提供预览，企业研究继续使用模型。

当前市场包括美国、澳大利亚、加拿大、英国、欧洲（不含英国）。市场与地区是搜索条件，不能当作企业实际国家或地址。B/C 表示企业服务的客群，只作为有原文依据的企业事实保留，不参与获客筛选；个人消费者另行判断。服务 C 端的真实企业、本地安装供货商、零售商和自有工厂不因角色本身被全局排除。

获客只使用官网发现。指定产品只查对应产品及别名，不静默扩展到全部行业。

## 执行引擎与连接

使用 Node.js 直连：网页检索／提取 → 官网采集 → 模型结构化研究 → 原文与身份核验 → 准入及程序评分 → SQLite 保存并读回客户档案与最新评估 → 后台同步飞书。去重及新增核验使用本地主档案；本地保存成功即可收录，飞书同步状态单独显示，失败后核对重试。唯一获客入口为 `/api/v1/acquisition`，不再支持外部工作流执行引擎。

「API 连接」保存值优先于进程环境和 `.env`；默认文件 `.data/api-connections.json`，保存后重建适配器与令牌缓存，后续任务立即生效。只回显密钥脱敏摘要；留空保留原值，明确选择清除才删除。存在运行中、暂停待核对或结果不明操作时拒绝更换连接。

| 能力           | 现有实现与替换方式                                                    |
| -------------- | --------------------------------------------------------------------- |
| 网页检索／提取 | Tavily 或 DeepSeek Search／Fetch；HTTP 桥接提供 `/search`、`/extract` |
| 企业研究       | DeepSeek；可用支持项目结构化输出约束的兼容模型服务                    |
| 客户存储       | SQLite 客户主档案，飞书后台协作镜像；业务状态另按主题管理             |

选择 DeepSeek 网页检索时，继续使用「网页检索 API 基础地址」和「网页检索 API Key」字段，地址默认 `https://api.deepseek.com`，Key 需填写。网页检索与研究模型分别配置。兼容 HTTP 搜索服务仍需实现 `/search`、`/extract` 的现有请求与结果格式；仅更换地址和 Key 不会自动兼容另一家服务的原生接口。

研究模型使用「API 连接」中保存的模型 ID；日常运行沿用该值，更换服务或模型时填写服务商提供的 ID 并保存。模型目录查询与选择功能已移除，配置和保存无需访问模型服务。推理强度不在日常设置页展示，后端沿用已有配置，未配置时默认 `none`。

具体配置名以 [环境示例](../.env.example) 和「API 连接」实际字段为准。`npm run preflight:native` 核对配置、飞书可读性与模型，不执行搜索或写入；`npm run verify:native:live` 使用真实搜索／模型额度，飞书写入由隔离模拟替代。“已填写”不代表业务能力已实测。

## 任务预算与恢复

新增目标默认 20 家，允许 1–200 家，只计去重后写入并读回确认的新企业。既有档案更新、重复候选、未入库待核实及不确定写入不计新增。已核实主体和相关产品线的企业可保留开发机会；经营国家未知仍入库并计入实际新增，国家留空，在客户库“全部市场”筛选中的“待核实”集中查看，不能用搜索目标代填国家。已证实国家与目标市场不符时仍排除；未公开采购量、负责人、经营年限或邮箱不单独阻止收录。

执行记录中的未入库“待核实”候选可查看已保存的官网身份与产品依据，核对或更正企业官网后点击“重新核实并尝试入库”。重新核实使用独立幂等操作，仍需通过原文、主体、产品、去重及客户主库读回等校验；飞书镜像同步单独核对。成功后该行持久显示“核实后已入库”并链接客户档案，原获客轮次的历史新增数不回算。结果不明时只核对原操作，不换编号重写。当前获客任务正在处理时暂不能提交人工核实，自动任务继续运行。

同一实例只允许一个活跃任务。研究预算默认 `min(1600, max(12, 8 × 目标))`，可指定 1–1600；搜索最多 `max(20, 3 × 目标)` 次，累计运行最多 6 小时。达到目标结束，候选或预算不足报告部分完成及缺口。轮换产品与市场，只有排除列表变化后才重复付费执行同一查询。

停止等待当前企业处理到可保存状态，保留已有结果。关闭网页不停止后端；服务重启后，直连任务会核对未完成企业：明确在写入前中断的研究最多自动重试一次并继续队列，写入或阶段不明仍暂停核对。未知远端写入按原操作编号与已有记录 ID 核对，不能因超时而重新研究或新增。已退役引擎的历史任务仅供查询，不能交给当前引擎恢复执行。

仅采集字段可按核实结果更新；负责人、人工开发信息和首次发现时间等受保护字段不被研究覆盖。同域名多行或指定记录 ID 与官网不匹配时停止写入。远端写前持久化意图；新增携带稳定操作标识，响应不明时保留待核对，不凭域名相同推断这次操作成功。

## 连接与定时计划

「获客任务」内统一显示新建任务、定时计划和执行记录。新建页面按目标客户、执行安排、获客后处理分组；产品范围直接展示，指定产品时隐藏室内外偏好。默认全部窗饰业务、不限客户类型、每轮 20 家、立即获客、仅获客。定时设置区分仅执行一次（一个日期、一个时点）和重复执行（每周多选星期，最多 24 个无重复时点），统一 `Asia/Shanghai`，精确到分钟。重复计划从创建当天开始，持续到暂停或关闭；仅接受 `once`、`weekly` 和 `times` 时间列表，重复计划必须明确选择星期，选满七天即每天执行。

右侧摘要显示目标客户、每轮目标、完整一周的计划轮数及新增目标合计、实际下次执行时间和自动首发状态；数量均为目标，不保证实际收录或发送量。定时提交按钮为“创建并启用计划”，不是保存草稿。

调度默认每 15 秒核对到期计划，与手动任务共享单活跃限制。计划分钟内可以触发；跨过该分钟、连接未就绪或当前任务繁忙时跳过该时点，不积压补跑，也不打断正在执行的任务。重启后跳过过期时点，当前分钟仍有执行时点且条件就绪时立即执行，否则推进到未来时点。单次计划错过时点后结束，次数保持为实际触发数并显示跳过原因。人为暂停后恢复同样只从未来时点继续。关闭保留历史；暂停／关闭已启动轮次时，待当前企业处理后停止。每次以计划 ID 和原定时点构成持久幂等键；已创建但尚未记账的任务先恢复关联，重启不重复建任务。

## 获客后自动首发

开启自动首发后可选择“首封未回复自动跟进”，默认关闭。立即获客用于该轮；定时计划中的选项用于之后建立的轮次，不改写已有发送计划。各轮已建立的追信开关和暂停／恢复在沟通中心所属发送计划中管理；获客计划暂停或关闭同时阻止其追信继续。任务只读页和 T4 仅展示后续追信，首封不计入。

2026-11-05：新建立即获客或定时计划时可开启“获客后自动首发”，已有定时计划也可单独开启，默认关闭。开启后仅纳入后续轮次中实际新增或更新保存并读回确认的客户，不扫描历史客户库，也不将仅发现重复、未保存或结果待核对的企业加入发信范围。

每家客户保存成功后即可进入首封流程，不等整轮结束或飞书镜像同步。每轮开始读取最新已审核产品和可用邮箱，依据客户经营事实匹配，不受搜索产品限制；缺少邮箱或匹配依据等条件时列明原因，资料补齐后自动重新检查。每家企业仍只安排一封首信，沿用邮箱额度、发送间隔、客户实际往来与勿联系检查；明确失败与结果未知不自动重发。

暂停或关闭定时计划会同时停止尚未提交发送的首封，恢复后重新核对未发客户。立即获客的执行详情可独立暂停或恢复自动首发，停止这轮立即获客也会暂停首发；自然完成或部分完成仍继续处理已确认的客户。执行记录中的“查看首发进度与缺项”进入沟通中心的对应记录，控制入口保留在获客任务。设计依据见 [ADR-0023](adr/0023-acquisition-scoped-automatic-first-touch.md)。

## 官网采集与证据

每家最多读取五个计划内同域 HTTPS 页面，从首页及真实链接发现联系、关于、服务范围及必要法律页面。直连失败或只返回明确加载空壳、脚本提示、挑战占位及无信息残片时，按网址先补采 basic；仍无有效正文时最多升级一次 advanced，成功网址不重复提取，各次请求及供应商返回的费用累计记录。补采仍受原范围限制，有效正文替换同网址空壳；真实短页和完整但业务无关的页面不会仅因字数或缺少产品词触发补采。全部失败不调用研究模型或写客户；部分失败保留有效证据，产品依据不足时标为采集未完成、待核实。完整 HTML 提供联系方式、追踪代码及社媒提取；研究正文与独立字段提取分别保存。

研究输入最多五个有效 URL，每页 16,000 字符、合计 80,000 字符；这是正文预算，不是总 token 预算。引文必须存在于实际提交的正文，不用模型常识补事实。原始 HTML 上限 4 MiB。官网读取支持 `WEBSITE_HTTPS_PROXY`，Windows 未显式指定时读取已启用系统代理，缓存 30 秒；公网地址、同域跳转、TLS 与私网拒绝校验继续生效。

原生引擎在预算截断前折叠同页精确重复块、重复短菜单并清理明确的 Cookie 控件；法律及隐私页只压缩可识别的模板段落，保留公司、法人、商号、邮政地址、产品用途、否定说明及第三方归属。无法可靠分类的正文保留；已识别的平台来源保留原文供来源预筛。删除位置及预算截断使用独占一行的 `[...]` 标记，引文不能包含或跨越该边界，模型与证据核验使用同一份正文。完整 HTML 联系证据不受精简影响；操作用量保存 `original_chars`（精简前）、`compacted_chars`（精简节省）及 `input_chars`（预算后实际正文），字符减少不直接视为 token 或耗时同比减少。

电话区号依据实际企业国家或原国际区号；规范值去重，保留分机，最多三个主要号码，不将分支网点全部混入。实际地址、服务范围和搜索目标分开，社媒保留来源。获客不抓取广告追踪代码。采购需求必须有企业明确表达的原文，经营产品不能冒充采购意向。企业名称与联系人边界见 [客户数据](customer-data.md#企业身份与联系方式)。

模型响应只在正文、URL、目标、提示词、Schema、模型及请求参数均相同时精确复用，保存 7 天、每表作用域最多 200 项。每轮仍重新采集并执行当前核验、准入、评分和写入读回；复用响应不复用旧写操作。记录实际请求尝试、复用次数、正文字符及供应商返回的 token，未提供统计时保持未知。

## 市场地区与数据许可

美国提供 50 州及华盛顿特区，澳大利亚 8 州／领地，加拿大 13 省／地区，英国采用 ONS 的 12 个 ITL 1 市场地区；欧洲展开国家、不下钻城市。界面显示中英文名称，请求与历史计划沿用英文值；不把英国的统计地域解释为统一行政层级。

`server/data/geography.json` 为 [Countries States Cities Database](https://github.com/dr5hn/countries-states-cities-database) 名称与代码的派生子集，来源提交 `d345fcf530996528b598f17c827f15c5c246cd25`，2026-10-19 获取；派生数据按 [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/) 提供，全文见 `server/data/GEOGRAPHY-LICENSE.txt`。原城市参考不参与当前选择器。

英国地区依据 [ONS 2025 年 1 月 ITL 1 数据](https://geoportal.statistics.gov.uk/datasets/a1c258da2f404f93ad43b98d04a3c726_0/explore)，主来源采用 [Open Government Licence v3.0](https://www.nationalarchives.gov.uk/doc/open-government-licence/version/3/)。这里保留既有数据的来源和许可，不宣称重新核实最新行政区划。
