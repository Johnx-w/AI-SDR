# 初始开发优先级

当前规则为 `acquisition-v4.0`。评价单位是企业的一项具体供货方向和产品族；成品、材料配件和样本展示分别取证，不跨方向借用经营角色。模型提取官网事实，程序核对引文、来源和产品方向后给出结论。

## 匹配与排序

先核对企业主体、目标产品、市场、客群和必需条件。明确不匹配的新发现企业不建客户档案；主体冲突或必需条件待核实的机会暂停自动开发。一个方向不适合时仍可保留同企业另一个有效方向。

已收录的有效企业按以下规则排序：

| 开发优先级 | 同一供货方向的依据                                                                 |
| ---------- | ---------------------------------------------------------------------------------- |
| 高优先     | 主营产品与对应专业或综合供货角色均已核实                                           |
| 常规开发   | 相关产品已核实，但主营程度或对应经营角色尚无充分依据，或产品只是明确副线／邻近业务 |

匹配等级单独说明产品关联是明确匹配、潜在匹配、待核实或不匹配。优先线索保留主营产品、供货角色、现有供货流程、定制及系统特征等已核实事实和原文来源。年限、网点、案例、定制、联系人及公开采购需求未知不会压低开发优先级，也不补成已确认事实。成品业务可以支持潜在材料供货机会，但不证明材料采购方式或采购意愿。

客户可进入客户库而暂时没有可发送的邮箱；实际首封发送仍须满足企业身份、公司级联系入口、内容依据和触达计划授权。同一企业只要仍有经营事实或必需条件冲突，即使其他产品已获高优先评级，也暂停自动首封。首封候选先选高优先，再选常规开发。已保存的旧 A/B/C 等级筛选计划需要明确更新后才能匹配新版客户。未回复后的定期邮件联系不在本次规则内。

## 档案与历史

客户档案不因官网未公开年限、采购量、负责人或定制细节而默认显示“待确认／补资料”；真实的主体、产品或强制条件冲突仍列出复核事项。材料采购细节可在业务沟通中确认，不作为获客项目的人工补档前置条件。

每企业保留本地最新评估快照。旧 A/B/C 和已支持分数按原规则版本只读显示；新版理由展示匹配等级、开发优先级、优先线索与来源，不展示百分制总分。补充资料如有真实依据仍可按对应产品方向重算，但不要求销售为了让评分完整而补齐普通官网缺项。重新评价旧快照前须备份，因为保存新快照会替换该企业的旧快照。
