# 评分

当前初评规则为 `acquisition-v3.2`，每企业只保留最新评估。旧评分 v1/v2/v3 及历史量表见 [归档](archive/2026-10-28/README.md)，不混入当前规则。

## 业务初评

评价单位是企业与具体供货方向／产品族。模型只提取事实及原文来源，程序核验后按固定规则计算，各方向分别评价，企业展示最佳有效方向；不跨方向拼分。

| 维度             | 满分 | 主要依据                                                                       |
| ---------------- | ---: | ------------------------------------------------------------------------------ |
| P 产品契合       |   40 | 具体目标产品是核心、副线、邻近或无关；主营档 40，明确副线档 30                 |
| R 经营角色       |   30 | 专业供货角色 30，明确承担该产品的综合供货角色 25；仅安装／维修等按对应较低档位 |
| D 持续经营       |   20 | 有证据的经营年限、实际网点／经销商、独立交付案例及当前供货流程                 |
| V 定制与系统特征 |   10 | 同方向可匹配的定制，以及电动／自动化或工程配套特征；分别最多 5                 |

未知项保留未知，不按比例补满。P≥30、R≥25 且已支持总分≥75 为 A、≥60 为 B，其余相关企业保守为 C；D 未知不单独阻止 A/B。产品／角色评分证据不完整时仍可保留已核实相关企业的 C 初评，主体冲突或明确不匹配分别处理。实际固定档位和引文校验以 `server/customer-assessment.mjs` 为准。

A/B/C 是初始开发优先级，不代表采购意向、成交概率、资料齐全、采购负责人已找到或已联系。成品经营可以支持潜在材料供货机会，但材料采购方式仍待沟通；没有公开求购不等于无开发价值。

## 最新评估与补充资料

官网研究 → 原文与方向核验 → 程序评分 → T2 写入及读回 → 本地最新快照。每企业的新评估原子替换旧快照，保留分项、来源、缺项、限制、时间和规则版本；T12 和历史同步入口已取消。不接受客户端直接提交分数，也不将人工评级伪装成自动结果。

「客户库 → 企业详情 → 最新评估」展示已有结果。无自动结果显示空态；客户表与企业范围隔离，旧操作恢复不能覆盖较新的快照。远端写入或快照保存失败沿原操作核对，不重复搜索、调用模型或新增客户。

「补充资料」记录事实、产品方向、依据、确认人和服务端时间，按原评分规则重算，不接受手填加分。相反官网证据仍保留冲突，普通备注不能清除缺项。采购需求须引用同客户真实来信／确认通话，不能冒充官网公开需求；保存补充本身不自动建 T1。

人工确认保存在 `lead_supplements`，不随最新快照替换删除；同产品重新研究继续应用，来源标记人工确认。官网读取失败保留原有有效依据及其时间，新增研究限制，不用失败时间冒充成功取证时间。
