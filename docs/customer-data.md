# 客户与产品数据

当前口径：2026-10-28。网页是日常操作入口，飞书保留业务资料与协作镜像，运行状态和完整记录在后端持久化。旧字段改名、建表、数据清理及验收台账均已 [归档](archive/2026-10-28/README.md)，不重复执行历史迁移。

## 业务表和数据归属

| 表          | 职责                                                 | 关联                 |
| ----------- | ---------------------------------------------------- | -------------------- |
| T2 企业档案 | 企业身份、经营画像、来源、初评摘要和人工业务信息     | 同一真实企业统一建档 |
| T5 产品资料 | 公司产品、采购形态、参数、来源、品牌市场、审核和版本 | 供需求与任务引用     |
| T1 采购需求 | 客户明确表达的采购／咨询、规格数量、阶段和负责人     | T2、T5、来源 T3      |
| T3 沟通记录 | 实际往来的原文、参与方、渠道、时间和结果             | T2、相关 T1          |
| T4 跟进任务 | 下一步行动、时间、执行方式、负责人及实际结果         | T2、T5、T1、相关 T3  |

T12 及独立评分历史已取消，每企业只维护一份最新评估。关键词、获客执行与计划、连接凭证、邮箱和自动接待配置由网页及后端维护，不再增加飞书运行控制表。关联使用稳定编号和真实记录 ID，不用名称作为关系键。

T2 五列的现行名称为初评结果、企业经营产品、主营产品概况、公开采购需求、企业服务客群；另保留企业官网、主要供货机会和待确认事项。历史旧名只用于兼容读取，不代表新增一套字段。

## 企业身份与联系方式

公司名称优先采用官网自述经营法人全名，保留原文与法律后缀；仅能确认商号时保留商号并标明法人未知。别名独立保存，品牌、商标持有人、母公司、网站制作商或经销品牌不自动等于网站经营主体。自述法人名称不等于工商登记或海关主体已经核实。

每项身份结论保留原文、同站来源和时间；主体冲突进入待核实，名称或官网变化后不套用旧结论。身份资料按客户表、记录 ID、域名与当前名称隔离。海关需要名称之外的地址等证据进一步匹配。

主体和相关经营产品已核实、但国家尚不能确定的企业照常收录，国家保持空值；客户库市场显示为“待核实”，可在“全部市场”下拉中单独筛选。之后取得实际国家依据并更新档案时，归入对应市场。“待核实”在此表示国家未知，不表示客户业务不匹配或尚未入库。

客户库及详情读取已保存资料；联系方式页可按当前功能重新核实官网，补充项保留来源与原文，不把一次读取失败当作联系方式不存在。电话、邮箱按规范值去重，区号取实际经营国，分机保留，网点号码与主电话区分。联系入口齐全不代表联系人就是采购负责人，个人邮箱不证明客户为个人消费者。

产品显示可使用 `English product name(中文名称)`，中英文同名合并只影响展示，不新增采购事实。公开采购需求须有企业在公开来源明确表达的逐字证据，客户私信需求另存 T1。广告代码仅证明检出追踪配置，不能证明正在投放。

## 企业与产品资料

「产品与资料」维护具体产品、英文名、采购形态、已核实参数、MOQ、交期、品牌与市场、原始来源、附件、版本和审核。获客产品／搜索词库用于找客户，不自动成为公司供货目录或对外承诺。

未知事实留空；资料审核需要可回查依据与审核人。实质变更后重新待审，新批准只作用于对应版本和适用范围。可外发完整事实句及其限制条件随资料审核，易变商务事实按有效期核对；稳定产品事实不要求每日重新确认。

资料完备按某封邮件实际引用内容判断，不要求整个产品库填满。资料审核、品牌覆盖、自动发信授权和文件外发许可分别核对；公司总目录有产品不代表任一邮箱获准用于首封开发。实际发信规则见 [邮件沟通](outreach-first-touch.md) 和 [自动接待设计](ai-sales-agent-design.md)。

产品保存在 SQLite 并同步 T5，归档保留查询。新增使用幂等操作，编辑要求当前版本，网页保存与远端同步分别报告；远端结果不明按产品编号核对，不重复新建。

## 客户读取副本

客户库优先读取本机 SQLite 副本。首次需完整同步飞书；之后立即返回已有快照，后台更新。客户库可见时每 60 秒检查；隐藏时暂停前端轮询，重回页面立即检查；后台在 2 分钟没有活跃信号后降至 5 分钟。主动刷新与获客写入核验不受空闲间隔限制。

同步完整验证全部分页后，以事务更新实际变化的记录，未变项只更新时间；同步失败保留旧快照。客户的内容版本独立，其他企业变化不使其详情失效；人工确认与补充资料不会被保存前启动的旧同步覆盖。不同客户表配置隔离存储作用域。

列表加载轻量摘要，完整档案按详情或导出读取；当前筛选和分页仍在网页进行。同步指标与请求耗时只记录计数、耗时和大小，不保存客户内容或凭证。服务重启后累计请求性能统计重新计算，客户副本与同步事实持久保存。

## 会话需求与跟进任务

「客户业务」按企业维护会话，再登记实际消息，从同企业、同会话的真实来信或确认通话原文摘录建立需求。一个消息可支持多个品类需求，同一企业及会话不因品类重复建档。客户要求与公司确认能力分别保存，引用 T5 不表示已经确认满足全部规格。

沟通原文、收发方、时间和实际结果不可用摘要覆盖；后续可补关联与备注。草稿、计划和不确定发送不登记为已成功联系。明确匹配企业和固定邮箱的真实邮件可桥接为沟通记录；当前同步与人工回复不自动创建采购需求或改变接待归属。

任务明确人工执行或系统计划，默认人工执行，不采用固定 1/3/5/7 天节奏。执行前核对最新消息、资料版本和接待状态；人工接管暂停对应系统任务，保留真人自己的任务。客户新回信使旧跟进依据失效，需核对后恢复，不补发积压内容。

沟通类任务完成须关联同客户、同会话及所涉需求的实际发送证明；内部行动填写具体结果。任务核验、任务完成和存在系统计划都不产生渠道发送许可。当前任务执行接口明确返回 `automaticSend:false`；自动回信和追信按最终设计另行接入。

## 开发进度与暂缓

开发进度按实际事实展示：正式邮件被服务商接受或已核实发出后为已联系，正常客户来信为已回复，有真实需求及后续推进依据时为跟进中。保留更后续的人工进度与成交状态；草稿、失败、未知结果、系统自动回复或官网画像不能推进进度。飞书原始信息与本地计算分别保留。

企业暂缓按同一家企业控制已关联联系人及自动开发计划，必选原因，可填复查日期；到期只提醒，不自动恢复。人工收信、人工回复和实际沟通记录保留。恢复需核对最新沟通，旧草稿失效、任务单独核验，不能补发积压邮件。将来接入自动回信时同样遵守企业暂缓，人工交回接待不自动解除暂缓。

## 持久化与同步

客户副本默认 `.data/lead-library.sqlite`；客户业务默认复用获客数据库，可用 `CUSTOMER_BUSINESS_DB_PATH` 指定；产品及资料使用既有后端持久库。所有业务图按客户主表范围隔离，创建幂等、修改核对版本。

网页维护客户业务图，飞书是协作镜像；直接修改飞书的 T1/T3/T4 不自动导入后台图。镜像先核对 T2/T5，再保存稳定记录，最后写循环关联；完整读回一致才报告同步成功。本地保存成功后远端异常不丢记录，异常写入先核对，日志按 `BUSINESS_MIRROR_JOURNAL_PATH` 保存。

日常新增、编辑与同步使用网页。建表和字段迁移命令用于受控初始化，不作为每次启动步骤；历史备份和迁移记录保留在本机忽略目录。运行、备份和接口见 [架构与运行](architecture.md)。
