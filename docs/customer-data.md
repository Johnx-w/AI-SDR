# 客户与产品数据

当前口径：2026-11-10，自动整理、页面精简与两次追信已完成本地实现，云端以实际部署版本为准。网页是配置与例外处理入口，飞书保留业务资料与协作镜像，运行状态和完整记录在后端持久化。本次覆盖前设计见 [归档](archive/2026-11-10/customer-automation/README.md)；旧字段改名、建表及数据清理见 [历史归档](archive/2026-10-28/README.md)，不重复执行历史迁移。

## 业务表和数据归属

| 表          | 职责                                                 | 关联                 |
| ----------- | ---------------------------------------------------- | -------------------- |
| T2 企业档案 | 企业身份、经营画像、来源、初评摘要和人工业务信息     | 同一真实企业统一建档 |
| T5 产品资料 | 公司产品、采购形态、参数、来源、品牌市场、审核和版本 | 供需求与任务引用     |
| T1 采购需求 | 从真实来信自动整理的采购／产品咨询及其原文依据       | T2、T5、来源 T3      |
| T3 沟通记录 | 实际往来的原文、参与方、渠道、时间和结果             | T2、相关 T1          |
| T4 跟进任务 | 系统安排的后续追信、计划时间及真实执行结果           | T2、T5、T1、相关 T3  |

T12 及独立评分历史已取消，每企业只维护一份最新评估。关键词、获客执行与计划、连接凭证、邮箱和自动接待配置由网页及后端维护，不再增加飞书运行控制表。关联使用稳定编号和真实记录 ID，不用名称作为关系键。

T2 五列的现行名称为初评结果、企业经营产品、主营产品概况、公开采购需求、企业服务客群；另保留企业官网、主要供货机会和待确认事项。历史旧名只用于兼容读取，不代表新增一套字段。

## 企业身份与联系方式

公司名称优先采用官网自述经营法人全名，保留原文与法律后缀；仅能确认商号时保留商号并标明法人未知。别名独立保存，品牌、商标持有人、母公司、网站制作商或经销品牌不自动等于网站经营主体。自述法人名称不等于工商登记主体已经核实。

每项身份结论保留原文、同站来源和时间；主体冲突进入待核实，名称或官网变化后不套用旧结论。身份资料按客户表、记录 ID、域名与当前名称隔离。

主体和相关经营产品已核实、但国家尚不能确定的企业照常收录，国家保持空值；客户库市场显示为“待核实”，可在“全部市场”下拉中单独筛选。之后取得实际国家依据并更新档案时，归入对应市场。“待核实”在此表示国家未知，不表示客户业务不匹配或尚未入库。

客户库及详情读取已保存资料；联系方式页可按当前功能重新核实官网，补充项保留来源与原文，不把一次读取失败当作联系方式不存在。电话、邮箱按规范值去重，区号取实际经营国，分机保留，网点号码与主电话区分。联系入口齐全不代表联系人就是采购负责人，个人邮箱不证明客户为个人消费者。

产品显示可使用 `English product name(中文名称)`，中英文同名合并只影响展示，不新增采购事实。公开采购需求须有企业在公开来源明确表达的逐字证据，客户私信需求另存 T1。

## 企业与产品资料

「产品与资料」维护具体产品、英文名、采购形态、已核实参数、MOQ、交期、品牌与市场、原始来源、附件、版本和审核。获客产品／搜索词库用于找客户，不自动成为公司供货目录或对外承诺。

未知事实留空；资料审核需要可回查依据与审核人。实质变更后重新待审，新批准只作用于对应版本和适用范围。可外发完整事实句及其限制条件随资料审核，易变商务事实按有效期核对；稳定产品事实不要求每日重新确认。

资料完备按某封邮件实际引用内容判断，不要求整个产品库填满。资料审核、品牌覆盖、自动发信授权和文件外发许可分别核对；公司总目录有产品不代表任一邮箱获准用于首封开发。实际发信规则见 [邮件沟通](outreach-first-touch.md) 和 [自动接待设计](ai-sales-agent-design.md)。

产品保存在 SQLite 并同步 T5，归档保留查询。新增使用幂等操作，编辑要求当前版本，网页保存与远端同步分别报告；远端结果不明按产品编号核对，不重复新建。

## 客户档案主库

直连引擎以云端 SQLite 为客户档案主库。首次没有本地资料时完整导入飞书历史客户；之后列表、详情、去重和新增核验优先读取 SQLite，后台同步不阻塞已有档案。研究、新增及联系方式／补充资料修改先在同一事务保存档案和待同步操作，再后台同步飞书。飞书异常不影响本地保存与新增计数，网页分别显示本地保存和待同步数量。

飞书保存完整读回一致后才清除对应版本的待同步状态；响应丢失、进程重启或同步期间再次编辑均保留核对依据，旧同步不能清除新修改。新客户使用稳定本地编号，飞书编号单独关联；同步沟通、需求和跟进任务时转换关联编号，不变更本地客户关系。相同官网存在冲突或飞书主体变化时提示核对，不自动覆盖。

客户库可见时每 60 秒检查；隐藏时暂停前端轮询，重回页面立即检查；历史导入检查在 2 分钟没有活跃信号后降至 5 分钟；数据库到飞书的写入同步仍由服务器每分钟执行。手动「同步飞书」立即核对待同步操作并导入尚无本地档案的历史客户；直接修改或删除飞书 T2 不覆盖或删除本地主档案，日常编辑应在网页进行。客户的内容版本独立，不同客户表配置隔离存储。

列表加载轻量摘要，完整档案按详情或导出读取；当前筛选和分页仍在网页进行。同步指标与请求耗时只记录计数、耗时和大小，不保存客户内容或凭证。服务重启后累计请求性能统计重新计算，客户副本与同步事实持久保存。

## 自动记录与人工边界

日常获客、发信、收信、记录与常规跟进由系统执行；人工负责配置、产品资料和例外处理。删除客户下独立的采购需求、沟通记录页面及手工新增、编辑流程，删除专属表单、接口、导航和人工确认需求入口；后台的真实邮件、会话、固定邮箱、需求证据和飞书关联继续保留。官网研究得到的“公开采购需求”不属于手工采购需求模块。

沟通中心是完整邮件往来的唯一日常查看入口，保留原格式阅读、实际收发结果和必要的人工回复。消息原文、参与方、时间和实际结果不能被后续摘要覆盖；自动回复、退信、失败和结果未知分别保存。记录或飞书同步失败不得触发重新发送。

### T1 自动整理采购需求

客户明确询问具体产品、索要报价或提出采购条件时，从已明确归属企业及会话的真实客户来信自动生成需求，不要求逐条人工批准。每项需求保留客户原文及来源消息；规格、数量等缺失就留空，不用官网画像、我方发信或模型猜测补齐。纯致谢、拒绝联系、自动回复和退信不创建需求；现有 T3 客户需求摘要可能包含拒绝态度，不能将所有摘要直接复制成采购需求。

同一会话同一事项的补充更新原需求，明确的新项目建立新需求；一封来信可涉及多个独立事项。有歧义或依据不足时保留待核实原因，作为例外处理，不自动决定冲突事实。新消息更新不能覆盖既有原始邮件。客户要求与公司供货能力分别保存，关联产品资料不等于承诺满足客户要求。

T1 由服务器持久化后自动同步飞书；网页不恢复手工建单流程，飞书也不是反向控制入口。历史真实需求保留，不为了让表格有数据而将普通兴趣或未证实机会转成需求。

### T4 自动追信与只读任务页

跟进任务页面只展示自动任务的客户、原始沟通、计划时间、状态、原因及实际结果，删除全部手工新增、修改、标记完成等操作。暂停、恢复、取消通过所属发送计划处理，不在只读页维护另一套控制状态。

一条 T4 任务对应一次系统安排的后续追信。首封开发、客户来信和即时回信不生成 T4；未接通的 WhatsApp、网站留言及电话不生成占位任务。首封未回复跟进按 [自动接待设计](ai-sales-agent-design.md#首封未回复跟进) 的既定规则执行：从首封成功发送起 72 小时、168 小时各一次，不扩展到询价或报价后的沉默。

任务状态使用待执行、已完成、跳过、终止；实际发送成功才完成。计划暂停、自动回复、额度不足或核验失败保留待执行并展示原因；超过补发期限则跳过，客户真实回复、人工成功发信或计划取消则终止剩余任务。失败或发送结果未知不能写完成，也不得自动重发未知结果。

计划未开启追信或没有新首封成功发送时，T4 可以没有真实任务。历史人工任务只保留历史事实，MOCK 记录不进入真实自动任务列表、统计或执行队列，均不得自动转换为新的发信授权。

### 实施范围与验收

本次范围包含页面精简、T1 自动提取与同步、T4 只读展示和首封未回复两次自动追信。自动来信接待、报价后跟进及其他渠道执行仍按各自设计另行接入。已有首封计划默认不启用追信；明确开启仅覆盖之后成功发送的首封，历史首封不自动回填为待发任务。

后台每分钟增量收信并整理已匹配客户的真实来信，T1 提取复用 API 连接中的研究模型。按来源消息及处理版本去重，更新保留最初引文和后续补充证据；缺配置或提取失败保留原文并重试，歧义原因在沟通中心可见，由人工通过澄清邮件处理。没有逐条手工建单或补录入口。

追信执行记录独立于首封统计，T4 是该执行记录的投影；首封数不会混入后续追信，邮箱额度和最小间隔共同计算。SMTP 已接受后记录故障只重试补记录，重启时发送中的追信转为结果待核实，不自动重发。任务链接进入所属计划，客户链接进入该客户的邮件。

验收应覆盖：具体咨询自动形成 T1、同事项补充不重复建单、拒绝和自动通知不建单；邮件仍完整可读且同步 T3；首封不写 T4、两次追信按原时间执行；回复及人工发信停发；暂停、取消、24 小时过期和额度生效；重启及重复同步不重复发送；同步失败保留本地事实；旧手工入口移除且历史数据不被删除。

## 开发进度

开发进度按实际事实展示：正式邮件被服务商接受或已核实发出后为已联系，正常客户来信为已回复，有真实需求及后续推进依据时为跟进中。保留更后续的人工进度与成交状态；草稿、失败、未知结果、系统自动回复或官网画像不能推进进度。云端保存实际进度，再同步飞书。

## 持久化与同步

客户档案及待同步操作默认 `.data/lead-library.sqlite`，可用 `LEAD_LIBRARY_DB_PATH` 指定，须一起持久化备份；原有副本原位升级并保留记录编号。客户业务默认复用获客数据库，可用 `CUSTOMER_BUSINESS_DB_PATH` 指定；产品及资料使用既有后端持久库。所有业务图按客户主表范围隔离，创建幂等、修改核对版本。

所有修改先写云端 SQLite，服务器每分钟同步待处理变化，关闭网页不影响执行，重启后继续。系统依据真实邮件及执行事实维护客户业务图，飞书是协作镜像；直接修改飞书的 T1/T3/T4 不自动导入后台图。镜像先核对 T2/T5，再保存稳定记录，最后写循环关联；完整读回一致才报告同步成功。本地保存成功后远端异常不丢记录，异常写入先核对，日志按 `BUSINESS_MIRROR_JOURNAL_PATH` 保存。

产品与配置通过网页维护，T1/T3/T4 由系统产生并自动同步。建表和字段迁移命令用于受控初始化，不作为每次启动步骤；历史备份和迁移记录保留在本机忽略目录。运行、备份和接口见 [架构与运行](architecture.md)。

T2 新增评级依据摘要、最近联系时间和最近回复时间。领导原表 T3 按一轮发送及其回复一行展示，后台仍逐封保存原文；完整正文同步飞书，HTML 和附件在沟通中心查看。未配置原表编号的旧镜像仍按其既有结构同步。低频字段仅隐藏，未删除。明确不匹配的新客户不入库；已有往来者保留原记录及关联，移出日常视图，不另建归档或恢复流程。
