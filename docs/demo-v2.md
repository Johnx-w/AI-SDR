# 窗饰获客工作台 V2 演示说明

## 演示路径

1. 运营总览：点击“去审核”进入沟通中心，查看客户询盘、AI 示例草稿、需求与跟进状态。
2. 沟通中心：修改草稿并保存；“审核并发送”打开确认窗口，确认后仅模拟发送。待处理数量减少，并自动增加跟进事项。
3. 跟进计划页面已移除；首页待办和原有沟通数据保留。
4. 客户库：筛选演示客户，打开画像、证据与联系方式；可以手工录入演示客户、修改状态并导出 CSV。
5. 切换“真实获客”：从飞书实时读取客户。不匹配与待核实客户同样保留。点击客户可查看原始官网事实、联系证据和画像 JSON。
6. 获客任务：创建 mock 扫描，切换暂停与继续，模拟完成；通过“真实 n8n 工作流”打开原有真实任务表单。
7. 产品与资料：筛选与预览演示目录、技术资料和沟通模板。

## 数据与工作流边界

- 演示操作仅影响浏览器 localStorage；“真实获客”仅支持读取，不提供改写真实客户、生成真实邮件或外发功能。
- 原获客工作流 `EycE9OmaPkRFUDSq` 保留原有搜索、画像与入库闭环；仅升级“构建飞书记录”中的联系方式提取段，修复美国号码漏采。Webhook 认证、幂等、防并发、超时处理及执行记录接口保留。
- 独立只读工作流 `n5emHnlFL4iTQSNW`：受 Header Auth 保护的 GET Webhook → 获取飞书 token → 读取现有客户表。请求中的 cursor 只能作为固定飞书表接口的分页参数，不接受用户指定外部 URL。
- 服务端遍历分页后向前端返回标准化客户，飞书失败时展示错误，不回退为 mock 客户。前端可手动刷新；未完整读取时不展示为成功。
- 真实记录没有评级或评分时显示“未评分”。目标国家、目标城市仅为任务条件，不补作真实企业地址。
- 官网事实为采集时的历史证据；联系方式为公开发现，不代表已验证投递或已获得 WhatsApp 联系许可。

## 联系方式展示

客户详情中的域名指向官网首页，“联系方式”内来源链接指向原研究页。页面只显示已入库信息；官网联系方式补采功能及接口已移除。电话格式、来源页优先规则及现有数据清理见[客户联系方式与页面精简](customer-contact-cleanup.md)。

纯函数 `server/contact-extractor.mjs` 同时用于本地补全和 n8n。优先提取显式电话/邮箱链接及 JSON-LD，再检查可见正文，排除普通脚本、SVG 数字和资源路径。每条记录保存规范值、公开原值、来源页、引文与提取方式。现有画像内有联系证据而独立字段为空时，也能读出已有联系方式。

`tests/fixtures/n8n-build-record-original.txt` 保留升级前的入库节点用于回归；`server/n8n-contacts.mjs` 仅替换联系提取段，其他原逻辑保持。已用模拟 n8n 上下文验证美国电话、字段映射、客户身份键和异常分支，并将新规则发布至原工作流；未重新触发真实获客搜索或历史客户写入。

## 验证

`npm run build` 编译 TypeScript 并生成生产构建。`npm test` 包含原有 n8n 接口测试与飞书读取测试，覆盖分页、异常、认证边界、无伪造评分和实际所在地保留。

浏览器验收包括真实客户切换、客户详情、草稿编辑与审核、新增跟进事项以及模拟发送不发起外部消息。页面适配桌面双列总览、三栏沟通中心及窄屏堆叠布局。
