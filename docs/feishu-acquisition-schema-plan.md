# 飞书获客字段调整草案

**历史方案，已被2026-10-21用户要求的[简化两表方案](feishu-acquisition-simplified.md)替代。** 下文三表、新增大量主表列和批量改名不再作为首期实施指令。当前T2仅执行用户指定字段变更并新增评级依据，T12为评估历史，不建供货机会表。

状态：待用户检查，尚未执行字段增删、改名或评分回写。2026-10-21通过现有飞书客户端只读取得当前主表24个字段及类型，并列出当前配置多维表格中的全部表：仅有 `T2 客户主表`。此前一条空白记录已在用户授权下备份清理，随后读回26条客户记录。

最终核对入口：[首期汇总清单](acquisition-final-review.md)。新增评分完整性和海关数据状态摘要，以便区分真实支持分与缺项；字段操作仍待整体验收方案确认后实施。

## 落地原则

- 网页是主操作入口，服务端持有身份、机会、证据、评估、执行及责任人等完整关系；飞书同步摘要和必要历史供公司查看。
- 同一企业一行主档，多个供货机会和每轮评估分别存放，不把它们拼成一个无法追溯的长文本。
- 现有主字段 `customer_id` 和记录关联保持稳定；迁入的26条客户标记为存量，其补全和重评不冒充新增客户。
- 当前代码使用字段名，部分字段还有必需校验。先改映射与兼容逻辑、建新结构并核对数据，再切换同步，不能先在飞书删列/改名。
- 不再需要的原字段先隐藏或转为历史字段；经过迁移核对后按用户认可方案清理。没有消息发送或主动飞书通知。

## 建议首期三张业务表

| 表                       | 一行代表什么                          | 主要内容                                                                 |
| ------------------------ | ------------------------------------- | ------------------------------------------------------------------------ |
| 企业客户主表（沿用现表） | 一家已归一企业                        | 企业事实、主联系入口、当前最高可开发机会摘要、准备状态、负责人及跟进摘要 |
| 供货机会表（新增）       | 一家企业的一个具体供货方向/产品族机会 | 产品关联、采购路径、潜力证据、障碍、五项评分及当前等级、关联主档         |
| 评估历史表（T12，新增）  | 某机会的一次版本化评估                | 规则版本、评分档位、证据、未知项、评估时间、人工修正及原因               |

原始海关行、完整网页正文、来源明细、多联系人、计划/执行和搜索词统计先由服务端保存，网页可查看定位；飞书按需同步摘要和记录引用。此方案不要求立刻建立参考文档全部12张表。已核实当前配置的这份多维表格仅有T2，实施时再读取最新结构，避免在并行人工修改后重复建表。

## 当前24列逐项处理

| 当前字段     | 当前类型     | 建议处理及最终含义                                                                                                     |
| ------------ | ------------ | ---------------------------------------------------------------------------------------------------------------------- |

| 相关产品     | 文本         | 迁移后可改名企业经营产品，表示其经营目录，不等于采购需求                                                               |

| 详细地址     | 文本         | 保留可核实的实际经营地址                                                                                               |

| 主营产品偏好 | 文本         | 改名主营产品概况；说明官网业务重心，不伪装成实际采购偏好                                                               |

经营角色建议值：批发商、经销商、进口商、贸易商、品牌商、制造商、零售商、工程承包商、服务商、其他。只选择有证据支持的角色；supplier泛称需结合实际经营模式，不能自动标进口商。

## 主表建议新增字段

| 字段            | 建议类型                 | 含义                                                                                          |
| --------------- | ------------------------ | --------------------------------------------------------------------------------------------- |
| 企业官网        | 超链接或兼容文本         | 已确认官网；与原发现来源分离                                                                  |
| 经营角色        | 多选                     | 兼营的实际角色，替代旧客户类型单选                                                            |
| 潜在供货方向    | 多选                     | 从有效机会汇总成品、材料配件、样本展示等，不作为明确采购需求                                  |
| 优先供货机会    | 文本/关联                | 说明当前最高可开发评分具体对应什么方向，避免只看公司分数                                      |
| 开发优先级分    | 数字                     | 对应机会的当前系统分数，无可评价机会时留空                                                    |
| 评分完整性      | 单选                     | 完整、部分缺项、未评估；与已支持分数一起展示                                                  |
| 海关数据状态    | 单选/文本摘要            | 未导入、未覆盖、待匹配、已匹配有相关记录、已匹配未检出相关记录、资料异常等；不统一写无采购    |
| 资料准备状态    | 单选                     | 待研究、研究中、待核实、待补全、可交接、暂不开发；内部身份/合并状态独立保存，摘要显示阻碍原因 |
| 业务负责人      | 文本，后续可映射飞书人员 | 显示网页账号对应人员；真正归属由服务端账号ID维护，不能拿网页用户ID假装飞书用户ID              |
| 开发状态        | 单选                     | 待开发、跟进中、已回复、暂缓开发等手工业务状态，不和资料准备混用                              |
| 联系准备情况    | 文本摘要                 | 公司入口是否具备、有无明确采购岗位，以及联系验证状态；姓名不等于其个人联系地址                |
| 待补信息 / 风险 | 文本                     | 规模、外采方式、身份或规格等尚待核实的内容                                                    |
| 最近研究时间    | 日期                     | 区别于真实沟通的最近接触时间                                                                  |
| 最近评估时间    | 日期                     | 当前有效机会的评估时间                                                                        |
| 评分规则版本    | 文本                     | 对应当前摘要的已发布规则版本                                                                  |

主表默认视图建议只显示企业名称、国家、经营角色、主营概况、优先机会、分数/等级、准备状态、业务负责人、开发状态及最近研究时间；联系详情和来源从详情展开。增加必要结构的同时减少默认视图噪音。

## 供货机会表建议字段

- 机会ID、关联企业、供货方向、产品族/具体拟供产品。
- 匹配理由、外采路径证据、规模证据、采购活动/扩张证据、事件日期及来源引用。
- 拟按评分v2保存P/R/D/V/I各项分数（未知留空）、官网支持小计、已支持总分、系统等级、规则版本及评估时间。旧v1历史保留原维度及版本，不能直接改列名混算。
- 真实规模/外采方式与来源、近期扩张事件单独记录；海关未接入和未知原因可见。校准的海关满分情景不写成正式分数或客户等级。
- 海关摘要保存观察窗口、相关数量/单位、独立进口票数、活跃月份、最近进口日期和来源批次引用，I的规模/频率/新近性分项分别留存；原始记录仍在服务端。
- 机会状态、强制条件、适配/商业障碍、未知项、人工优先级和调整理由。

一个机会只能引用同一产品方向和主体范围内的证据；不能把工厂材料采购证据套给成品机会，或把集团总规模套给某个分支。

## 评估历史表建议字段

- 评估ID、关联企业和机会、评估时间、规则版本与触发原因。
- 五项档位及分数、总分、等级、当时的未知项和障碍。
- 本次证据引用或摘要快照、证据时间范围。
- 自动/人工评估标记、操作人、修正前后结果和理由。

历史不随着主档当前值覆盖；规则版本升级和新证据重评追加记录。

## 迁移顺序和回退

1. 读取所有现有表，确认目标表、字段及关联；备份字段定义和原始记录至受控位置，记录迁移批次及恢复步骤。
2. 为现有客户建立稳定身份映射，原记录ID/customer_id不变，标记存量；未知主体/官网不猜测。
3. 新增需要的表/字段，集中修改读取、写入、校验、导出和去重映射；旧列暂时保留。
4. 把主营概况、经营产品、服务客群、明确需求迁到对应语义；经营角色、官网和新评分有证据再回填，不因空值覆盖旧有效信息。
5. 选少量存量客户试迁移，核对身份、联系信息、原评级历史、来源、状态及数据量；失败回退到批次前快照和旧映射。
6. 用户已确认规则后试算评分，确认结果展示、历史追加和企业最高机会摘要正确，再启用同步；主表等级不是对旧人工评级的无记录覆盖。
7. 完成读写回核对后调整默认视图，隐藏退休列；只有依赖、备份及数据核对全部通过后再决定物理删除哪些历史列。

当前硬依赖包括来源链接、客户名称、customer_id、客户类型、广告代码、需求产品、客户行业画像等；直接删列或改类型可能中断现有真实入库。实施时逐项适配，不把字段编辑与运行链路割裂执行。
