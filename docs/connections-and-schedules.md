# API 连接与定时获客

## API 连接

`/settings` 改为 API 连接页，填写 Tavily Key、DeepSeek Key/模型、飞书 App ID/App Secret 和多维表格 App Token/Table ID。保存时启用 Node.js 直连，后续任务使用新配置，无需重启。

服务端配置优先级：连接页保存值 > 进程环境（含 `.env`）。默认文件为 `.data/api-connections.json`，在 Git 忽略目录下，采用临时文件与原子重命名保存。密码输入留空保留原值，清除必须勾选对应项目。“已填写”仅表示有配置，不代表已经通过远端实际调用验证。密钥不会写入浏览器本地存储，也不会通过读取接口返回；非密钥标识和模型可回显编辑。

存在运行中或暂停待核对的任务、结果不确定的单次调用时，拒绝修改连接。保存后重新创建执行适配器和令牌缓存，清空旧客户读取缓存。历史任务、客户数据和定时计划保留。

接口：`GET /api/v1/connections`、`PUT /api/v1/connections`；PUT 接受 `{values: {配置名: 新值}, clear: [明确清除的配置名]}`。仅允许上述连接字段，不接受任意环境变量、路径或接口地址。

## 定时计划

在 `/automation` 选择“定时自动获客”，沿用当前产品、地区、客群、客户类型、画像、搜索词和新增目标，填写计划名、日期、一个或多个执行时间、指定日期/每天/每周。所有时间使用 **Asia/Shanghai（北京时间）**，精确到分钟；每周按开始日期的星期执行。可添加或删除时间点，例如 `09:00`、`14:30`、`18:00`，当天每个时间点分别执行一轮。最多 24 个时间点，服务端拒绝重复时间并按升序保存。提交前不会启动采集。

新格式 `timing` 包含 `repeat`、`startDate`、`times: ["09:00", "14:30", "18:00"]`、`timezone: "Asia/Shanghai"`。旧的单时间字段 `time` 仍可读取和提交，自动按一个时间点处理。指定日期的计划在当天所有选定时间点触发后结束；创建时这些时间点均须晚于当前时间。

`/tasks` 展示真实持久化计划及全部选定时间点。可以暂停、恢复、关闭计划，展开本轮任务查看新增数、淘汰原因和处理进度。本轮任务也可使用现有的停止/核对后继续操作。指定日期的计划全部时点触发后不再产生下一轮，其本轮任务仍可查看和停止；关闭计划保留历史记录。上次触发同时展示实际启动时间与原计划时间，以区分排队后的延迟启动。

计划默认保存在 `.data/acquisition-schedules.sqlite`，以 15 秒间隔检查到期任务。后端服务运行时可关闭浏览器；电脑休眠或服务停止期间不会采集。每个时间点单独排队，启动后从原计划时间推进到下一个时点，不因启动延迟而跳过中间的时点。服务恢复后按原计划时间先后补执行，仍共享单活跃任务限制。暂停后恢复则从下一个未来时点开始，不补执行暂停期间的时点；指定日期的计划若已没有未来时点，需重新创建。

全部计划与手动任务共享单活跃任务限制。任务运行、待核对或 API 尚未配置时保持等待。暂停/关闭计划会关闭后续触发；本轮已开始时请求在当前企业处理结束后停止，未知写入结果仍须核对，不会强行取消或重发写入。

每次到期使用计划 ID 和原定触发时间构成固定幂等键，持久化创建的 BatchJobs。若在任务创建后、计划更新前中断，恢复时按该键找到原任务并关联，不重复创建。服务启动恢复待核对任务时沿用现有暂停规则，不自动重放企业写入。

接口：

- `GET /api/v1/acquisition/schedules`
- `POST /api/v1/acquisition/schedules`（包含 `name`、`input`、`timing`，要求 `Idempotency-Key`）
- `POST /api/v1/acquisition/schedules/:id/pause`
- `POST /api/v1/acquisition/schedules/:id/resume`
- `POST /api/v1/acquisition/schedules/:id/close`

本阶段为本机单进程调度，不应同时启动多个服务进程操作相同的任务数据库。
