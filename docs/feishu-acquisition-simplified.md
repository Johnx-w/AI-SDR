# 飞书获客表：用户确认的简化方向

2026-10-21。此方案替代此前“三表+多项主表字段”的草案。用户明确要求先调整T2，并将供货机会的信息纳入评级依据，评估历史作为T12。通用需求记录：[Issue #9](https://github.com/Johnx-w/AI-SDR/issues/9)。

## 两张表

| 表 | 用途 |
| --- | --- |
| T2 客户主表 | 一家企业一行；保留现有业务/联系字段，用户评级和评级依据展示当前判断 |
| T12 客户评估历史表 | 每次评估一行；关联客户，保留当时评级、评分、依据和规则版本 |

首期不单独建立飞书供货机会表。成品、材料配件、样本展示仍是业务判断的不同方向，在评级依据中分别说明；不能跨方向拼分。网页/服务端需要的结构化证据不强制展开成飞书许多列。

## 本次已执行的T2字段调整

| 操作 | 结果 |
| --- | --- |
| 删除主体类型 | 原值已随完整表备份；主体判断仍可作为内部研究事实，不再单列飞书字段 |
| 最近接触时间改名 | 最近研究时间，保留原字段ID与日期类型；原列全部为空，不将今天伪造为历史研究时间 |
| 客户类型改类型 | 从单选改为多行文本，原有类型值保留；不另加经营角色多选列 |
| 客户等级改名 | 用户评级，原字段保留A/B/C单选配置；没有虚构初始评级 |
| 新增开发状态 | 单选：待开发、跟进中、已回复、暂缓开发、已成交；存量值保持空白，不猜测真实跟进状态 |
| 新增评级依据 | 多行文本，将拟供方向、匹配理由、评分解释、来源和待核实事项汇总在一列 |

其余字段按现状保留，本次不执行旧草案中的相关产品/需求产品等改名，也不批量增设准备状态、评分完整性、海关数据状态、负责人等独立列。以后确有业务需要再调整。

## T12字段（表结构和自动评分同步链路已接入）

| 字段 | 类型 |
| --- | --- |
| 评估ID | 主字段，文本 |
| 客户 | 单向关联T2，一条评估对应一家企业 |
| 评估时间 | 日期时间 |
| 用户评级 | A/B/C单选 |
| 评分 | 数字；资料不足时不能随意填满 |
| 评级依据 | 多行文本，保存当轮事实、方向、缺项和解释 |
| 规则版本 | 文本 |

用户随后授权优先实施自动评分与历史，已接入[自动评分链路](automatic-assessment.md)。官网研究后的真实结果更新T2并在T12追加，禁止仅覆盖主表而丢失历史；未知留未知，不使用校准假设分。未对全部存量客户无依据批量赋分。

## 评级依据内容模板

```text
拟供方向/产品：……
本轮用户评级与已支持分数：……；缺失项：……
匹配理由：产品……；采购角色……；持续经营……；定制/电动等……
海关依据：观察窗口、相关数量/单位、独立进口票数及最近日期；未导入/未匹配等明确说明
证据来源：页面/导入批次与记录定位
待确认：实际外采方式、适配条件等
评估时间/规则版本：……
其他方向：分别说明，不混用证据
```

此为内容模板，未填入真实企业或当作已完成评分。海关15分和其他规则仍按已讨论业务口径实施，假设满分不写入真实评级。
