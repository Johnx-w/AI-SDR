# Node.js 获客迁移

2026-10-21：第一阶段将现有网页获客链路迁移到 Node.js。前端通过统一接口访问执行引擎，旧 n8n 接口保留为兼容路径。飞书仍是业务客户表；当前任务库仍使用 SQLite。

## 已迁移

- Tavily 搜索、候选官网筛选、已有域名排重。
- 公网 HTTPS 官网采集，最多五个同域页面；从完整 HTML 发现联系、关于和服务范围页。失败页面可由 Tavily 补充，补充范围仍限于计划内页面。
- DeepSeek Responses API、严格结构化研究请求，以及原文引证校验。
- 飞书应用认证、完整分页读取、字段类型检查、身份匹配、定向更新和写后读回。
- 已有批量任务的停止、继续、预算及进度持久化；新任务记录执行引擎，防止迁移后误恢复旧引擎任务。
- 操作日志保存在 acquisition_operations 表，包含研究证据、写入意图、记录 ID 与最终输出。凭证由服务端环境或本机连接配置提供，不回传密钥原值。

## 配置与预检

可以在“API 连接”页填写并保存，保存后立即生效；也可在本机 .env 或服务器环境中配置：

    ACQUISITION_PROVIDER=native
    TAVILY_API_KEY=填写现有 Key
    DEEPSEEK_API_KEY=填写现有 Key
    DEEPSEEK_MODEL=deepseek-flash
    FEISHU_APP_ID=填写原飞书自建应用 ID
    FEISHU_APP_SECRET=填写原应用 Secret
    FEISHU_APP_TOKEN=填写现有多维表格 app token
    FEISHU_TABLE_ID=填写原数据表 ID
    BATCH_DB_PATH=.data/acquisition.sqlite

运行 npm run preflight:native：核对配置、飞书表格可读性与 DeepSeek 模型，不调用搜索或写入。

npm run verify:native:live 使用真实 Tavily / DeepSeek 额度，以一个已有客户验证官网采集与研究；飞书写入被替换为内存模拟，网络层也禁止所有多维表格写请求。结果保存到 .data/native-verification.json，原记录应保持不变。

正式进程使用 server/index.mjs 为任务、操作日志、定时计划及连接配置提供持久化路径。直接使用 createApp 或 NativeAcquisition 时必须显式提供数据库路径；省略路径用于隔离测试的内存库。修改 .env 后需要重启 API 子进程；前端连接页的覆盖配置优先于 .env，无需重启。预检、只读验收及电话维护脚本也读取同一份覆盖配置。服务只绑定 127.0.0.1。

## 接口

统一路径为 /api/v1/acquisition，包含 status、locations、jobs、jobs/:id、jobs/:id/stop、jobs/:id/resume、runs、executions。搜索词由前端共享领域函数 `buildSearchQuery` 生成；已删除的 search-query 接口返回 404。旧 /api/v1/integrations/n8n 路径映射到同一选定引擎，不会根据请求路径绕过配置。

native 模式下 /api/v1/leads/real 直接读取飞书，无需 n8n 只读 Webhook。status 仅表示配置是否齐备，不伪造平台连接验证。executions 只返回操作编号、状态和时间，不返回密钥或完整证据。

## 写入与恢复

研究按最新简化方案核实经营主体、具体产品与证据。个人消费者不入库；本地供应安装商、零售商和自有工厂不再全局淘汰，按具体供货方向评价，生产方式/范围未知也不直接淘汰。C 端企业可正常通过。官网评分和后台最新评估见[实施说明](automatic-assessment.md)，不再依赖 T12 历史表。仅保留美国、澳大利亚、加拿大、英国和欧洲（不含英国）获客市场；旧任务恢复时重新校验。

仅采集字段可更新，负责人、开发状态、备注、客户等级及首次发现时间不会被复核覆盖。新增前重新读取身份；同域名多行、指定记录 ID 不匹配均停止写入。搜索已收录域名时直接跳过，显式指定 target_record_id 才允许复核原记录。

远端写入前持久化写入意图，新增请求附 UUID client_token；发生不确定结果不会自动重发写请求。若记录编号已返回而读回失败，重启后仅通过原编号核对字段。若写响应丢失且没有记录编号，维持暂停，不能仅凭相同域名出现就宣称该操作成功；需要人工核对，不能重新提交来掩盖不确定状态。

第一阶段按现有单实例、单活跃任务运行。不要同时启动多个指向同一数据库的工作进程；不要从 n8n 和 native 同时对同一范围执行获客。切换配置前先完成或核对所有未结束任务。

## 回退

将 ACQUISITION_PROVIDER 改回 n8n 并重启 API，原 Webhook 和只读入口配置继续生效。历史客户和任务不删除。旧任务没有 provider 字段时按 n8n 处理；暂停任务必须由创建它的引擎恢复，不会跨引擎自动执行。

若曾在连接页保存覆盖配置，回退时需同步修改 `.data/api-connections.json` 中的 `ACQUISITION_PROVIDER`，否则覆盖配置仍优先启用 native。

迁移前线上工作流快照保存在本机忽略目录 artifacts/native-migration-workflow-before.json；本轮未修改或停用线上 n8n 工作流。

## 后续阶段

## 低成本自动化（2026-10-24）

搜索计划、候选过滤、域名去重、联系方式提取、原文校验、评分运算与入库继续由 API 和确定性代码执行。企业主体、产品与采购语义等研究仍交给一个模型请求，不为每个字段另起 Agent，也不自动升级昂贵模型。

直连企业研究新增以下默认机制，无须在页面逐项配置：

- **精确请求复用**：每次仍重新读取官网；实际送入研究的正文及 URL、目标条件、提示词、Schema、模型、服务地址、协议和请求参数相同，才可复用已解析成功的模型响应。响应保存 7 天，每个飞书表格作用域最多 200 项；按旧项淘汰。模型或条件变化会重新请求，不按域名粗略复用。
- **重新核验而非重放**：缓存只有模型响应，没有旧准入结果、评级或飞书写操作。命中后仍用本轮正文执行当前引文核验、身份校验、准入、评分及写入读回；模型输出未完成、JSON 解析失败的响应不进入复用。注入适配器没有明确的非秘密请求身份时不复用。
- **正文硬闸**：研究正文至多 5 个有效 URL，每页 16,000 字符、合计 80,000 字符，保留头尾、去重并避免截断 Unicode 代理对。引文核验只使用实际传给模型的正文，完整 HTML 的联系方式等独立提取结果不被覆盖。这里是正文字符预算，不是模型总 token 限额；提示词和 Schema 仍有额外开销。
- **调用统计**：原生研究输出 `research_usage`，任务聚合为 `researchUsage`；记录模型请求尝试、结果复用、正文字符，以及供应商实际返回的输入/输出 token。缓存命中不重复累计旧 token，操作核对与恢复不重复累计。旧任务或外部引擎未返回统计时保持未知，不伪造零消耗。

这不改变既有初评分、未知事实和海关身份规则，不增加自动开发或发信权限。离线验收验证相同正文与条件的两次独立研究只请求一次模型，而两次都重新读取官网；该结果不是对真实任务总体节省比例的承诺。真实开支仍以检索/海关提供方和模型账单为准。

## 北美逐票发现与可替换提供方（2026-10-23）

当前已接入 `web`（官网发现）、`customs`（海关逐票）、`dual`（双通道）；旧计划中的 `tavily_web` 仍兼容，渠道名不决定实际检索供应商。前端新建任务默认官网发现，海关连接独立配置，未配置时不影响原有官网任务。

海关经营市场限定美国、加拿大，产品词包覆盖成品帘、窗饰面料、组件/叶片、plantation shutters（透气窗）、户外遮阳和窗饰样本册。选择“全部窗饰业务”时检索这六类，指定产品任务仅使用所选产品及其别名，不支持的产品不会静默扩大为全部业务。货物描述须通过对应品类过滤，普通图书、服装面料、电子屏幕等不因此成为窗饰买家线索。规格用于后续核实，不把所有尺寸强制 AND 到描述检索中。当前底层读取美国进口披露记录，不代表加拿大完整海关覆盖或其他国家已接入。

海关搜索先返回相关货运记录，归并收货方，再寻找并核实独立官网，复用原有原文引证、准入、官网域名去重、P40/R30/D20/V10 初步评分、飞书写入读回和后台最新评估保存。自有工厂不自动淘汰。已收录企业通过 `target_record_id` 更新原档案，保留人工跟进信息，不计新增。

同名不是已核实的进口主体：`name_only` 表示官网经营名称一致，但缺少地址等第二身份依据；`verified` 才表示主体名称及地址等依据吻合。名称冲突或官网经营国未知的海关候选进入待核实；名称一致、官网符合原有业务条件的企业可作为官网核实的潜在客户入库，但进口表现仍标关联待核实。披露市场和卸货港不能推断买家经营国。后续新产品记录复用已保存的官网身份事实，无需重复建档或重新调用模型。

客户库列表展示已有海关记录的数量与入口；客户详情“海关记录”按来源记录逐条列出记录日期、产品、进口数量，保留箱、卷等原始单位，缺数量或单位时明确标注未提供。记录条数与不同提单号数量分别显示；即使提单号、货描及数量相同，不同来源记录也分别占一行，同提单记录提示数量不累加，不据此推断实际进口次数。买方关联状态持续可见，提单、原始货描、服务商编号及来源可展开查看，没有关联记录时明确显示空态。进口记录不进入初评分，不变成企业公开采购需求；记录数、不同提单数均不等于采购订单数。不相加不同单位，也不将包装数量换算为产品件数。

### 连接配置

“API 连接”可分别配置三种提供方，密钥只保存在服务端，不回显。

| 可替换项           | 默认实现                                                          | 替换接口                                                                                                               |
| ------------------ | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 网页检索和正文提取 | `WEB_SEARCH_PROVIDER=tavily`，兼容 `TAVILY_API_KEY`               | `http`：`WEB_SEARCH_BASE_URL` + `/search`、`/extract`，`WEB_SEARCH_API_KEY`                                            |
| 研究模型           | `RESEARCH_MODEL_PROVIDER=deepseek`，兼容 `DEEPSEEK_API_KEY/MODEL` | `openai_compatible`：`RESEARCH_MODEL_BASE_URL` + `/chat/completions`、`RESEARCH_MODEL_API_KEY`、`RESEARCH_MODEL_MODEL` |
| 海关货运记录       | 显式选择 `CUSTOMS_PROVIDER=billofladingdata` + `CUSTOMS_API_KEY`  | `http`：`CUSTOMS_BASE_URL` 为完整标准化 POST 地址，按需配置 `CUSTOMS_API_KEY`                                          |

网页 HTTP 桥接返回 `{results:[{url,title,content?,raw_content?}],usage?}`；研究模型须支持 JSON Schema 结构化输出，之后仍走同一个原文审计。不是任何兼容聊天接口都自动满足该能力。海关 HTTP 桥接接收 `{family,products,hs_codes,source_markets,date_range,page_no,page_size,scope_version}`，返回 `{records,total?,has_more?}`；每条至少提供 `description` 和 `buyer.name`，建议同时提供稳定 `id`、`date`、`bill_of_lading_number` 和 `buyer:{id,name,address,country,role}`，完整字段参见 `server/customs-provider.mjs`。替换供应商只更改适配器或桥接，不改准入和评分规则。

BillOfLadingData 使用经公开文档核对的 shipping-records 接口；默认不调用 Top Importers 或收费公司详情。公开标准响应未保证买方 ID/地址，只有确认实际返回路径后才在服务端配置 `CUSTOMS_FIELD_MAP`，例如其 `buyer_id`/`buyer_address` 映射键。缺字段不猜测。当前启用美国披露记录源以发现北美候选，不代表加拿大的全部海关覆盖。

### 预算、持久化与验收

`customs_record_budget` 每轮 1–300，默认 300，单页不超过 50；所有词包共用预算。先公平读取各词包首批，再在预算内继续分页，随后由官网通道补找。初始基线最多 12 个月，未读完保留原窗口与页大小，后续轮次继续；基线完成后查最近 30 天。增量窗口不是实时监控，须由现有获客计划实际触发。

默认复用 `ACQUISITION_DB_PATH` / `BATCH_DB_PATH`，也可配置 `CUSTOMS_DB_PATH`。逐页缓存、计费预算、游标及同轮原始记录去重落在 `customs_*` 表；企业身份快照与分产品海关证据落在获客操作库。成功付费页在官网研究中断后可从缓存续跑；请求计费状态不明时保存预算并暂停，不自动重发。页大小固定，避免更改偏移导致漏票。相同记录跨产品查询可能仍由上游重复计费，因此预算按实际返回行计，去重不能取消上游已经发生的费用。

接入初期通过离线适配器合同测试、官网核实/飞书模拟读回、双通道预算与恢复测试及生产构建，后续真实执行记录见 [批量收录验证](batch-acquisition.md#验证)。2026-10-24 本次范围与客户库展示调整通过离线全量回归及生产构建；只读核对当前 16 家客户中 3 家带有共 4 条已保存记录，均为名称匹配、身份关联待核实。本次未启动新的获客任务或请求付费海关接口，新增词包的实际产出仍需后续任务验证。
