# 自动评分与T12评估历史：实施说明

本功能按用户确认的[简化T2/T12方案](feishu-acquisition-simplified.md)实现，当前规则版本为`acquisition-v3.0`。官网研究后进行百分制初评、当前摘要与历史同步；海关采购表现移到初评之后独立分析，其数据接入尚未实现。

## 自动处理链

1. 官网研究提取企业、实际产品和评分事实。每条评分事实带产品方向、原文引文和来源URL；网页文字和查询条件仅为数据。
2. 服务端核对引文来自本次实际读取的页面。拒绝拼接摘要、未取得的网页、无法识别的网点/案例等不合要求的证据。
3. 固定规则计算P40/R30/D20/V10，共100分。不同产品方向分别算，不拼分；企业选最高有效可开发方向。
4. 初评只包含上述四项，海关不加分、不影响完整性，也不作为初评缺项；四项内的未知仍保留未知，不按比例补满。
5. 研究结果与用户评级、最近研究时间写入T2并读回。评级依据列可选：存在时写完整摘要，现有表删去此列时以服务端快照和T12展示依据，不强制加回。已评估客户的评级不留空：证据充分时为A/B/C，资料不足或明确不开发时分别写待核实/待补全/暂不开发。
6. 评估快照在服务端持久化，按稳定评估ID追加T12，再读回关联客户、评级、分数、依据、时间及版本；确认后本轮才完成。

本轮同步移除旧“纯本地安装/零售即排除”“同类自有工厂即排除”“生产方式未知即排除”的全局条件，仍需核实经营主体及具体产品。工厂材料/配件和其他产品方向分别评价，真实未知不会自动评C。

## 评分事实与规则

研究模型只输出事实分类与原文，不输出分数。新增`assessment_opportunities`包含具体产品、方向及以下事实：产品主营/副线、供货角色、当前供货流程、定制、电动/明确工程规格、同主体持续经营时间、可识别网点/实际经销商/具体交付案例、主体冲突或强制要求。

事实提取使用DeepSeek Responses的非思考模式、温度0及16000输出上限，评分仍由程序计算。此前10000上限会被推理token消耗而截断JSON；官方说明该上限同时包含可见输出和推理token，`reasoning.effort=none`可关闭思考模式，见[DeepSeek接口文档](https://api-docs.deepseek.com/api/create-response/)。在调用前保存已读取页面，便于核对，不用截断文本伪造完整研究。

业务规则采用[评分v3](acquisition-scoring-v3.md)，A≥75、B≥60，配套门槛为P≥30、R≥25、D≥5。年份没有月日时，按最晚可能周年保守计算；个人/团队合计经验不当作企业经营年限。服务城市、规划门店和图片张数不当作经营规模。关键产品/角色/主体未知或事实相互冲突，或具体强制条件待核实时，不发布A/B。旧v2.1快照不改写，重新评估才生成新版本；网页标示旧版结果，历史展示各自版本。

评分结果保存各维度支持分、支持事实、未知项、产品方向、研究页面和规则版本；完整摘要、结构及引文留服务端，客户库可按当前客户读取最新快照，T2的评级依据列若保留则同步摘要。T12每轮新增，不覆盖旧评估事实。

T12的评级依据只展示业务事实、引文、来源和缺少的依据，不重复放评估编号、评估时间、规则版本、评级、总分或各项分值。编号、时间、版本、评级和分数保留在各自独立列。旧历史可以按已保存快照转换展示格式，核对其他列一致后只调整依据及原空评级的明确状态；原始评估快照不变。

对存量客户，官网采集/模型研究失败或来源仅为第三方平台时，保留现有企业及联系资料，只更新本轮待核实评级、研究限制与研究时间，并留T12历史。不会声称研究成功，也不把缺资料当C类或删除客户。

## 网页入口

客户库 → 企业详情 → **评分与历史**。

- 可以选择已支持的国家、填写具体产品，点击**研究并评级**，对存量客户重新读取官网并生成当轮评估。
- 查看已支持分数、四项初评分数/缺项、规则版本、评估时间及T12同步状态。旧版历史仍按其原五项展示。
- 展开每条历史查看当时的评级依据和来源。
- 异常时核对同一次评估，不直接换新操作号重跑付费研究；同一浏览器标签页刷新或关闭重开详情后保留未确认操作号。T12待同步可以单独核对。

现有手工评级不伪装自动评分；没有评估记录时展示未自动评级。

## 幂等、异常与恢复

- 研究操作号、客户表范围和规则版本产生稳定评估ID；同一操作重试复用结果。
- 本地SQLite评估快照和同步状态保存于持久化数据库，默认复用当前获客数据库，也可通过`ASSESSMENT_DB_PATH`单独配置。
- T12自动查找当前多维表格中唯一的T12表并核对7列及客户关联。可用服务端环境变量`FEISHU_ASSESSMENT_TABLE_ID`指定，不能指向T2。
- 每次追加前按评估ID查询；本地条件更新领取写入权，防止并发工作重复创建同ID。
- 写入已明确被飞书拒绝时可修正后重试；网络中断导致结果未知时，先查回历史，未确认前不再次创建。
- 同步失败保留完整快照和错误；后台定期核对，网页可见异常。T2成功、T12未确认时不声称整轮成功。
- 新企业只有一次主档写入；恢复过程中不重新调用搜索/研究。存量评级操作不冒充新增获客数。

飞书原始客户数据与本地快照不提交Git。云端部署时需同时持久化并备份评估数据库和原获客数据库。

## 接口

- `GET /api/v1/assessments/rules`：当前规则与支持市场。
- `POST /api/v1/leads/real/:recordId/assessments`：国家/具体产品，必须带`Idempotency-Key`；服务端重新研究和计算，不接受客户端分数或证据。
- `GET /api/v1/leads/real/:recordId/assessments`：该客户的服务端评估快照及T12同步状态。
- `POST /api/v1/leads/real/:recordId/assessments/:assessmentId/retry`：只核对/恢复T12同步，不重复研究。

以上复用现有本机接口来源限制及直连引擎。完整多人登录权限、云端部署和海关导入仍属于后续实施项，不以这次功能接通表示已经全部完成。
