# 飞书镜像同步当前业务结果与真实沟通

状态：有效；2026-11-10 对照客户镜像、沟通轮次、分析与业务同步代码核对。具体云端版本和同步结果以运行环境验收为准。

运行服务器 SQLite 是客户及业务事实的主库，飞书为协作镜像，不迁移数据库技术，不用本机测试库覆盖正式数据。T2 同步当前评级、依据摘要与由真实往来推导的开发进度、最近联系和回复时间；自动回复和退信不推进正常回复状态。

配置领导原业务表编号时，T3 按一轮发送及其回复一行，完整正文、回复时间与真实回复类型保留；新发信另起一轮。优先按回复头关联，缺少头部的历史消息才按同一客户、会话、渠道、账号内最近发信关联。数据库仍逐封保留原文，飞书映射持久化，冲突待核对；未配置原表编号的通用镜像仍逐条同步。

T3 的客户信息和需求摘要从客户本次原文及签名提取并核验引文；拒绝态度可写摘要，但不作为采购需求。具体采购或产品咨询由独立提取链路自动生成 T1；T4 只同步系统追信，规则见 [ADR-0025](0025-automatic-business-records-with-read-only-followups.md)。摘要不能覆盖原始邮件。

后台约每分钟核对待同步事项，稳定编号及读回避免重复，失败保留本地事实并重试；补记录不重发。正式 Base 使用运行环境的有效配置及真实表 ID，见 [飞书填写规范](../new-feishu-bitable-filling-spec.md)。领导原 T5 已恢复原始字段，当前代码明确停止网页产品资料向该表镜像；通用 T5 则核对版本和读回，不用旧资料覆盖较高版本。

已撤销企业暂缓功能，不再提供原因、复查或恢复；计划暂停、勿联系和首封去重仍有效。明确不匹配的新企业不入库，既有真实档案及往来保留、日常视图过滤，镜像初评清空；不把不匹配冒充 C，也不新增归档表或恢复流程。

这种单向镜像保持业务证据和执行状态一致，同时保留历史。完整现行规则见 [客户与产品数据](../customer-data.md)。
