# 业务表保留企业、需求与沟通关系，系统配置由网页管理

2026-10-24 用户确认将原十二表方案收敛为五张核心业务表和一张可选模板表，先实施 T2 企业档案与 T5 产品资料库。T1 记录客户明确表达的采购或咨询需求，T3 记录实际沟通，T4 记录具体下一步行动；企业、会话、消息与品类需求分别关联，多个品类需求共享统一对外会话和固定邮箱。

关键词、获客计划及执行、销售人员和渠道账号、触达规则、区域搜索策略在网页后台管理，避免业务表、规则表与运行状态分别成为相互冲突的来源。T10 在业务人员需要单独维护模板时保留。T12 和独立评分历史取消，后台只维护客户最新完整评估与当前规则版本，真实沟通与执行留痕仍保留。

T2 本期原位改名五个字段：用户评级改为初评结果，相关产品改为企业经营产品，主营产品偏好改为主营产品概况，需求产品改为公开采购需求，服务客群改为企业服务客群；补充企业官网、主要供货机会、待确认事项。企业官网用于身份、研究和去重，来源链接保留原始发现出处。供货机会只表示潜在关联，不能填入客户未表达的采购需求；新研究继续保留人工开发状态、既有联系资料和真实跟进记录。

T5 的公司产品资料与获客搜索产品词汇分别维护。网页是资料录入、审核和归档入口，本地数据库保存当前资料，飞书同步当前业务内容并核对读回；直接修改飞书镜像不作为另一套资料来源。产品名称出现在获客词库或某个网站中，不代表公司已确认供应。未知参数、MOQ、交期、品牌与市场保持空白，审核需要明确依据和审核人，已审核内容实质改变后重新审核。资料审核不替代具体商务承诺、附件外发或真实触达授权。

采用分阶段迁移，是为了让旧服务在重启前继续读取原字段：先备份并添加三列、建立 T5，待新服务的业务结构版本和最新评估存储标识均核验通过后，再原位改名并删除 T12。迁移保留原字段编号、类型、选项、记录编号和原有字段值；异常外部写入先核对，避免重复建表或重放不确定写入。
