# 真实沟通作为需求依据，任务按执行方式和需求范围核对

2026-10-28 整理：当前产品行为与实现状态见 [现行主题说明](../customer-data.md)；以下保留决策形成过程及当时范围。

2026-10-24 用户确认实施 T1、T3、T4 及其与 T2、T5 的联动，延续 ADR-0003、0005、0006、0007 和 0009。

沟通记录保存已经发生的事实，新增记录必须明确确认实际发生；原文、参与方、渠道、时间和实际收发结果不被后续编辑覆盖，只允许补充需求关联和备注。T1 的需求必须由同一企业、同一会话下实际收到的消息或确认的电话纪要支持，并保留连续原文摘录；官网画像、初评分、供货机会和我方已发邮件不能代替客户需求。每条来信可以支持多个需求，多需求仍共享企业档案、会话和固定对外邮箱。

首次真实邮件收发绑定企业的固定邮箱，后续品类需求沿用该邮箱。空会话或发送失败、结果未知不能冒充已开启的真实邮件沟通。现有两个公司地址的邮箱连接试点继续独立，其测试线程不自动导入业务记录或生成采购需求。

T4 区分人工执行和系统计划，默认由业务员人工执行。人工接管暂停所涉系统计划，同时保留真人自己的行动安排；客户新回复、明确拒绝联系、硬退信、关闭需求或会话以及发送结果未知仍按适用范围核对。单项需求的接管与拒绝不自动作用于独立需求；未明确限制到某需求的拒绝联系按企业范围抑制。暂停后的任务需要明确核对与恢复，不自动补发积压行动。

跟进任务引用当前 T5 资料版本以及关联需求引用的版本。执行前重新核对资料是否已审核、已生效及版本是否一致；修改后的资料需要重新核对，不能将旧依据套用到新声明。已经实际发生的对外沟通仍如实登记，历史执行结果的登记不代替新的发送许可或商务承诺审核。

首次联系、补问规格及报价跟进的任务完成，必须关联同一企业、会话、渠道并覆盖所涉需求的实际已发送消息；草稿、失败或结果未知不能证明完成。样品、人工审核及其他内部行动以明确执行说明留痕，完成这类任务不代表报价、附件外发或后续自动触达已获批准。

网页维护业务记录，本地持久化完整会话与记录图，飞书三张表同步当前业务内容及真实关联字段。先建立稳定编号的业务记录，再核对循环关联，全部读回后才报告同步成功；远端异常不丢失本地已保存事实，未知写入先核对而不盲目重放。T2 和 T5 保留其业务含义与原有数据，网页提供从企业、产品资料反查需求和任务的入口。
