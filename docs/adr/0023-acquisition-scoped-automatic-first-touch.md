# 按获客计划开启自动首封开发

状态：有效；2026-11-12 实现无可用商务邮箱跳过本次首发，替换该类客户补齐后原安排自动恢复的规则。GitHub、云端版本与历史数据处理须按发布验收核验。

每个获客计划分别开启“获客后自动首发”，开启后为后续每轮新增或重新发现并更新、尚未首发且符合发送条件的企业自动生成并发送首次开发信，无需逐轮手动创建和启动触达计划；现有计划不自动开启，历史客户库不因开启而被整体纳入。首封未回复追信已有独立开关，默认关闭，见 [ADR-0025](0025-automatic-business-records-with-read-only-followups.md)；来信自动接待仍待正式接入。

选择将自动首发范围绑定到具体获客计划的产出，而不是沿用面向全库的持续触达范围，是为了让负责人能明确控制哪些获客安排会产生对外联系，同时避免反复创建开发任务；获客计划与触达计划仍是不同的业务概念，自动衔接沿用现有首封发送条件和企业去重规则。

每家客户新增入库或更新保存成功后立即进入首发队列，不等待整轮获客结束，以便已具备条件的客户及时开始联系；进入队列不等于已发送，实际发送仍遵守邮箱的每日额度、发送间隔及发送前检查。

首发依据客户实际经营证据，从已审核产品和负责对应产品的可用邮箱中自动选择最匹配的组合，不受本轮获客搜索产品限制；选择依据是产品匹配事实，不将匹配强弱表述为成交概率，同一企业仍只安排一封首次开发信。

产品与邮箱范围不锁定在首次开启时。每轮获客开始时，自动首发安排读取最新的已审核产品和可用邮箱，将新增且符合条件的产品、邮箱纳入后续匹配，无需重新开启或逐轮批准；尚未生成邮件的待处理客户也可在安排有效时使用更新后的范围重新检查，已经准备的邮件不因单纯新增产品或邮箱而自动更换内容与身份，发送前仍检查原产品资料与邮箱是否有效。

本流程的开启包含对上述持续更新范围的自动发信授权，更新 [ADR-0017](0017-automatic-sending-with-confirmed-information.md) 中扩大产品或发件范围须重新确认计划的规则在本流程中的适用方式；原有手动触达计划不自动取得这项持续授权，产品资料审核、邮箱连接验证、启用状态及品牌覆盖要求继续适用。

符合发送条件的客户先行发送；客户无格式有效且适合商务联系的收件邮箱时，记录“已跳过”及原因，结束该客户本次首发，不生成邮件或人工待办，不标记勿联系。发件邮箱配置、匹配依据等其他缺项保留现有待处理规则，不增加自动补全流程。

已跳过是该客户在本次安排中的终态。补齐收件邮箱、同轮更新、恢复或编辑原计划、重启服务均不恢复旧尝试；后续开启自动首发的获客轮次再次更新并保存该客户，或新建包含该客户的手动触达计划，可按最新资料重新评估，仍遵守企业去重、实际往来与勿联系检查。选择结束缺邮箱尝试，是为了避免没有处理责任人和补全流程的记录持续堆成待办；代价是补齐邮箱后需要新任务才能发信。

其他待处理客户的必要资料补齐后，只要原自动首发安排仍有效，就重新检查并在符合条件时自动入队。已跳过保留历史但不进入默认发送列表及需处理数量；计划详情显示跳过结果。历史无邮箱空记录通过一次性离线整理转为已跳过，不保留旧规则兼容分支；步骤见[邮件沟通](../outreach-first-touch.md#历史无邮箱积压的一次性整理)。

负责人暂停或关闭获客计划时，同时停止该计划来源、尚未提交发送的首封邮件；已经提交的邮件不能保证撤回，保留其实际结果。

恢复暂停计划时，依据最新客户状态和有效资料重新检查此前未发且未跳过的客户，再继续符合条件的首发；已经联系、收到回复或被标记勿联系的客户不再首发。

“立即获客”的单次执行也提供相同的自动首发开关，开启后沿用上述逐家衔接和发送规则。

立即获客的执行详情还可永久取消本轮自动首发：停止未提交首封和剩余追信、保留实际已发记录，取消后不能恢复。暂停仍是可恢复的独立控制；具体操作见 [获客](../acquisition.md#获客后自动首发)。
