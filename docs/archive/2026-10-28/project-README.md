## 启动

要求 Node.js 24.5+，客户读取副本与批量任务使用内置 SQLite 持久化；公开官网读取支持环境变量 `WEBSITE_HTTPS_PROXY`，Windows 默认使用已启用的系统代理，详见[官网信息补全](website-enrichment.md)。

```powershell
cd D:\CodeX\ai获客
npm install
npm run dev
```

网页：<http://127.0.0.1:5174>，API 服务：<http://127.0.0.1:4311>。

```powershell
npm test
npm run build
npm start
```

生产构建本地预览使用 <http://127.0.0.1:4311>。开发进程会监听文件修改。

`npm run build` 只更新前端产物，`npm start` 不会自动重载已运行的后端。修改后端代码后，需要在任务空闲时重启原服务，再在原端口核验关键接口；否则可能出现新版页面请求旧后端而返回 404。日常开发使用 `npm run dev`，前后端均监听文件变化。正式发布应使用同一版本的前后端产物，替换后端进程并通过关键接口检查后再开放流量。

自动获客支持每次新增 1–200 家，默认 20 家，后台逐家处理并自动补找。任务可选择多个产品和多个客户类型；补充要求作为优先偏好，必需条件有反证时排除、未知时列为待核实。进度、停止、继续、实际搜索词产出及任务历史保存在本机，详见 [批量收录说明](batch-acquisition.md)。当前只沉淀关键词效果数据，自动升降权与淘汰仍属于后续阶段。

## 工作台界面

界面采用冷灰白底色、蓝灰导航与靛蓝主操作，使用 React / TypeScript / Vite 与独立 Node API。各业务页面读取真实服务端记录。

- 运营总览：真实待处理事项、四项业务指标、优先处理客户、获客执行与计划、新增趋势及当前需求阶段分布。
- 客户库：真实客户的市场、评级、产品、状态、来源与匹配筛选，以及搜索、分页、CSV 导出与详情。
- 真实获客：客户列表优先读取本机 SQLite 副本，后台同步飞书；列表摘要与完整档案分开加载。查看画像、匹配结论、官网事实、联系方式和原始字段；没有评分的客户显示“未评分”，不将任务目标国家当作实际所在地。
- 联系方式补全：详情页域名与来源页可直接点击；在“联系方式”中自动核实当前官网页、首页及已发现的站内联系页，支持手动重新读取。电话、邮箱均附来源和原文证据，本次补全不自动写回飞书。电话链接使用已规范化的国际号码。
- 统一浅色主题：全站通过 `src/theme.css` 管理颜色，导航、表格、表单、弹窗与详情面板使用同一套浅色层级；成功、警告与错误保留语义色。左上角使用四条窗饰线条与 ShadeFlow 标识。真实客户列表和详情优先读取官网页头、响应式高清源和官方结构化数据中的 Logo，失败时使用网站图标，再降级到文字缩写。品牌图片独立异步读取并保存到 `.data/branding`（可用 `BRANDING_CACHE_PATH` 调整），Logo 缓存七天且重启后保留；过期先显示旧图再后台更新，仅取得图标或获取失败时半小时后重试。浏览器复用五分钟会话缓存，白色透明 Logo 自动使用深色底，低清图标不放大。
- 获客任务：真实任务统一在“新建任务 / 定时计划 / 执行记录”中管理。产品按成品、材料配件、样本展示分组，可搜索或为本次任务添加新产品；勾选后可保存为常用产品。搜索词由系统生成，执行记录展示实际查询、去重、研究、待核实、新增及评级产出。
- 沟通中心：多邮箱管理、邮件会话、首封触达计划和发送记录。支持手动同步最近 30 天邮件及后续增量、原格式与纯文本阅读、搜索和本地未读筛选；会话内人工回复支持富文本、签名、附件及服务器草稿。内嵌图片正常显示，外链图片按封加载。首封按官网产品覆盖分配邮箱并单独准备、审核、启动；保留企业去重、版本核验及未知结果暂停。详见[沟通中心](outreach-first-touch.md)。
- 产品与资料：维护、审核版本化产品资料及业务适用范围。
- API 连接：维护实际获客引擎及检索、研究、飞书和海关等连接配置。

旧演示收件箱、触达计划、报表、演示数据仓储与未启用 HTTP 仓储已移除。旧 `/campaigns`、`/reports` 地址保留跳转到当前真实功能；不再加载 `shadeflow:workspace:v3`。

客户读取副本默认保存在 `.data/lead-library.sqlite`，可用 `LEAD_LIBRARY_DB_PATH` 指定位置。首次读取需完整同步飞书；已有副本时立即返回本地数据。客户库可见时每 60 秒检查更新，页面隐藏时暂停自动轮询、重新可见时立即检查；后台在 2 分钟未收到客户库活跃信号后将同步间隔降低到 5 分钟。主动刷新与获客核验仍立即同步，不受空闲间隔限制。网页显示最近同步时间与同步失败提示，刷新和同步失败均保留已有客户。

同步只在完整读取并验证全部分页后，以事务新增、修改或删除实际变化的客户，不再全表重写。内容未变化时只更新时间与同步指标，保留数据版本；每位客户的内容版本独立，其他客户更新不使其详情缓存过期。已确认的联系方式与补充资料同步更新本地副本，且不会被保存前开始的同步覆盖。飞书保留现有写入与读回核验流程，切换飞书客户表或读取入口时使用独立副本范围。数据库文件与其他 `.data/` 业务文件一起备份。

客户接口：`GET /api/v1/leads/real/list` 返回轻量摘要，`GET /api/v1/leads/real/:id` 返回单个完整档案，`POST /api/v1/leads/real/refresh` 主动等待一次飞书同步。兼容接口 `GET /api/v1/leads/real` 返回本地完整快照，用于按需 CSV 导出；它不再强制每次访问飞书。获客任务的去重和写入核验仍强制读取最新飞书记录，不能使用过期副本作成功凭据。列表接口返回 `syncedAt`、`scope` 和 `sync` 状态，客户端按副本版本更新详情缓存。当前摘要仍整体加载并在网页筛选、分页，完整证据只按详情或导出请求读取。

客户库“同步详情”展示同步次数、成功/失败数、最近同步耗时与新增/更新/删除/未变化数量。开发核验可读取 `GET /api/v1/leads/real/metrics`：同步指标按客户表持久保存，接口性能指标按当前服务进程及连接范围记录列表、详情、导出、主动刷新的累计请求数、错误数、平均耗时、最大耗时和最近 200 次请求的 P95。指标只包含计数、时间与响应大小，不记录客户名称、联系方式、凭证或错误正文；读取指标不会触发飞书同步。上述四类接口同时提供 `Server-Timing` 响应头，耗时涵盖后端读取和 JSON 序列化，不包含浏览器下载及渲染时间。模拟增长数据可运行 `node scripts/benchmark-lead-library.mjs`，结果明确标注模拟档案大小与本机测量条件。

## 数据边界

运营总览、获客任务、客户库和客户业务读取真实服务端数据。沟通中心的邮箱、会话、计划及发送记录来自本机服务与 SQLite，授权码加密存储。收件由手动只读同步触发，人工回复由用户逐封点击发送；明确匹配客户的往来进入沟通记录，不自动回信、生成采购需求或改变接待归属。人工回复不受开发日额度限制，仍尊重邮箱暂停及连接状态。内部技术测试、客户业务事实与正式开发授权分别保存。

真实 n8n 工作流：<https://vynox.app.n8n.cloud/workflow/EycE9OmaPkRFUDSq>。

2026-10-19 已修复原入库节点仅匹配澳洲电话导致美国号码漏采的问题。`构建飞书记录` 节点与本地官网补全使用同一提取函数，支持美、澳、英、阿联酋号码及国际格式、电话/邮件链接、JSON-LD 联系字段与公开邮件保护编码，并规范去重。搜索、画像、身份键、写入分流与既有飞书记录保持原逻辑；没有为此重新执行付费搜索或批量写回历史客户。

飞书只读工作流：<https://vynox.app.n8n.cloud/workflow/n5emHnlFL4iTQSNW>。该流程独立于原获客链路，复用现有 Header Auth 与飞书自建应用凭证，仅获取 token 并读取客户记录；不会触发 Tavily、Dify、写入或发送。服务端通过 `FEISHU_READ_WEBHOOK_URL` 配置入口，复用 `.env` 的 `N8N_WEBHOOK_SECRET`。不把密钥、token 或 Webhook 认证头交给前端。

2026-10-19 已验证只读接口返回 7 条飞书真实客户；数量会随飞书数据变化。详情中的匹配结论、事实和研究时间来自原始记录；公开联系方式未验证投递。

Codex MCP OAuth 是开发工具的授权，不自动提供给本网页。网页使用独立服务端 Webhook 凭证。**没有配置 Webhook 时，界面会明确显示“等待接入”，禁用真实运行；不会退回 mock 成功。** 真实运行会沿原 n8n 逻辑调用 Tavily、Dify 并写入飞书。此版本不提供 iframe 编辑器。


## 当前限制

应用仍是本机单用户开发版本，服务仅绑定 `127.0.0.1`，没有团队身份认证。批量任务、定时计划、产品目录和客户最新评估已使用 SQLite 持久化；邮件会话与触达记录保存在同一触达 SQLite，沟通中心可直接访问，所有 `/api/v1/outreach/*` 请求保留本机来源校验。旧固定双邮箱后台及接口已退役，原数据文件保留。旧版单次 n8n 运行的进程内核对记录仍不会跨重启保留。上线公网前仍需补充服务端登录、角色权限、正式数据库备份和运行审计。不得把 `.env`、邮箱客户端安全密码、平台密钥或用户凭证放进前端、Git 或公开部署包。
