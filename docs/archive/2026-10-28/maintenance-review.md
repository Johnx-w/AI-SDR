## 保留的边界与后续建议

- n8n 与 native 都仍在支持范围内，保留兼容路径和工作流维护脚本。生成到 n8n 沙箱中的自包含函数属于部署需要；不把这些代码直接改为 Node.js 导入，也不将独立业务规则全部合并为一个大模块。
- `Workbench.tsx`、`Business.tsx` 承载多页演示功能。代码较长，但本次没有仅为缩短文件而拆组件；后续接入真实沟通、触达或资料后端时，按业务资源拆分状态和页面更有价值。
- 三份 CSS 存在历史叠加和覆盖，当前按固定顺序加载。删除样式需要先建立页面与不同屏宽的视觉回归基线，不能凭文本重复就判定规则无效。本次不改布局样式。
- 历史工作流生成脚本依赖指定快照的节点名称，`build-enrichment-artifacts.mjs` 还写死了目标表地址。这些脚本没有在应用运行链路执行；后续再次维护该工作流时应先改为环境配置并验证生成产物，避免复制到其他环境后仍指向旧表。
- 演示 workspace 与真实飞书客户采用不同数据契约。保留仓储接口，后续真实业务后端按资源接入；避免将演示整库保存接口直接当作生产架构。
- n8n 旧单次幂等记录仍存在进程内，native 操作与批量任务仍保留原 SQLite 持久化方式。这次只整理代码边界，不改变恢复和写入策略。
