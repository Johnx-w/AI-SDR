# 自动评分与最新评估：实施说明

> 历史归档：保留原日期与当时结论，不作为当前实施步骤。现行说明见 [文档导航](../../README.md)。

2026-10-24 用户确认取消飞书 T12 和独立评估历史功能。T2 保留客户当前评级，后台每家企业只维护一份最新评估，网页直接显示该评估的分数、方向、证据和缺项。规则版本为 `acquisition-v3.2`。海关发现已接入，贸易证据独立展示，不参与初评加分。

本机已在用户手动重启后完成收尾：T12 实表已删除，T2 评级列已原位改名为「初评结果」，16 家客户及 15 份最新评估核验完整。T2/T5 字段与资料维护见[T2/T5 实施说明](t2-t5-setup.md)。

## 自动处理链

1. 官网研究提取企业、实际产品与带原文、来源 URL 的评分事实。
2. 服务端核对来源、连续引文及具体产品方向；查询条件不成为企业事实。
3. 程序按 P40/R30/D20/V10 计算，不同方向不拼分；企业展示最佳有效方向。
4. 企业、当前评级和最近研究时间写入 T2，并按记录 ID、域名和实际写入字段读回。
5. 已核对的评估保存在本地持久库；同一企业的新评估原子替换旧快照。该步骤不查询或写入 T12。
6. 客户写入与最新评估均核对后才完成操作。保存失败沿用原操作恢复，不重复搜索、调用模型或新增企业。

## 当前评分口径

产品与角色达到 P≥30、R≥25 时，已支持总分 A≥75、B≥60，其余为 C。已经核实的相关经营企业可以在角色或其他评分资料不足时保留保守 C 初评级；D 未知不单独阻止 A/B。未知事实不补分，主体冲突、明确不匹配仍分别处理。

A/B/C 只表示初始开发优先级，不能解释为采购意向、成交概率、资料齐备或已完成联系。成品经营支持的材料潜在关联继续标注采购方式待沟通，不冒充材料采购事实。现行程序规则见 `server/customer-assessment.mjs`，旧评分文档仅供决策沿革参考。

最新快照保留：产品与供货方向、已支持分数、分项、事实与引文、来源 URL、缺项、研究限制、评估时间和规则版本。T2 的评级依据列可选，没有该列时网页仍可读取后台依据。

## 网页与接口

客户库 → 企业详情 → **最新评估**，显示当前规则的评估结果及依据。页面不再提供评估历史列表或 T12 同步核对按钮；没有自动评估的客户保留明确空态，人工主表评级不伪装为自动结果。

- `GET /api/v1/assessments/rules`：返回当前规则及 `assessmentStorage: latest_only`。
- `GET /api/v1/leads/real/:recordId/assessments`：返回 `assessment`；兼容的 `assessments` 数组最多一条。
- `POST /api/v1/leads/real/:recordId/assessments`：沿用已有受控研究入口及幂等要求，不接受客户端分数。
- 旧 `.../:assessmentId/retry` 返回 410，评估历史同步已停用。获客操作的异常通过原任务恢复入口核对。

## 人工补充资料

客户画像的待确认事项、最新评估的评分缺项均可进入「补充资料」。保存确认内容、对应产品和供货方向、依据、可选来源链接、确认人及服务端确认时间；网页统一显示北京时间，确认历史默认折叠。

评分资料选择事实类型，服务端沿用 P/R/D/V 规则重算，不接受手填分数。事实仅用于同一产品和方向；原官网的相反事实仍保留为冲突，普通备注不能清除评分缺项。经营法人名称更新档案并标记人工确认；采购需求须引用同客户实际正常来信或已确认电话纪要，不写成官网公开采购需求，也不自动创建 T1 业务需求。

- `POST /api/v1/leads/real/:recordId/supplements`：携带当前评估编号和 `Idempotency-Key`，保存确认资料并更新档案、当前评级及已补齐的缺项，不重新抓取官网或调用研究模型。
- `GET /api/v1/leads/real/:recordId/supplements`：恢复尚未核对完成的保存内容和原保存编号；重试先读回核对，避免重复写入和计分。

人工确认历史独立保存在获客 SQLite 的 `lead_supplements` 表，按客户表、客户记录和官网域名隔离；不随最新评估替换而删除。来源标为人工确认，不混入「官网证据」。重新研究同一产品时继续应用人工事实；官网读取失败时保留此前依据和人工确认，显示研究限制，官网取证时间不被失败尝试覆盖。

## 持久化与迁移

沿用 `ASSESSMENT_DB_PATH` / 获客 SQLite 数据库，每个客户表范围和企业只保留最新快照。新快照与旧快照替换在同一事务内；同操作重放不追加，较旧操作恢复不会覆盖较新评估。不同客户表范围隔离。

T12 取消前备份飞书字段、记录及一致性 SQLite 副本，确认最新评估已在后台保存，客户数量及 T2 字段值不变，停止旧同步链路后再删除 T12。现有运行恢复日志和私有备份用于排查，不作为客户评分历史展示或参与当前评级。

本次取消评估历史不改变搜索范围、评分权重、企业准入、客户开发状态或真实触达权限；其他业务表的设计仍单独确认。
