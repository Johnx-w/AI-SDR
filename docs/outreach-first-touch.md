# 邮件沟通

当前口径：2026-10-29。沟通中心统一管理邮箱、首封触达计划、邮件会话和发送记录。已实现手动只读收件及人工回复；[AI 业务员与自动接待](ai-sales-agent-design.md) 属于待实现设计。合并前的专业首封步骤及技术验收见 [归档](archive/2026-10-28/outreach-first-touch.md)。

## 邮箱与身份

在沟通中心录入实际公司邮箱、客户端授权码、显示名称、品牌、产品覆盖与签名，验证连接后启用。当前直接适配阿里邮箱的加密 SMTP／IMAP；其他服务商需要相应适配。

发件地址和固定签名由程序取自账号配置，模型不能更换身份。签名支持姓名、结束语、公司、地址、官网及 Logo；Logo 为 PNG／JPG、最多 256 KB、尺寸不超过 4096 像素，显示宽度 80–320 像素。已有人工草稿保留原内容，不因改签名静默替换。

首封先按客户经营证据匹配具体产品，再按已审核品牌覆盖选邮箱，最后在适用账号内按可用额度和间隔安排。发送间隔最低 5 秒，各邮箱独立计时；每日额度和草稿生成时间仍会影响实际速度。现有三个品牌的准确产品方向统一维护在 [邮箱路由](../agents/export-sales/mailbox-routing.md)，本页不再复制品牌表。官网暂不可读不撤销有效业务批准，宽泛品类或空闲额度不扩大覆盖。

客户已有实际往来后沿用固定邮箱；跨品类可取得共享目录及专业支持，同一会话统一回复，不因换品类或人工接管另换邮箱。归属冲突先核对。

## 首封开发

新计划采用简化流程：选择客户范围、产品、邮箱和目标数量 → 启动计划 → 普通 LLM 依据客户证据与已确认产品信息生成 → 系统核验、入队、发送。无需预填介绍、准备样稿或逐封审核；启动是对当前范围与数量的授权。旧专业模式计划继续遵守其原生成与批准方式，不自动迁移历史记录。

程序固定首行 `Hi {客户公司名} team,`，LLM 生成其后正文，程序附账号签名；不从邮箱前缀、公司故事或主观推测补人名。已发送原文保留。

简化流程的首次开发信使用独立的[写作提示词](../agents/first-touch-writer/system.md)：正文 55–85 个英文单词，正式、自然、简洁，先写有来源的客户产品观察，再介绍对应发件品牌、已确认的供货产品和联系目的，最后问是否愿意了解简短产品介绍。标题突出相关产品和供货目的。产品仍由程序按计划范围和客户证据匹配，写作模块不选择客户或更换发件身份。

三段各自承担不同作用：客户观察、品牌及供货介绍、一个容易回复的问题。通用收件箱可询问简短介绍对采购负责人是否有用，不假设收件人本人负责采购；不增加第二个请求或未经确认的能力承诺。品牌和合作目的各介绍一次。

客户观察聚焦匹配产品，不机械罗列客户目录；已获准供货和制造事实不等于“专注某产品”等自我定位。生成器拦截无依据的专注或专业化声明。

2026-10-28 负责人确认自有工厂，2026-10-29 提供的开发信样例确认三个品牌可在各自范围内表述从中国供货，依据保存在[已确认供货事实](../agents/first-touch-writer/confirmed-supply.json)。只有产品品牌、名称、采购形态及发件品牌、官网、邮箱域名均对应时，写作模块才能使用这些地域、制造商和细分产品事实；其他情况只作已有产品的一般供货介绍。客户证据和供货事实均支持时才采用细分产品切入点，工厂身份不扩展为具体规格或商务承诺。事实及提示词纳入资料版本，变更后沿用发送前复核机制。

程序依据最强匹配证据确定一个双方共同支持的细分切入点，不能确定唯一细分时保留所选大类，另提供最多两条与所选产品匹配的客户事实作背景。程序检查输出格式、来源编号、三段排版、字数、单一结尾问题及部分未确认声明；55–85 词是写作目标，程序容忍上下各 5 词的偏差，避免仅少一词就拦截合格内容。仅排版或写作格式不合格时自动修订一次，再次不合格仍阻止生成；事实、来源或商务声明检查失败直接阻止。来源编号有效不等于每句含义都已自动验证。提示词变更先用少量真实客户资料生成样例验收，将反馈明确写入适用规则，不将个别客户的改动无条件套用到所有客户，也不增加日常逐封审核。

首封开发信由撰写 Agent 生成，通过上述程序检查后进入发送队列。2026-10-29 移除独立审核 Agent 及其模型调用；写作格式不合格时仍由撰写 Agent 修订一次，事实、来源与发送权限检查继续由程序执行。

进入发送须满足：

- 企业尚未触达、没有进行中的客户会话或人工接管；直接使用客户库当前记录中格式有效的商业邮箱，不再要求附带官网来源证明。已有来源保留，明确无效或隐私、退订、招聘等专用地址仍排除。
- 产品、采购形态、市场及品牌覆盖适用，连接和签名有效，账号未暂停。
- 当前计划已启动并在授权范围内，客户未退订、勿联系或暂缓，企业首封去重通过。
- 账号发送限额与最小间隔满足，发送前再次核对客户状态、资料及配置版本。

同一企业跨联系人、账号、品类和计划只安排一封首信。首次实际发送后保留账号归属。计划持续加入符合条件的新客户，达到目标或取消后停止；无适用账号时等待，不跨品牌补量。

资料完备按本封需要判断，只有已确认产品事实时即可发送基础介绍；省略无依据的价格、库存、认证等。适用且获授权的标准商务内容可按完整条件使用，条件报价不能冒充客户最终报价，缺少尺寸、数量等计算条件时先问缺项。

资料实质变更后旧审核失效，相关未发邮件暂停。新版本批准且仍在原授权范围内时重新生成、核对并继续；扩大产品／市场或改变品牌须重新授权，已发送原文不修改。基础首封不自动添加产品或技术附件，账号签名 Logo 可内嵌。

「取消计划」停止新增准备及未提交发送，保留记录，取消后不恢复；重新开发需新计划并继续通过企业去重。已提交邮件不能保证撤回，保留实际结果。明确失败和结果未知均占用本轮尝试名额，不为凑目标盲目重试。

## 连接测试与真实授权

公司邮箱试发仅在明确的自有地址之间发送带唯一标记的固定非营销测试内容，幂等提交。SMTP 接受和实际收件核对分别记录，测试不写成真实客户开发事实，也不扩大正式计划或自动回信权限。

邮箱连通、资料审核、首封计划启动、自动回信接待和主动追信分别核对。旧专业模式的历史测试批准流程不应成为新简化模式的额外样稿审批步骤。

## 阅读与人工回复

打开邮件会话只读本机缓存；点击「同步邮件」才用加密凭证连接只读 IMAP，邮箱暂停发送不影响读取。首次同步最近 30 天收件箱及可识别已发件箱，每文件夹每次最多 50 封，有剩余时继续同步；增量按账号、文件夹和 UIDVALIDITY 保存游标，失败保留原文与进度。

同邮箱按标准消息编号及回复引用归并，会话不按相同主题随意合并；不同账号独立缓存。已读仅在本工作台保存。升级补 HTML 沿用原范围，不清空旧会话或已读。

支持原 HTML 与纯文本切换，正文单部分最多 1 MiB；CID 图片每张最多 512 KiB、合计 2 MiB，外链图片逐封点击加载。HTML 清理与隔离展示，普通附件同步元信息。真实客户归属明确的收发进入客户沟通记录，不自动创建需求或改接待归属。

会话内提供单人「回复」，沿用原账号，优先 Reply-To，否则回发件人；保留线程引用。编辑器支持基础富文本、账号签名、服务器版本化草稿及附件，最多 10 个、合计解码后 10 MiB。

用户点击发送授权这一封人工回复，不套用首封审批、营销时段或开发日额度；仍检查连接、账号暂停、身份和草稿版本。自动接待将来使用独立授权与限额，不能继承这项人工发送许可。

## 发送事实与暂缓

发送前持久化操作、内容指纹和 Message-ID；同一草稿及操作只提交一次。SMTP 接受不等于送达、已读或客户有意向；已发件箱核实、归档和客户业务登记分别记录。

明确失败、已接受与结果未知分别显示。服务重启时未完成操作标未知，先核对，不自动重发；归档、清理草稿或登记客户业务失败不能触发再发邮件。

企业暂缓同时控制相关联系人和计划，保留人工收信与回复；复查到期仅提醒，恢复须核对最新沟通，不补发旧邮件。将来自动回信同样遵守暂缓和接待归属，详见 [客户数据](customer-data.md#开发进度与暂缓)。

## 存储与检查

`OUTREACH_DB_PATH` 默认 .data/outreach/outreach.sqlite；`OUTREACH_DATA_DIR` 默认 .data/outreach，保存公开邮箱配置及加密凭证。Windows 使用当前用户 DPAPI，迁移机器／用户重新录入；其他平台使用独立密钥与 AES-GCM。.data/ 不纳入 Git。

队列由后端执行，关闭网页不停止；重启恢复符合条件的已启动首封计划，未知发送先核对。旧固定双邮箱试点接口和后台已退役，不再启用原轮询。

相关离线检查为 `tests/outreach-*.test.mjs`、`tests/mail-conversations*.test.mjs`、`tests/mail-replies*.test.mjs`、`tests/mailbox-reader.test.mjs` 及客户业务测试。模拟传输不能证明真实投递；实际小批核验记录内容、收件地址、Message-ID 和真实状态，不把归档中的历史通过次数当作当前全量回归。
