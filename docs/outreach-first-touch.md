## 邮件模板与本机对照演示

在「沟通中心 → 跟进序列 → 编辑序列」逐封编辑主题和正文。左侧支持直接写文案、插入公司／产品／品牌变量，以及插入 AI 开场、正文和回复问题。右侧助手可生成整封、主题、开场或附言，也可按指引改写选中的正文，采用后才修改模板。自定义 AI 变量保存名称和写作指引，按每位收件人的经营资料和已核实产品生成。当前序列其他步骤可以复用变量。个性化设置管理该步切入点、回复目标及口吻。

中栏可选择两家示例企业，也可从当前数据源已发送首封的记录选择联系人。点击生成预览会使用对应客户、邮箱和产品资料；修改固定文字可立即看到结果。正文按模板展开，称呼与邮箱签名自动加入，跟进沿用原线程主题。客户或自定义变量缺少必要依据时，起草会显示原因。保存产生序列版本，首封生成时记录模板版本，跟进排期时冻结各步模板和规则。

本机检查时先运行 `npm run build`，再运行 `node scripts/demo-outreach-templates.mjs 14374`。打开 [模板编辑](http://127.0.0.1:14374/inbox?tab=sequences) 和 [对照记录](http://127.0.0.1:14374/demo/records)。每次启动建立独立临时库，使用离线模型、模拟邮箱和模拟时钟。离线模型可用英文陈述句替换示例首段，用英文问句替换首封结尾或跟进问句。演示页的「用已保存模板生成并模拟发送」会建立一家新的合成企业，按当前规则生成首封及各步跟进。展开企业查看实际记录。

07 与 08 各用四家不同的澳洲成品卷帘经销商，在批次内用固定种子按企业打散后平分。07 两组共用品牌、邮箱、产品、时段及零跟进配置；A 沿用简短介绍，B 询问是否需要一页卷帘产品卡，卡片可从演示页打开。08 两组用相同首封模板，只有 B 增加第 3 天跟进，其中一家模拟真人回复以检验停止行为。正式效果按 14 天内积极回复的独立企业数除以各组实际首发企业数，另记退信、退订和履约时间。演示记录只用于功能验收。

## 自动记录与首封未回复跟进

跟进任务的「邮箱来信跟进」按 IMAP 历史列出客户来信和本账号后续回复。点客户回信主题会打开收件箱的「有回复」视图，定位同一邮箱及原线程。其他类型的来信直接打开对应线程。已知客户可由档案进入其已有来信的会话，收件箱内展示从原文提取的需求及待核实原因。正常业务服务自动整理 T1 并将真实收发同步到 T3。[历史来信与只读同步](mail-automation/mail-history.md)

在所属发送计划开启首封未回复跟进。工作区默认安排在首封实际发送后第 3、7 天，业务员可在「跟进序列」增删步骤、调整天数和每步写作要求。每封首封邮件提交时记录策略版本，核实发送成功后按该版本排程。T4 及只读任务页各以一条任务记录一次后续跟进。「跟进序列」展示各计划、客户、步骤、到期时间及停止原因，可暂停和恢复跟进。计划详情仍可关闭剩余追信，达到首封目标的历史计划保留相同控制。

发送前完整同步收件及已发送文件夹。真人回复或人工发信终止本轮，已识别的自动通知沿用原定跟进安排，待核实回执停止本轮自动追信。历史任务中等待业务员确认的自动回执沿用原处理方式。遵守原发送窗口、时区、邮箱总额度与间隔，每次最多延后 24 小时。结果未知时保留记录待核实。完整文案及条件见 [首封未回复跟进](ai-sales-agent-design.md#首封未回复跟进)。

## 邮箱与身份

在沟通中心录入实际公司邮箱、客户端授权码、显示名称、品牌、产品覆盖与签名，验证连接后启用。当前直接适配阿里邮箱的加密 SMTP／IMAP；其他服务商需要相应适配。

发件地址和固定签名由程序取自账号配置，模型不能更换身份。签名支持姓名、结束语、公司、地址、官网及 Logo；Logo 为 PNG／JPG、最多 256 KB、尺寸不超过 4096 像素，显示宽度 80–320 像素。已有人工草稿保留原内容，不因改签名静默替换。

邮箱卡片展示已配置的完整签名与 Logo。进入邮箱管理、保存签名或手动刷新时按需读取完整配置；日常状态轮询不携带图片。部分签名读取失败时保留其他邮箱的预览并提示刷新重试。

首封先按客户经营证据匹配具体产品，再按已审核品牌覆盖选邮箱，最后在适用账号内按可用额度和间隔安排。发送间隔最低 5 秒，各邮箱独立计时；每日额度和草稿生成时间仍会影响实际速度。现有三个品牌的准确产品方向统一维护在 [邮箱路由](../agents/export-sales/mailbox-routing.md)，本页不再复制品牌表。官网暂不可读不撤销有效业务批准，宽泛品类或空闲额度不扩大覆盖。

客户已有实际往来后沿用固定邮箱。跨品类问题可由业务员取得专业支持，对外回复沿用同一会话，自动答疑仅引用该官网已选且有效的资料。归属冲突需先核对。

## 首封开发

计划管理采用一行一个计划的表格，展示名称、状态、已发送／目标、已跳过数量、需处理数量、创建时间和操作。默认查看当前正式计划，已完成／已取消的正式计划进入历史计划，公司试发单独查看；各视图支持名称搜索、状态筛选和分页，默认每页 20 条，可选 10／20／50／100 条。列表可打开详情、暂停运行计划，编辑与取消收在“更多”中，保留启动及取消确认。

触达计划由服务器 SQLite 筛选、排序、分页，业务员在所属计划查看提交结果及需核实的记录。进入跟进序列可核对已发送首封的实际时间和正文，打开关联收件箱可阅读后续往来。计划进度只计入实际已发数量。

新计划采用简化流程：选择客户范围、产品、邮箱和目标数量 → 启动计划 → 普通 LLM 依据客户证据与已确认产品信息生成 → 系统核验、入队、发送。无需预填介绍、准备样稿或逐封审核；启动是对当前范围与数量的授权。2026-11-06 按未上线项目的清理要求，移除旧专业模式、样稿审批和试发审批链路，不保留兼容分支；此项替代 ADR-0018 中保留旧模式的安排。

程序固定首行 `Hi {客户公司名} team,`，LLM 生成其后正文，程序附账号签名；不从邮箱前缀、公司故事或主观推测补人名。已发送原文保留。

简化流程的首次开发信使用独立的[写作提示词](../agents/first-touch-writer/system.md)：正文 55–85 个英文单词，正式、自然、简洁，先写有来源的客户产品观察，再介绍对应发件品牌、已确认的供货产品和联系目的，结尾按模板提出一个低压力问题（默认询问是否需要简短产品介绍）。标题突出相关产品和供货目的。产品仍由程序按计划范围和客户证据匹配，写作模块不选择客户或更换发件身份。

三段各自承担不同作用：客户观察、品牌及供货介绍、一个容易回复的问题。通用收件箱可询问简短介绍对采购负责人是否有用，不假设收件人本人负责采购；不增加第二个请求或未经确认的能力承诺。品牌和合作目的各介绍一次。

客户观察聚焦匹配产品，不机械罗列客户目录；已获准供货和制造事实不等于“专注某产品”等自我定位。生成器拦截无依据的专注或专业化声明。

2026-10-28 负责人确认自有工厂，2026-10-29 提供的开发信样例确认三个品牌可在各自范围内表述从中国供货，依据保存在[已确认供货事实](../agents/first-touch-writer/confirmed-supply.json)。只有产品品牌、名称、采购形态及发件品牌、官网、邮箱域名均对应时，写作模块才能使用这些地域、制造商和细分产品事实；其他情况只作已有产品的一般供货介绍。客户证据和供货事实均支持时才采用细分产品切入点，工厂身份不扩展为具体规格或商务承诺。事实及提示词纳入资料版本，变更后沿用发送前复核机制。

程序依据最强匹配证据确定一个双方共同支持的细分切入点，不能确定唯一细分时保留所选大类，另提供最多两条与所选产品匹配的客户事实作背景。程序检查输出格式、来源编号、三段排版、字数、单一结尾问题及部分未确认声明；55–85 词是写作目标，程序容忍上下各 5 词的偏差，避免仅少一词就拦截合格内容。仅排版或写作格式不合格时自动修订一次，再次不合格仍阻止生成；事实、来源或商务声明检查失败直接阻止。来源编号有效不等于每句含义都已自动验证。提示词变更先用少量真实客户资料生成样例验收，将反馈明确写入适用规则，不将个别客户的改动无条件套用到所有客户，也不增加日常逐封审核。

首封开发信由撰写 Agent 生成，通过上述程序检查后进入发送队列。2026-10-29 移除独立审核 Agent 及其模型调用；写作格式不合格时仍由撰写 Agent 修订一次，事实、来源与发送权限检查继续由程序执行。

进入发送须满足：

- 企业尚未触达、没有进行中的客户会话或人工接管；同域商务地址可沿用旧档案。跨域地址需要官网邻近原文明示为企业自身联系渠道。首页及联系页均可使用标明本企业名称的联系方式栏，联系页内另列的外部平台地址仍需核对归属。旧队列发送前继续复核客户和收件人；新增的拦截说明不单独使已排队邮件失效。监管投诉或第三方客服地址跳过，有合适的备选地址时继续筛选。已有来源保留，明确无效或隐私、退订、招聘等专用地址仍排除。
- 产品、采购形态、市场及品牌覆盖适用，连接和签名有效，账号未暂停。
- 当前计划已启动并在授权范围内，客户未退订或标为勿联系，企业首封去重通过。
- 账号发送限额与最小间隔满足，发送前再次核对客户状态、资料及配置版本。

同一企业跨联系人、账号、品类和计划只安排一封首信。首次实际发送后保留账号归属。计划持续加入符合条件的新客户，达到目标或取消后停止；无适用账号时等待，不跨品牌补量。

客户无可用商务邮箱、已联系或勿联系、身份和经营证据不足、产品匹配未通过、经营事实冲突等客户条件不满足时，结束该客户在本计划内的首次开发尝试，记录“已跳过”及具体原因，不生成邮件或人工补档待办，也不因跳过标记勿联系。已排队邮件发送前复核发现这些条件不满足时同样跳过，保留原记录并释放未提交占用；已尝试发送、明确失败及结果未知记录不改为跳过。

已跳过不占发送目标名额；补齐资料、修正规则、同轮更新客户、编辑或恢复旧计划、重启服务都不能恢复旧尝试。客户可通过新的手动触达计划，或后续开启自动首发且再次更新并保存该客户的获客轮次，重新通过最新条件与企业去重检查。发件邮箱、签名、产品审核和范围等配置异常在计划层显示，修复后重新检查仍有效的计划；额度和发送时段等待原授权范围内的下一次机会，不转成客户待办。跳过不改变整个计划的授权或目标；固定批次耗尽当前队列时仍按原规则暂停，无其他阻塞时不提示跳过客户需要处理；持续计划仍可纳入其他符合条件的新客户。

资料完备按本封需要判断，只有已确认产品事实时即可发送基础介绍。当前首封写作模块拦截价格、MOQ、库存、认证、交期、运费及付款等声明；已确认资料也不绕过这项首封内容限制。标准商务内容自动回复属于待实现的接待设计，须另行实现资料、客户条件和商务权限核对。

资料实质变更后旧审核失效，相关未发邮件暂停。新版本批准且仍在原授权范围内时重新生成、核对并继续；扩大产品／市场或改变品牌须重新授权，已发送原文不修改。基础首封不自动添加产品或技术附件，账号签名 Logo 可内嵌。

「取消计划」停止新增准备及未提交发送，保留记录，取消后不恢复；重新开发需新计划并继续通过企业去重。已提交邮件不能保证撤回，保留实际结果。明确失败和结果未知均占用本轮尝试名额，不为凑目标盲目重试。

## 获客自动首发

获客任务开启自动首发后，每轮自动建立一项带客户来源范围的触达安排。客户新增或更新保存确认后逐家加入；客户条件不足跳过本次，配置及额度异常在计划层持续检查。进入新轮次后，旧轮次不再发送尚未提交的首封。已成功发出首封的客户继续按原版本跟进，定时计划暂停时暂缓，关闭时停止。这一安排没有独立的累计发送目标，邮箱每日额度与发送间隔继续适用。同轮持续纳入最新已审核产品和可用发件邮箱，补齐发件配置后无需等待下一轮；已准备邮件不因新增产品或邮箱而换身份，发送前仍检查当前资料和客户状态。

这类记录在沟通中心显示“获客后自动首发”，仍在运行或暂停时归入当前计划，进度标明“已发送／本轮收录客户”，可查看邮件和缺项；开关、暂停、恢复和关闭由所属获客任务控制，列表保留“管理获客与自动首发”入口，不能在沟通中心另行启动或改为全库筛选。原手动触达计划的范围和数量规则保留。具体用法见[获客后自动首发](acquisition.md#获客后自动首发)。

## 连接测试与真实授权

公司邮箱试发仅在明确的自有地址之间发送带唯一标记的固定非营销测试内容，幂等提交。SMTP 接受和实际收件核对分别记录，测试不写成真实客户开发事实，也不扩大正式计划或自动回信权限。

邮箱连通、资料审核、首封计划启动、自动回信接待和主动追信分别核对。公司试发与收件核对独立保留，不再提供正式发送的试发审批入口。

## 阅读与人工回复

打开「收件箱」读取服务器缓存。正常业务服务的后台增量收信及手动「同步邮件」使用加密凭证连接只读 IMAP，邮箱暂停发送不影响读取。首次同步最近 30 天收件箱及可识别已发件箱，每文件夹每次最多 50 封，有剩余时继续同步；增量按账号、文件夹和 UIDVALIDITY 保存游标，失败保留原文与进度。

同邮箱按标准消息编号及回复引用归并，会话不按相同主题随意合并；不同账号独立缓存。已读仅在本工作台保存。升级补 HTML 沿用原范围，不清空旧会话或已读。

支持原 HTML 与纯文本切换，正文单部分最多 1 MiB；CID 图片每张最多 512 KiB、合计 2 MiB，外链图片随原邮件自动加载。HTML 清理与隔离展示，图片请求不携带来源页，普通附件同步元信息。真实客户归属明确的收发进入客户沟通记录；客户具体产品咨询和采购事项另由后台从原文自动整理 T1，不自动改变接待归属。

客户档案的“客户邮件”进入 `/inbox?tab=inbox` 并带客户编号和 `inboundOnly=1`，仅列出该客户已有来信的会话，默认打开最新一段；会话继续展示完整收发原文。后台 `GET /api/v1/outreach/conversations` 支持相同的客户与来信筛选，按邮箱、客户、关键词及未读状态筛选后分页，收件箱每页 25 段，普通沟通中心不带来信限制。无来信显示明确空状态，读取失败单独报错；缓存未包含的新邮件仍需邮箱同步。

会话内提供单人「回复」，沿用原账号，优先 Reply-To，否则回发件人；保留线程引用。编辑器支持基础富文本、账号签名、服务器版本化草稿及附件，最多 10 个、合计解码后 10 MiB。

业务员点击发送仅授权当前人工回复。提交时核对账号、暂停状态、停止联系和草稿修订。自动答疑还需要邮箱接待授权、可用的已审核资料、发送间隔和日额度。

## 发送事实

发送前持久化操作、内容指纹和 Message-ID；同一草稿及操作只提交一次。SMTP 接受不等于送达、已读或客户有意向；已发件箱核实、归档和客户业务登记分别记录。

发送记录的状态包括待发送（正在生成、排队、提交中）、已发送（服务商已接受或经核实已发出）、投递失败（提交后收到并关联的退信）、需处理（待人工确认的完整草稿、未经核实的明确失败、结果待核实）、已核实未发出、已跳过和已取消。总览和计划的需处理数量按首发提交结果统计。草稿生成完毕但仍需人工操作时归需处理，已跳过和已核实未发出均为终态。

在「触达计划」打开计划详情查看发送记录，在「跟进序列」点「查看首封」核对主题和原文。SMTP 提交结果用于计划进度和发件额度统计。

历史邮箱缓存和新增 IMAP 邮件沿用同一退信规则。在同一发件账号内，按原邮件 Message-ID 匹配标准退信，或按阿里云企业邮箱退信中明示的原收件人与主题唯一匹配。通知时间须不早于提交时间；仅延迟通知、普通来信及无法唯一关联的退信留在原邮箱会话。退信匹配、账号与提交结果存于服务器邮件 SQLite，计划详情按需读取正文。

未生成邮件的详情称“首发记录详情”，说明客户、所属计划、具体跳过原因、时间及旧计划不会恢复发送，可跳转客户资料；不显示空邮件正文或恢复发送按钮。“标记不再联系”是独立的客户联系偏好操作，不用于结束本次首发。计划保留实际已发送／本轮收录客户（手动计划为设定目标）的分母，另列已跳过数量，不能把跳过数显示成待发送缺口。生成失败且从未提交的空草稿重试时更新同一条记录，不再反复新增取消记录；已有完整正文的旧版本仍保留，已发送和结果待核实记录不受影响。

结果未知的正式首发保留原客户占用和 Message-ID，禁止自动重发。新进入未知状态时自动同步对应原邮箱，只接受邮箱识别的已发送目录中 Message-ID、发件人与收件人均吻合的证据；详情的“核实发送结果”可再次检查。找到可信的原邮箱已发送证据后记录为已发送，仅证明邮件发出，不证明客户已收到；没有找到或同步失败仍为结果未知，不能以缓存缺失认定未发送。人工核实须填写结果、依据和操作人，并记录时间；确认从未成功提交时记为明确失败、释放客户占用，但旧计划仍不能恢复本次发送，新轮次才可重新评估。核实已发出不追溯自动追信，不改变既有邮件内容。
