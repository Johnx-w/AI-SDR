# 邮件沟通

沟通中心的四个栏目为「邮箱管理」「触达计划」「收件箱」「跟进序列」。业务员在收件箱查看原信、审核草稿、回复和接管，在跟进序列编辑工作区默认策略，在触达计划详情的「客户跟进」页签查看真实首封及各步执行情况。实数查看使用本机快照，正常业务服务按该环境的授权收发邮件。[运行入口和验收](mail-automation/README.md)

## 邮件模板与本机对照演示

演示启动时保存独立构建快照，后续本地构建完成后可重新启动演示查看新版本。`/demo/followups` 为当前运行的客户跟进示例入口，自动定位对应计划。

在「沟通中心 → 跟进序列 → 编辑序列」逐封编辑主题和正文。左侧支持直接写文案、插入公司／产品／品牌变量，以及插入 AI 开场、正文和回复问题。右侧助手可生成整封、主题、开场或附言，也可按指引改写选中的正文，采用后才修改模板。自定义 AI 变量保存名称和写作指引，按每位收件人的经营资料和已核实产品生成。当前序列其他步骤可以复用变量。个性化设置管理该步切入点、回复目标及口吻。

中栏分别选择发件邮箱、客户大类及匹配产品。类别复用现有经营角色及官网事实，同一客户可属于多个有证据的类别；不依据搜索条件、品牌或产品名称归类。系统从完整类别中选取当前邮箱与产品适用的一个真实客户，显示名称、类别、产品、类别原文来源和选择依据，可更换同类样本。没有合格样本时说明缺少的依据，不回退虚构客户。已固定邮箱的客户不跨品牌取样。暂停或额度用尽不妨碍只读预览，但不会授予发送许可。

预览显示正式生成器按本次模板替换后的完整主题、正文和签名。点击“本次使用的写作规则”核对首封、当前步骤、基础规则和产品依据，规则仍从左侧及个性化设置编辑。修改模板、样本、邮箱或步骤后清除旧预览，重新生成后才能看到新结果；迟到响应不覆盖当前选择。第 3、7 天的预览按当前未保存规则依次生成首封和此前步骤作为上下文，不冒充历史实发记录。预览不会保存策略、创建计划、改客户状态或发邮件。保存策略才产生新版本，之后正式起草和跟进排期沿用现有版本冻结规则。

范围、回归及性能证据见[分类预览验收](mail-automation/category-preview.md)。

本机检查时先运行 `npm run build`，再运行 `node scripts/demo-outreach-templates.mjs 14374`。打开 [模板编辑](http://127.0.0.1:14374/inbox?tab=sequences) 和 [对照记录](http://127.0.0.1:14374/demo/records)。每次启动建立独立临时库，使用离线模型、模拟邮箱和模拟时钟。离线模型可用英文陈述句替换示例首段，用英文问句替换首封结尾或跟进问句。演示页的「用已保存模板生成并模拟发送」会建立一家新的合成企业，按当前规则生成首封及各步跟进。展开企业查看实际记录。

07 与 08 各用四家不同的澳洲成品卷帘经销商，在批次内用固定种子按企业打散后平分。07 两组共用品牌、邮箱、产品、时段及零跟进配置；A 沿用简短介绍，B 询问是否需要一页卷帘产品卡，卡片可从演示页打开。08 两组用相同首封模板，只有 B 增加第 3 天跟进，其中一家模拟真人回复以检验停止行为。正式效果按 14 天内积极回复的独立企业数除以各组实际首发企业数，另记退信、退订和履约时间。演示记录只用于功能验收。

## 自动记录与首封未回复跟进

跟进任务的「邮箱来信跟进」按 IMAP 历史列出客户来信和本账号后续回复。点客户回信主题会打开收件箱的「有回复」视图，定位同一邮箱及原线程。其他类型的来信直接打开对应线程。已知客户可由档案进入其已有来信的会话，收件箱内展示从原文提取的需求及待核实原因。正常业务服务自动整理 T1 并将真实收发同步到 T3。[历史来信与只读同步](mail-automation/mail-history.md)

在所属发送计划开启首封未回复跟进。工作区默认安排在首封实际发送后第 3、7 天，业务员可在「跟进序列」增删步骤、调整天数和每步写作要求。每封首封邮件提交时记录策略版本，核实发送成功后按该版本排程。T4 及只读任务页各以一条任务记录一次后续跟进。「跟进序列」展示各计划、客户、步骤、到期时间及停止原因，可暂停和恢复跟进。计划详情仍可关闭剩余追信，达到首封目标的历史计划保留相同控制。

发送前完整同步收件及已发送文件夹。真人回复或人工发信终止本轮，已识别的自动通知沿用原定跟进安排，待核实回执停止本轮自动追信。历史任务中等待业务员确认的自动回执沿用原处理方式。遵守原发送窗口、时区、邮箱总额度与间隔，每次最多延后 24 小时。结果未知时保留记录待核实。完整文案及条件见 [首封未回复跟进](ai-sales-agent-design.md#首封未回复跟进)。

## 邮箱与身份

在沟通中心录入实际公司邮箱、客户端授权码、显示名称、品牌、产品覆盖与签名，验证连接后启用。当前直接适配阿里邮箱的加密 SMTP／IMAP；其他服务商需要相应适配。

发件地址和固定签名由程序取自账号配置，模型不能更换身份。签名支持姓名、结束语、公司、地址、官网及 Logo；Logo 为 PNG／JPG、最多 256 KB、尺寸不超过 4096 像素，显示宽度 80–320 像素。已有人工草稿保留原内容，不因改签名静默替换。

邮箱卡片展示已配置的完整签名与 Logo。进入邮箱管理、保存签名或手动刷新时按需读取完整配置；日常状态轮询不携带图片。部分签名读取失败时保留其他邮箱的预览并提示刷新重试。

首封先按客户经营证据匹配具体产品，再按已审核品牌覆盖选邮箱，最后在适用账号内按可用额度和间隔安排。发送间隔最低 5 秒，各邮箱独立计时；每日额度和草稿生成时间仍会影响实际速度。现有三个品牌的准确产品方向统一维护在 [邮箱路由](../agents/export-sales/mailbox-routing.md)，本页不再复制品牌表。官网暂不可读不撤销有效业务批准，宽泛品类或空闲额度不扩大覆盖。

客户已有实际往来后沿用固定邮箱。跨品类问题可由业务员取得专业支持，对外回复沿用同一会话，自动答疑仅引用该官网已选且有效的资料。归属冲突需先核对。

## 首封开发

### 手动触达计划产品选择（本地实现）

新建与编辑时至少明确选择一个供货产品，空集合表示未选，页面和 API 均拒绝保存。可选项取所选邮箱覆盖、品牌许可、审核与生效条件的交集；室内窗饰、其他和未分类分组显示计数、供货形态及负责邮箱，支持按组选择。切换分组保留全部勾选；切换邮箱保留失效项并显示具体原因，移除或补回负责邮箱后才能保存。

保存持久化 `filters.products` 编号集合与产品范围快照，品类只作页面分组。新增目录或覆盖不扩大手动计划，明确编辑保存后才纳入。启动重新核对当前产品条件，发送继续检查产品范围、原邮箱与资料版本；获客自动首发独立沿用持续授权。

启动服务时幂等迁移旧手动计划：仅从保存的产品快照取编号，再与原显式产品、原品类及原邮箱当前覆盖、品牌许可求交集，不从当前目录补产品。缺失快照或交集为空标为等待确认，活动计划暂停，编辑确认前不可继续发送。迁移不删除邮件及发送历史；`productSelectionVersion=1` 避免重试扩大范围。

### 触达计划范围与删除规则（本地实现）

2026-11-27 用户已确认以下产品选择、范围维护与删除规则，产品选择、旧手动计划迁移、邮箱范围维护及删除来源联动已在本地实现并以隔离夹具验收；生产尚未发布。来源获客任务采用可恢复暂停，同时持久化关闭来源及关联定时安排的获客后自动首发，页面取消勾选。直接恢复仅继续获客，用户重新勾选并保存后才建立新的触达安排。下列步骤描述本地实现规则。

正式规格与 AC01—AC22 见 [GitHub Issue #85](https://github.com/Johnx-w/AI-SDR/issues/85)，删除及恢复规则按用户此次修正同步更新。

正式配置核对来源为云端运行版本 `93144d8` 的 `GET /api/v1/outreach/state?view=current` 与 `GET /api/v1/products/knowledge`，核对时间为北京时间 2026-11-27 16:04。共 7 条供货产品，均已审核并生效；3 个邮箱覆盖其中 6 条，剩余 1 条户外遮阳基础记录未分配邮箱。逐项覆盖与现行[邮箱路由](../agents/export-sales/mailbox-routing.md)一致。该核对覆盖当时全部供货配置。行为验收在独立合成夹具中完成，详见[触达计划验收](mail-automation/outreach-plan-acceptance.md)，不代表生产现有客户与计划已全量验收。

已确认的规则如下。

- 邮箱负责范围构成计划可选产品的上限。操作顺序为选择邮箱，再明确勾选本次产品，产品旁显示负责邮箱及供货形态。
- 品类作为产品列表分组，支持按组选择产品，保存明确的产品清单。界面同时显示已选产品数量及清单。
- 手动计划保存明确的产品范围，邮箱后来增加产品时，经编辑确认后纳入。获客自动首发继续按 ADR-0023 的持续授权规则同步范围。
- 产品撤审或邮箱撤销覆盖时，对应未发任务停止发送并显示原因。
- `indoor` 展示名称调整为“室内窗饰”，同组可包含成品、轨道和配件，通过产品形态区分。分组从实际可选产品生成，已有“其他”和缺失分类记录纳入设计。
- 邮箱设置提供负责产品维护入口，允许负责人在品牌覆盖相符的已审核产品中调整，保存前列出受影响的计划。
- 切换邮箱后保留失效产品勾选及原因，由用户移除失效产品或补回负责邮箱后保存。取消最后一项时提示至少选择一项产品。
- 删除计划同时停止剩余首发与未回复跟进，并从普通列表移除。已发送邮件、客户往来、未知结果及企业去重依据继续保留，可从客户历史追溯；正在提交的邮件等待结果结算。
- 删除后在“已删除”视图保留原计划、发送结果与删除时间，供查阅。再次开发通过新建计划重新确认范围与客户状态。
- 删除获客来源计划时，暂停对应的来源任务和关联定时安排，在来源页面显示“关联触达计划已删除，获客已暂停”，附被删除计划的名称与查看入口。将来源及关联定时安排的自动首发开关持久化为关闭，页面取消勾选，等待人工恢复或删除来源任务，详见 [ADR-0026](adr/0026-pause-acquisition-when-deleting-outreach.md)。

本地实现采用以下规则。

- 手动计划空产品数组表示未选并拒绝保存；品类只作分组，切换不再删除已选编号。
- 当前手动计划在保存时记录产品范围快照，启动只批准对应版本。快照还包含名称、品类、供货形态、品牌和市场，发送时核对范围与资料有效性。
- 旧手动计划按原邮箱、产品、品类及保存快照求交集，保持原授权。空交集和缺失快照等待编辑确认。
- 邮箱设置提供负责产品维护入口。新建邮箱按已审核产品与官网匹配自动建立覆盖，编辑官网保留既有产品编号；手动调整时预览影响，保存时复核品牌覆盖。
- 已生成或排队的邮件继续核对原产品和原发件身份，产品资料或负责范围发生变化时给出具体原因。

计划列表和详情均提供删除入口，已完成计划的待追信也会结束。发送中及结果未知的记录、核实过程、企业去重和客户跟进继续关联原计划。来源同步遵守删除标记。删除接口可安全重复调用，调度与异步发送结算识别删除标记，结果核实继续关联原发送记录。

产品选择与日常维护的细节如下。

1. 新建计划按当前所选邮箱列出实际适用的已审核且生效产品，以明确复选框和计数表示本次选择，支持全选及按组选择。新增邮箱或新增目录产品时，重新展示可选项，由用户勾选后保存。
2. 切换邮箱后，仍在计划内但失去覆盖的产品保留在已选区并展示原因。用户移除失效项或补回负责邮箱后保存，最后一项取消后阻止保存。每项产品可列出多个负责邮箱，最终按客户证据和现行邮箱调度规则确定唯一发件身份。
3. 手动计划保存时冻结产品集合与现有范围快照，启动时重新检查当前审核、生效、品牌和邮箱有效性。产品后续撤审、品类或供货形态等范围实质变化时，相关未发任务等待重新确认。
4. 邮箱配置采用修订号或等价条件更新，避免两人同时修改导致覆盖丢失。影响预览后再次提交时复核版本，已准备邮件继续锁定原产品和发件邮箱。
5. 已有“其他”或缺失分类的合法产品归入可见分组，并通过同一审核、覆盖及品牌校验。资料文件和产品供货记录继续按现有标志识别。

删除和来源联动按以下步骤处理。

1. 所有正式计划状态均能从“更多”发起删除。确认界面展示计划名称、待提交邮件与追信数量、结果待核实数量，以及关联获客任务和定时安排。获客来源计划的确认文案明确说明获客会同时暂停。
2. 持久化删除请求后即阻止该计划取得新的首发或追信提交许可。取消未提交任务，释放对应未提交占用，保留已发送及结果未知企业的去重依据。已进入邮件服务商提交过程的邮件等待结算。
3. 来源任务持久化人工暂停原因及关联计划编号，同时将任务和关联定时安排的自动首发开关保存为关闭。页面取消勾选，刷新、重启、异步回调及检查点回写均保持关闭，过期提交通过修订校验拒绝。正在研究的企业完成当前保存或写入结果核对后进入暂停，保留队列与进度。定时安排同步暂停并清除下次执行时点。可恢复暂停独立于清理队列的 `stop` 操作，异步保存及检查点保留该控制状态。
4. 删除请求首先在触达库持久化，立即停止旧首发和追信提交；来源暂停与自动首发关闭随后持久化，后台每轮仅通过待删除索引读取未完成请求并补齐。重复删除、来源写入失败及进程重启都能继续完成同一请求。来源暂停或自动首发关闭尚未全部确认时，页面显示“删除处理中”，原触达计划持续处于停止提交状态。
5. 删除标记优先于来源同步，旧计划始终保持删除状态。单次任务人工直接继续同一轮时，自动首发保持关闭，仅恢复获客进度。用户重新勾选并保存后，按来源递增 `outreachGeneration` 建立新的关联计划；来源仍暂停时新安排等待人工恢复。旧标识继续关联历史邮件和核实记录。发送许可同时校验来源与安排标识，避免旧邮件因来源恢复而重新入队。
6. 定时计划人工恢复后按正常规则等待未来时点，新轮次使用新的任务并继承自动首发关闭状态，仅在用户重新勾选并保存后按授权范围建立新触达安排。已结束的单次任务保留执行结果和暂停首发原因，人工重新执行时生成新任务。来源页面的删除操作结束该来源后续安排并保留已有客户与沟通证据。
7. 新的触达安排仅处理符合当前规则的客户。已发送、结果未知、已有会话及同轮已跳过的旧尝试继续按既有去重与终态规则核对。来源恢复提示告知仅继续获客且自动首发保持关闭，重新勾选并保存时提示将建立新安排，旧计划在“已删除”视图中保持可查。

### 当前操作

计划管理采用一行一个计划的表格，展示名称、状态、已发送／目标、已跳过数量、需处理数量、创建时间和操作。默认查看当前正式计划，已完成／已取消的正式计划进入历史计划，公司试发单独查看；各视图支持名称搜索、状态筛选和分页，默认每页 20 条，可选 10／20／50／100 条。列表可打开详情、暂停运行计划，编辑与取消收在“更多”中，保留启动及取消确认。

触达计划由服务器 SQLite 筛选、排序、分页，业务员在所属计划查看提交结果及需核实的记录。进入跟进序列可核对已发送首封的实际时间和正文，打开关联收件箱可阅读后续往来。计划进度只计入实际已发数量。

新建或编辑触达计划时，可从获客国家目录搜索并多选目标市场。支持中英文名称和国家代码，选择多个国家时，客户匹配其中任一国家即可满足市场条件。清空选择表示全部市场。已有计划中超出当前获客范围的值会回显，可手动移除。

新计划采用简化流程：选择客户范围、产品、邮箱和目标数量 → 启动计划 → 普通 LLM 依据客户证据与已确认产品信息生成 → 系统核验、入队、发送。无需预填介绍、准备样稿或逐封审核；启动是对当前范围与数量的授权。2026-11-06 按未上线项目的清理要求，移除旧专业模式、样稿审批和试发审批链路，不保留兼容分支；此项替代 ADR-0018 中保留旧模式的安排。

程序固定首行 `Hi {客户公司名} team,`，LLM 生成其后正文，程序附账号签名；不从邮箱前缀、公司故事或主观推测补人名。已发送原文保留。

首封和各次跟进分别配置主题、段落、篇幅、品牌介绍与结尾。默认围绕匹配产品，运营显式要求时才询问对口联系人。跟进主题留空时沿用原线程主题，自定义主题仍引用原邮件。用 `{{ai_body}}` 试写自由正文；固定文案和自定义变量按模板展开。

客户观察聚焦匹配产品，不机械罗列客户目录；已获准供货和制造事实不等于“专注某产品”等自我定位。生成器拦截无依据的专注或专业化声明。

2026-10-28 负责人确认自有工厂，2026-10-29 提供的开发信样例确认三个品牌可在各自范围内表述从中国供货，依据保存在[已确认供货事实](../agents/first-touch-writer/confirmed-supply.json)。只有产品品牌、名称、采购形态及发件品牌、官网、邮箱域名均对应时，写作模块才能使用这些地域、制造商和细分产品事实；其他情况只作已有产品的一般供货介绍。客户证据和供货事实均支持时才采用细分产品切入点，工厂身份不扩展为具体规格或商务承诺。事实及提示词纳入资料版本，变更后沿用发送前复核机制。

程序依据最强匹配证据确定一个双方共同支持的细分切入点，不能确定唯一细分时保留所选大类，另提供最多两条与所选产品匹配的客户事实作背景。程序检查最终邮件、来源编号及商务声明。重复称呼、签名或内部措辞可修订一次，修订沿用当前步骤的写作要求。来源编号有效不等于每句含义都已自动验证。提示词变更先用少量真实客户资料生成样例验收，将反馈明确写入适用规则，不将个别客户的改动无条件套用到所有客户，也不增加日常逐封审核。

首封开发信由撰写 Agent 生成，通过上述程序检查后进入发送队列。2026-10-29 移除独立审核 Agent 及其模型调用；写作格式不合格时仍由撰写 Agent 修订一次，事实、来源与发送权限检查继续由程序执行。

进入发送须满足：

- 企业尚未触达、没有进行中的客户会话或人工接管；同域商务地址可沿用旧档案。跨域地址需要官网邻近原文明示为企业自身联系渠道。首页及联系页均可使用标明本企业名称的联系方式栏，联系页内另列的外部平台地址仍需核对归属。旧队列发送前继续复核客户和收件人；新增的拦截说明不单独使已排队邮件失效。监管投诉或第三方客服地址跳过，有合适的备选地址时继续筛选。已有来源保留，明确无效或隐私、退订、招聘等专用地址仍排除。
- 产品、采购形态、市场及品牌覆盖适用，连接和签名有效，账号未暂停。
- 当前计划已启动并在授权范围内，客户未退订或标为勿联系，企业首封去重通过。
- 账号发送限额与最小间隔满足，发送前再次核对客户状态、资料及配置版本。

同一企业跨联系人、账号、品类和计划只安排一封首信。首次实际发送后保留账号归属。计划持续加入符合条件的新客户，达到目标或取消后停止；无适用账号时等待，不跨品牌补量。

客户无可用商务邮箱、已联系或勿联系、身份和经营证据不足、产品匹配未通过、经营事实冲突等客户条件不满足时，结束该客户在本计划内的首次开发尝试，记录“已跳过”及具体原因，不生成邮件或人工补档待办，也不因跳过标记勿联系。已排队邮件发送前复核发现这些条件不满足时同样跳过，保留原记录并释放未提交占用；已尝试发送、明确失败及结果未知记录不改为跳过。

已跳过不占发送目标名额；补齐资料、修正规则、同轮更新客户、编辑或恢复旧计划、重启服务都不能恢复旧尝试。客户可通过新的手动触达计划，或后续开启自动首发且再次更新并保存该客户的获客轮次，重新通过最新条件与企业去重检查。发件邮箱、签名、产品审核和范围等配置异常在计划层显示，修复后重新检查仍有效的计划；额度和发送时段等待原授权范围内的下一次机会，不转成客户待办。跳过不改变整个计划的授权或目标；固定批次耗尽当前队列时仍按原规则暂停，无其他阻塞时不提示跳过客户需要处理；持续计划仍可纳入其他符合条件的新客户。

资料完备按本封需要判断，只有已确认产品事实时即可发送基础介绍。当前首封写作模块拦截价格、MOQ、库存、认证、交期、运费及付款等声明；已确认资料也不绕过这项首封内容限制。标准商务内容自动回复属于待实现的接待设计，须另行实现资料、客户条件和商务权限核对。

资料实质变更后旧审核失效，相关未发邮件暂停。新版本批准且仍在原授权范围内时重新生成、核对并继续；扩大产品／市场或改变品牌须重新授权，已发送原文不修改。基础首封不自动添加产品或技术附件，账号签名 Logo 可内嵌。

「取消计划」停止新增准备及未提交发送，保留记录，取消后不恢复；重新开发需新计划并继续通过企业去重。已提交邮件不能保证撤回，保留实际结果。明确失败和结果未知均占用本轮尝试名额，不为凑目标盲目重试。

## 获客自动首发

获客任务开启自动首发后，每轮自动建立一项带客户来源范围的触达安排。客户新增或更新保存确认后逐家加入；客户条件不足跳过本次，配置及额度异常在计划层持续检查。进入新轮次后，旧轮次不再发送尚未提交的首封。已成功发出首封的客户继续按原版本跟进，定时计划暂停时暂缓，关闭时停止。这一安排没有独立的累计发送目标，邮箱每日额度与发送间隔继续适用。同轮持续纳入最新已审核产品和可用发件邮箱，补齐发件配置后无需等待下一轮；已准备邮件不因新增产品或邮箱而换身份，发送前仍检查当前资料和客户状态。

这类记录在沟通中心显示“获客后自动首发”，仍在运行或暂停时归入当前计划，进度标明“已发送／本轮收录客户”，可查看邮件和缺项；开关、暂停、恢复和关闭由所属获客任务控制，列表保留“管理获客与自动首发”入口，不能在沟通中心另行启动或改为全库筛选。原手动触达计划的范围和数量规则保留。具体用法见[获客后自动首发](acquisition.md#获客后自动首发)。

## 连接测试与真实授权

公司邮箱试发仅在明确的自有地址之间发送带唯一标记的固定非营销测试内容，幂等提交。SMTP 接受和实际收件核对分别记录，测试不写成真实客户开发事实，也不扩大正式计划或自动回信权限。

邮箱连通、资料审核、首封计划启动、自动回信接待和主动追信分别核对。公司试发与收件核对独立保留，不再提供正式发送的试发审批入口。

## 阅读与人工回复

打开「收件箱」读取服务器缓存。正常业务服务的后台增量收信及手动「同步邮件」使用加密凭证连接只读 IMAP，邮箱暂停发送不影响读取。首次同步最近 30 天收件箱及可识别已发件箱，每文件夹每次最多 50 封，有剩余时继续同步；增量按账号、文件夹和 UIDVALIDITY 保存游标，失败保留原文与进度。

同邮箱按标准消息编号及回复引用归并，会话不按相同主题随意合并；不同账号独立缓存。已读仅在本工作台保存。升级补 HTML 沿用原范围，不清空旧会话或已读。

支持原 HTML 与纯文本切换，正文单部分最多 1 MiB；CID 图片每张最多 512 KiB、合计 2 MiB，外链图片随原邮件自动加载。HTML 清理与隔离展示，图片请求不携带来源页，普通附件同步元信息。真实客户归属明确的收发进入客户沟通记录；客户具体产品咨询和采购事项另由后台从原文自动整理 T1，不自动改变接待归属。

客户档案的“客户邮件”进入 `/inbox?tab=inbox` 并带客户编号和 `inboundOnly=1`，仅列出该客户已有来信的会话，默认打开最新一段；会话继续展示完整收发原文。后台 `GET /api/v1/outreach/conversations` 支持相同的客户与来信筛选，按邮箱、客户、关键词及未读状态筛选后分页，收件箱每页 25 段，普通沟通中心不带来信限制。无来信显示明确空状态，读取失败单独报错；缓存未包含的新邮件仍需邮箱同步。

会话内提供单人「回复」，沿用原账号，优先 Reply-To，否则回发件人；保留线程引用。编辑器支持基础富文本、账号签名、服务器版本化草稿及附件，最多 10 个、合计解码后 10 MiB。

业务员点击发送仅授权当前人工回复。提交时核对账号、暂停状态、停止联系和草稿修订。自动答疑还需要邮箱接待授权、可用的已审核资料、发送间隔和日额度。

## 发送事实

发送前持久化操作、内容指纹和 Message-ID；同一草稿及操作只提交一次。SMTP 接受不等于送达、已读或客户有意向；已发件箱核实、归档和客户业务登记分别记录。

发送记录的状态包括待发送（正在生成、排队、提交中）、已发送（服务商已接受或经核实已发出）、投递失败（提交后收到并关联的退信）、需处理（待人工确认的完整草稿、未经核实的明确失败、结果待核实）、已核实未发出、已跳过和已取消。总览和计划的需处理数量按首发提交结果统计。草稿生成完毕但仍需人工操作时归需处理，已跳过和已核实未发出均为终态。

在「触达计划」打开计划详情查看发送记录，在「跟进序列」点「查看首封」核对主题和原文。SMTP 提交结果用于计划进度和发件额度统计。

历史邮箱缓存和新增 IMAP 邮件沿用同一退信规则。在同一发件账号内，按原邮件 Message-ID 匹配标准退信，或按阿里云企业邮箱退信中明示的原收件人与主题唯一匹配。通知时间须不早于提交时间；仅延迟通知、普通来信及无法唯一关联的退信留在原邮箱会话。退信匹配、账号与提交结果存于服务器邮件 SQLite，计划详情按需读取正文。

未生成邮件的详情称“首发记录详情”，说明客户、所属计划、具体跳过原因、时间及旧计划不会恢复发送，可跳转客户资料；不显示空邮件正文或恢复发送按钮。“标记不再联系”是独立的客户联系偏好操作，不用于结束本次首发。计划保留实际已发送／本轮收录客户（手动计划为设定目标）的分母，另列已跳过数量，不能把跳过数显示成待发送缺口。生成失败且从未提交的空草稿重试时更新同一条记录，不再反复新增取消记录；已有完整正文的旧版本仍保留，已发送和结果待核实记录不受影响。

结果未知的正式首发保留原客户占用和 Message-ID，禁止自动重发。新进入未知状态时自动同步对应原邮箱，只接受邮箱识别的已发送目录中 Message-ID、发件人与收件人均吻合的证据；详情的“核实发送结果”可再次检查。找到可信的原邮箱已发送证据后记录为已发送，仅证明邮件发出，不证明客户已收到；没有找到或同步失败仍为结果未知，不能以缓存缺失认定未发送。人工核实须填写结果、依据和操作人，并记录时间；确认从未成功提交时记为明确失败、释放客户占用，但旧计划仍不能恢复本次发送，新轮次才可重新评估。核实已发出不追溯自动追信，不改变既有邮件内容。

## 存储与检查

`OUTREACH_DB_PATH` 默认 .data/outreach/outreach.sqlite；`OUTREACH_DATA_DIR` 默认 .data/outreach，保存公开邮箱配置及加密凭证。Windows 使用当前用户 DPAPI，迁移机器／用户重新录入；其他平台使用独立密钥与 AES-GCM。.data/ 不纳入 Git。

队列由后端执行，关闭网页不停止；重启恢复符合条件的已启动首封计划，未知发送先核对。旧固定双邮箱试点接口和后台已退役，不再启用原轮询。

相关离线检查为 `tests/outreach-*.test.mjs`、`tests/mail-conversations*.test.mjs`、`tests/mail-replies*.test.mjs`、`tests/mailbox-reader.test.mjs` 及客户业务测试。模拟传输不能证明真实投递；实际小批核验记录内容、收件地址、Message-ID 和真实状态，不把归档中的历史通过次数当作当前全量回归。

### 手动触达计划删除（本地实现，待发布）

正式手动计划在草稿、准备中、就绪、运行、暂停、完成和取消状态均可从列表或详情删除。确认框从 SQLite 回读待首发、待追信、结果未知数量。删除保留计划原业务状态，以 `deleteRequestedAt` 优先阻止启动、编辑及提交；`deletedAt` 表示完成。当前与历史列表排除删除请求，已删除视图按原状态、名称筛选并在数据库分页，保留删除时间及实际发送结果。

删除请求、取消未提交首发与待追信在同一事务保存。服务商已开始提交的邮件继续结算；未知结果及其原邮箱核实、企业占用和客户历史保留。删除后的核实成功不创建追信。重复删除和重启回读幂等，异步计划检查点不能覆盖已保存的删除标记。

接口为 `GET /api/v1/outreach/campaigns/:id/deletion-preview` 和 `POST /api/v1/outreach/campaigns/:id/delete`，后者要求 `revision` 与 `confirmed: true`，过期版本返回 409。来源计划删除已联动可恢复暂停；暂停和关闭开关未全部确认时不设置完成时间。共享服务入口为 `requestCampaignDeletion` 与 `completeCampaignDeletion`。

### 邮箱负责产品维护（本地实现，待发布）

在沟通中心「邮箱管理」打开「配置」，可勾选当前品牌许可相符的已审核供货产品，也可清空负责范围。素材文件与未审核、其他品牌产品不进入供货选择。失效的原选择保留提示，须主动移除或恢复许可后保存。

修改产品或品牌身份后，首次点击保存只显示增减差异及受影响计划，再点击「确认影响并保存邮箱」提交。手动计划维持原产品编号集合；新增覆盖只有获客自动首发的持续授权可使用。撤销覆盖会阻止原邮箱对应产品的未提交邮件，保留原产品、正文及发件身份，不改派其他邮箱。发送连接准备完成后、SMTP提交之前再检查一次；已经提交的邮件保留实际结果。

公开接口 `GET /api/v1/outreach/mailboxes/:id/coverage-products` 返回供货选择所需的目录摘要；`POST .../:id/coverage-preview` 校验产品、品牌及 `revision` 并返回差异和计划影响；`PUT .../:id` 提交明确 `productIds` 时必须携带最新 `revision`，冲突返回409，刷新后重新确认。邮箱配置版本与负责范围持久化保存；业务备注独立维护。

发件身份摘要现在只包括身份字段，产品覆盖逐项检查。升级前已准备邮件仅在旧公式精确证明当前发件身份及产品覆盖未变时迁移摘要并继续原队列；真实身份或旧覆盖不符仍阻止提交，不能无条件放行。此处仅说明本地实现，未推送或部署。

回归入口：`node --test tests/outreach-mailboxes.test.mjs tests/outreach-service.test.mjs`；构建后运行 `node scripts/verify-mailbox-coverage-browser.mjs`，隔离夹具包含两个不同品牌邮箱及空覆盖对照，外部发信使用替身，不证明真实投递。
